# 输入区操作弹层统一

状态：implemented
类型：feature
Owner：web/src/components/common/ActionDropdown.vue

## 问题

模型选择等待目录与元数据请求完成才展开，慢请求没有可见反馈。Agent、模型、审批、附件和项目入口分别持有弹层与按钮样式，输入区允许向下翻转，模型按钮还混用表单边框。

## 决策

`ActionDropdown` 拥有搜索、滚动区域、底部操作、外部点击关闭、Escape 和定位。默认根据空间自适应；`AgentChatComponent` 给模型、审批、项目选择器传入 `upward`，`AgentView` 与 `MessageInputComponent` 的输入区弹层直接设置 `upward`，显式禁止向下翻转。设置和定时任务等表单保持默认自适应。

`upward` 弹层以零高度定位容器对齐触发器上沿，内容绝对定位在容器底边；加载和筛选改变高度时直接向上增减，不等待组件库二次测量。自适应弹层保持普通文档流。高度受触发器附近的可视区域与 420px 上限约束，水平位置按可视宽度限制；可用高度不足 240px 时整个面板滚动，避免搜索和底部说明挤掉选项。可视区域移动和窗口变化重新计算边界。

`ActionTrigger` 拥有两种外观：`plain` 为输入区的 30px 无边框按钮，`field` 为表单中等宽的 32px 选择框。附加检查和清空操作通过兄弟节点插槽呈现，不嵌套按钮。`ModelSelectorComponent` 按 `modelType` 统一对话、Embedding 与 Re-ranker 目录，两个表单包装器保留 `value`、`update:value` 与 `change` 契约；Embedding 维度和状态检查保留。旧模型选择器公共 LESS 的消费者全部迁移后删除该文件。

模型选择先展开再请求，显式显示加载、失败重试和空状态。可选模型元数据在目录显示后独立补齐。已关闭弹层不会在请求完成时重新打开，权限与会话绑定仍由现有业务入口执行。

## 替代方案

仅修改模型选择器会保留重复样式与其他输入区菜单的翻转行为。全局强制向上会限制顶部表单，因此方向由场景显式选择；全局替换所有 Ant 弹窗会影响无关页面，当前共享组件只覆盖已迁移的操作选择器。

## 后果

当前五类输入区入口共用基础结构，系统中的三类模型选择器共用目录展示与表单外观。业务选项仍由各消费者拥有，共享组件不接管 API、权限或持久化。低高度时搜索栏与底部操作随整个面板滚动，以保证每项内容可访问。

## 验证

`web/test/unit/modelSelectorLoading.test.js` 验证慢请求立即展开、关闭后不重开、可选元数据不阻塞目录、失败重试、模型类型、禁用行为及包装器事件契约。恢复旧的等待请求后展开实现，立即展开断言失败，等待元数据案例超时。

`web/test/unit/actionDropdownPosition.test.js` 验证默认自适应、向上约束、水平边界与可视区域偏移；样式归属测试确认消费者接入共享弹层。真实开发页面在 1440×900、390×844、844×390 和 768×320 检查五类输入区菜单的上下及水平边界、Escape、搜索、慢请求和失败重试。设置页检查四个模型控件等宽、32px，以及默认向下展开；输入区检查 30px、无边框。浅色和暗色截图验证主题外观。移动端检查使用浏览器视口模拟，不等价于实体设备软键盘验收。

`web/test/browser/actionDropdownGrowth.js` 通过延迟目录响应及筛选缩小列表，逐帧检查弹层底边相对触发按钮的偏移不超过 1px。恢复普通流布局时，旧实现的底边漂移约 266px；固定底边后最大漂移约 0.03px。脚本仅在已登录的开发浏览器内拦截目录响应，不调用模型。

命令包括 `docker compose exec web pnpm run lint:check`、`docker compose exec web pnpm run test:unit`、`docker compose exec web pnpm run build`、工程契约检查及文档构建；实际结果与未验证范围写入交付报告。
