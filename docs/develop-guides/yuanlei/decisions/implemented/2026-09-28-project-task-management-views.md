# 项目任务管理视图与委派反馈

状态：implemented
类型：feature
Owner：web/src/views/ProjectWorkTasksView.vue
关联 Feature：[独立项目工作任务与 Issue](../../features/project-work-tasks.md)、[外部执行器委派与 Multica 桥接](../../features/external-executor-delegation.md)

## 问题

独立任务页面把新建表单与简易列表排在一起；未配置项目缩写时创建任务返回 409，却只显示通用冲突提示。单项目工作台仍有独立的治理审核任务，委派后只显示执行器与粗略状态；数字员工仅启用 Codex 时仍允许选择 OpenCode，失败会话不易发现。

## 决策

独立项目任务页使用同一持久任务列表切换看板、列表和按月甘特图。看板修改任务状态，甘特图按可选的 `start_date` 与 `due_date` 绘制并允许设置计划；日期属于 yuanlei schema v18，结束早于开始时服务拒绝写入。新建使用弹窗，首次创建先明确设置并固化项目缩写，再创建任务；缺失或冲突的缩写返回可展示的业务错误码与文案。

治理工作台继续处理待审核的治理任务，并明确标注其与长期项目任务的区别。人工委派使用项目数字员工的有效编码配置限制执行器，后端在写入委派意图前再校验。工作台展示本地投递与编码会话状态，支持读取会话错误；非终态委派定期刷新。

## 替代方案

- 用创建或更新时间推算甘特图工期：这些时间是审计事实，不能表达计划，故增加独立日期字段。
- 委派后直接跳转到聊天 Run：治理委派的执行 Owner 是编码会话，不是 AgentRun，跳转会误导用户。
- 把治理任务迁入独立项目任务表：两者审核与长期执行语义不同，数据迁移超出本次反馈修复范围。

## 后果

历史任务的计划日期保持空值，甘特图明确显示未安排；现有编号和状态不变。项目缩写仍由用户首次确定。治理任务的失败记录保留在原委派与编码会话中，可在工作台追踪；自动接受项目任务的设置仍独立于治理委派。
