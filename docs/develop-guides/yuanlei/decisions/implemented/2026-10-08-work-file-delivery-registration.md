# 正式工作文件交付登记与查看

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/project_work_execution_service.py

## 问题

正式工作文件写入成功后，摘要可能仅报告路径；自动结果只采信同一 Run 成功的 present_artifacts，导致真实文件未进入业务结果证据。结果卡片显示可访问路径，缺少直接查看入口。

## 决策

正式工作执行协议明确要求：文件写入并核对后调用 present_artifacts 登记当次交付物，数字员工需启用现有展示工具，纯文字事项无需文件。沿用原回收 Owner，只从当次 Run 成功展示记录读取产物，按项目文件边界验证可访问性，生成唯一待验收结果。

结果卡片未登记文件时显示说明；后端为当前可访问的项目文件计算 Workspace 虚拟路径，前端跳转现有工作区深链接预览。失败或越界文件不产生入口，工作区读取仍执行现有权限与文件边界检查。

## 替代方案

从摘要猜路径或扫描目录无法证明文件属于当次执行。补登记接口需新增版本冲突、pending 状态和操作历史流程，先验证现有展示协议是否足够。独立文件版本平台超出收尾范围。

## 后果

既有执行快照与已接受结果不回填，人工或纯文字结果仍可无文件验收。路径可访问性仅代表当前可读取，文件内容须人工核对，也不保证当次字节永久保存。上游同步保留同 Run 来源和受控文件读取约束。

## 验证

真实 PostgreSQL 回归核对可访问文件的深链接及缺失、越界文件无入口；真实执行通过冻结输入、工具调用、物理文件和待验收结果交叉回读。完整测试与环境限制见阶段收尾执行记录，Codex/Multica 成功闭环保留 S04/S05 未验收。
