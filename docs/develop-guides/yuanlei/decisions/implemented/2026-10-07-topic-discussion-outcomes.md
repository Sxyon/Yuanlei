# 议题回复、讨论处置与人工实际确认

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/governance_service.py

## 问题

持续讨论缺少原讨论回复和独立处置，议题未能保存现实达成的个人判断及当时条件。把任务完成或结果接受当作议题达成会混淆业务Owner。

## 决策

评论增加可空父评论，只允许回复同议题顶层讨论；回复保存发布时修订。原讨论正序装配回复，倒序时间线只保存可定位的回复事件，独立详情读取早期讨论。

处置按顶层讨论追加版本，保留采纳、部分采纳、不采纳及说明。可空去向明确显示尚未关联，实际去向必须引用同项目真实议题修订、决策版本或工作结果。版本及引用时状态随记录保存；引用创建不批准决策、不改验收和执行。

可选预期结果、核对条件随既有议题修订保存；实际确认、修正、撤回使用追加记录，冻结当时条件、说明、依据和个人身份。实际确认独立于纳入、进度、归档，不推导工作或运行终态。条件变化后旧确认仅表示旧条件。

新写入先锁项目，再锁议题，记录与时间线同事务提交。处置和确认各自检查预期版本，确认另检查议题修订；相同操作标识和原始意图重试返回原记录，改变意图拒绝。新增引用加入删除守卫。证据复用工作结果访问边界，网页保持引用标识。

迁移只推进yuanlei至36，旧父评论、预期结果和核对条件保持空，不反推未知历史。

## 替代方案

覆盖评论正文会丢失处理依据；把确认塞入主状态会耦合纳入与现实结果。无限回复树、独立目标或通用Review中心没有本批消费者，保留局部追加记录。

## 后果

归档只读，恢复后历史完整。旧评论未知修订继续显示未知。已批准文本、当次执行依据、业务结果验收和P07反馈继续由原Owner维护。团队权限、投票与周期工作不在范围。

## 验证

真实PostgreSQL服务测试覆盖迁移重入、版本并发、引用与删除竞争、同意图重试及非法引用；真实HTTP复验覆盖完整流转和精确旧决策修订读取。页面验证回复、部分采纳、实际确认、更正、双页面冲突草稿和条件变化提醒。完整命令、独立审查与未验证范围见[验收记录](../../../../元垒系统架构规划设计/P09执行与验收记录.md)。外部Codex和Multica继续待验收。
