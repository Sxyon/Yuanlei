# C1 个人连接与准确文本交付

状态：implemented
类型：architecture
Owner：backend/package/yuxi/services/delegation_service.py

## 问题

外部委派与正式工作委派的执行器限制不同；OpenClaw 协议探针证明文本来源，没有产品入口及持久绑定。C0 补充引用和严格 Schema 存在冲突，摘要预算应由当次任务约定。用户授权执行 C1 工程包及本地隔离验证；真实远端产品验收另按具体整卡授权。

## 决策

复用委派和 Result Owner；新增个人连接、项目许可、目标与 attempt 结构进 yuanlei 域，保持旧执行器及 source_delegation_id 唯一性。连接凭据在专属加密边界保存，目标长期配置仍归远端。OpenClaw 用安装版协议4 Gateway，固定版本/目标核查后创建唯一 session，以持久 intent/run 标记关联；响应不明停止自动重派，保留核对入口。

补充首版支持带字节/指纹的 inline-text 详细报告；complete 只表达报告完整性。摘要默认200 code point，当次可指定1—8192，超预算保存原文与不合规事实。外部URL和路径引用不自动读取。非阻塞 notices 明确 blocking=false，映射 Result.unresolved 的类型化说明，真实阻塞继续拒绝成功结果。

唯一读投影 Schema 由协作契约发布，分别表示处理者、答复接收方、等待执行者和人的义务；Dashboard 只映射素材动作，导航及不透明 return token 归宿主。

## 替代方案

仅加 Adapter 留下工作入口和数据库拒绝，不能满足 C1。配置都放全局环境不能表达个人/项目许可；完整配置平台成本过高。补充远端引用缺少稳定权限/字节证明，首版受控文本可避免伪来源。新增数据库版本及部署密钥，迁移和隔离HTTP/PG回归为交付门槛；日常环境不自动迁移。

## 后果

本地协议模拟和真实PG/HTTP证据只证明元垒边界，真实OpenClaw产品入口仍等待整卡授权。安装版原生配置在只读复核与真实动作间缺少已证明的原子锁，整卡期间专属目标必须保持冻结；配置漂移复核拒绝后不再派发。连接/目标修改会使旧尝试的远端读操作失效，本地准确输出和历史引用保留。Multica成功回收止损保持，部署边界只阻塞其能力。
