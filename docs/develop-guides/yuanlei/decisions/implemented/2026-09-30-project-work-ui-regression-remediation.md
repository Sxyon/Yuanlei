# 项目工作体系界面显示与看板状态回读整改

状态：implemented
类型：bug-fix
Owner：web/src/views/ProjectWorkTasksView.vue
关联 Feature：[独立项目工作任务与 Issue](../../features/project-work-tasks.md)、[用户收件箱](../../features/user-inbox.md)

## 问题

真实浏览器逐页回归项目工作任务、任务详情、数字员工工作台与用户收件箱后，确认以下展示与操作事实问题：

- 看板卡片的“更改任务状态”在更新请求失败时保留用户所选，卡片仍停留在原状态列，页面同时显示错误，界面与 PostgreSQL 事实不一致。
- 数字员工工作台页面标题显示内部 slug（如 `agent-4278a9bf3994`）；任务详情“智能体执行”列表也只显示 agent slug。
- 任务详情“问题单”列表直接展示英文状态 `open`/`resolved`/`closed`，与同页其他中文状态不一致。
- 用户收件箱种类映射缺少 `task_inspection`，周期巡检通知显示原始 kind 文本，且“查看来源”按钮的跳转目标与任务类通知一致却未显式声明。
- 工作台错误态缺少重试入口，与任务列表、任务详情、收件箱的错误态不一致。

## 决策

看板状态变更 (`ProjectWorkTasksView.changeStatus`) 在成功或失败后一律回读服务端任务列表：失败时展示 `actionError` 并让卡片回到 PostgreSQL 事实，不保留乐观选择。

工作台标题使用项目数字员工显示名：加载时并行读取项目归属列表，取匹配 slug 的 `name`；归属列表读取失败时降级为 slug 且不阻断工作台。任务详情执行记录通过页面已加载的 `agents` 列表把 slug 映射为名称，缺失时回退 slug。

问题单状态与收件箱种类补充中文映射（问题单 `待处理`/`已解决`/`已关闭`，收件箱新增 `task_inspection → 周期巡检`），未知值原样回退。工作台错误态补充重试按钮。

## 替代方案

- 在后端工作台响应里返回 `agent_name`：需要新增后端字段与集成测试；UI 展示需求用 Web 已有的项目归属列表即可满足，保持改动在 Web 层。
- 用乐观 UI 直接改写卡片状态：执行状态由 PostgreSQL 拥有，更新失败后前端回读服务端事实，不保留乐观值。
- 为收件箱未知 kind 建立通用回退样式：现有 `kindInfo` 已有回退，缺的是 `task_inspection` 这一落库种类的显式映射，补映射比扩大回退语义更小。

## 后果

看板状态更新失败时页面回到服务端事实并同时提示错误；工作台与任务详情使用可读名称；收件箱周期巡检通知可读并跳转到任务；工作台错误态可重试。未引入新依赖，未改变 API 契约、权限或持久化。

本修复不改动语义 Owner、持久化边界、权限或兼容承诺，属同一变更内即时生效且无待裁决取舍，直接记 `implemented`。
