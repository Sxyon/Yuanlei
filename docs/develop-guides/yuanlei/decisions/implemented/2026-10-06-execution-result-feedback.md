# 同次执行结果验收与计划反馈

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/project_work_result_service.py

## 问题

正式执行输出和委派回收已有真实归属，但个人验收仍依赖手工复制结果；要求在执行期间变化时不能把旧输出归为新条件。验收意见需要进入新尝试，反馈议题或蓝图需要明确确认、版本语境和竞争保护。

## 决策

复用 P05 业务结果，在 yuanlei v34→v35 增加自动来源与输出定位、可空条件快照，以及同项目结果—议题反馈关系。自动结果按实际尝试或委派建立数据库唯一约束；收敛与回收拥有提交事务，追加写入过程不独立 commit。仅成功的同次输出形成待验收结果；执行与工作完成分开，验收及完成沿用 P05 守卫。

P06 后续要求快照保存独立描述和验收条件；自动结果读取当次快照，不从当前任务补填。已有组合正文仍保留，缺少独立条件明确为依据不足，不能用于接受或完成。所选上次结果注入验收意见与要求修订。

议题反馈显式选择同项目目标、研讨或纠偏，沿用议题锁、版本及历史；幂等确认保存双向关系，不自动重开。蓝图复盘先预览可编辑正文，保存时核对读取内容哈希和文件身份，检测变化保留草稿。Workspace 根目录描述符的跨进程锁串行化同一物理用户目录内的受控写入、移动和删除，共用项目目录共用此锁；刷新冲突预览展示最新原文，需明确核对并合并草稿后才能保存。文件提交与数据库提交分开，不建立假的跨存储事务或通用反馈平台。

## 替代方案

调用人工结果接口会要求当前条件并错误替换旧依据；从线程最后消息取输出会串用相邻 Run；自动完成会绕过个人验收及既有 Git、活跃执行和证据守卫。为此直接在现有终态和回收 Owner 追加结果，复用最小未提交写入过程。

## 后果

应用锁不约束直接 shell、编辑器或沙盒进程的任意文件写入；这些修改在核对前发生时返回冲突。非协作进程在最后核对与 POSIX 替换之间的竞争没有原子 CAS 保证，不宣称任意外部写入都得到保护。保存期间应避免这类进程同时改写目标文件；若要求该保证，需要另行收敛运行文件写入契约，本批不扩展沙盒平台。

旧资料不完整保持可见不足，旧评论不迁移为结果。资源可访问不代表业务合格，网页只是未抓取引用。P03 真实 Codex 成功产物与 Multica 出向仍待补验收，内部协议捕获及确定性回放不替代外部产品证据。团队权限、周期工作定义、通用 Review/图平台不纳入。

标准 Compose 环境的 yuanlei=35 已验证；真实 v34 旧结果升级及迁移重入保留正文、验收状态和版本，旧条件不推断。数据库、HTTP、真实 worker、协议输入、页面和负向案例的命令及结果见[P07执行与验收记录](../../../../元垒系统架构规划设计/归档/2026-10-10-重整前/P07执行与验收记录.md)。工程约束、后端 unit、Web lint/unit/build、文档构建与独立审查通过；实际外部 Codex 和 Multica 出向保持未验收。
