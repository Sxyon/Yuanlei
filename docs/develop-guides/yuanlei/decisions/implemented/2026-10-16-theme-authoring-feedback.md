# 主题制作模式与创建结果核实

状态：implemented
类型：bug-fix
Owner：web/src/components/project/ProjectThemeManager.vue

资料接续：文中旧章节编号与执行状态属于原决定时点，原稿可从Git提交`63dc5af7`恢复；现行设计、维护和状态从[专项入口](../../../../元垒系统架构规划设计/README.md)进入。

## 问题

详情查看按钮与写入发布用词相同，内置版本已在当前模式时看似无反应；复制直接创建默认名称且缺少结果反馈。服务端先提交来源身份再复制候选，异常可能留下可恢复身份，前端通用失败不能证明未创建。存储检查与主题编辑混在同一层级。

## 决策

沿SYS15.12与DEV12.3 M1直接授权，详情使用有选中态的编辑草稿／已发布版本，内置只读；真正写入为发布新版本。切换查看区域保留本地草稿，相同模式不重读。创建可编辑副本先确认名称、本人归属、准确版本，成功进入原候选编辑；复制异常先回读有权目录，按请求前身份集合、准确复制版本和名称识别新身份，展示准确恢复对象，未核实前阻止重复创建。不改create协议或生成第二套身份；多结果明确列出供核对，不能猜选。

存储检查与维护折叠收纳，展开才请求，默认健康／残留／异常摘要，明细按需查看；检查只读，清理仍原确认与来源锁引用保护。JSON与ZIP保持受控编辑，不扩展可视化设计器。

## 替代方案

仅改文案仍掩盖复制部分成功；自动重发创建可能生成重复主题；重建幂等创建协议超出本次必要范围。有权目录核实复用真实身份与复制出处，代价是网络不可用或并发多个相同副本时必须先核实、不能自动推断唯一结果。

## 后果

目录核实只使用有权身份，不扩大权限；未明确创建结果不能重发。人工验收前只相关检查，等待人工反馈与明确验收才全量；不据开发交付启动S05-R2、S06、协作或Andon。
