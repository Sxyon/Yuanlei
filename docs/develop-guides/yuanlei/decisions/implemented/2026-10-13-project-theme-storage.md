# 项目主题的不可变文件版本与独立项目绑定

状态：implemented
类型：architecture

确认依据：2026-10-13用户“确认页面，开始实施”，范围为SYS-DB-001第11节R1；S04阶段通过仍待用户效果审阅。

## 问题

S03的同一ThemeHost及纯契约需要消费真实来源、版本和项目选择。候选覆盖发布字节、仅用摘要授权、项目共用Workdir时串绑定、文件与数据库提交中断，都可能让页面显示错误版本或未经授权的资料。

## 决策

来源拥有服务生成身份、归属、候选修订及维护状态；候选和发布版本引用同来源文件域内的完整快照，版本记录不可改。文件按原ZIP摘要保存，完整写入与fsync后原子无覆盖link，才提交数据库引用；文件写入成功而数据库失败留下完整孤儿，原候选及绑定保持。复制先提交空来源身份，再锁来源写候选；失败保留可授权对账入口。所有候选、发布、对账／清理在来源行锁内进行，选择按来源→Project顺序锁定并检查持久generation；资源读取获得同序锁后重查绑定，拒绝等待期间改选的旧请求。

Project主键拥有准确版本与文件alias，Workdir不拥有主题选择。来源与Project在后端repository最终授权；内置只读、个人公共限当前用户、专属限所属活动项目。停用阻止新发布和选择，候选仍可维护，既有版本继续加载；撤回阻止版本加载并保存原因，原绑定和历史保留。S04正式页只读定义和包内资源，业务及项目文件内容明确待S05；独立预览保留明确合成标识。

生产parser复用S03模型，校验成员、路径、类型、资源指纹与容量。stdlib ZIP正文按声明长度截断，不能独立证明实际展开量；保留其本地名称和重叠校验，按真实有界DEFLATE流计量、核对实际长度及CRC，再验证定义及资源。alias是逻辑名，资源读取用查询参数，不作为文件或URL路径段；前端映射使用无原型字典。

## 替代方案

直接覆盖候选文件减少快照数量，但数据库失败后修订与内容难以恢复；完整快照允许旧引用继续回读并用同一维护入口清理孤儿。全局摘要去重节省重复字节，却需要跨来源授权和全局清理锁；同来源去重让身份、授权及文件锁域一致，代价是不同来源可保存相同字节。

## 后果

仅用标准ZIP read较短，但伪报中心目录长度可隐藏实际展开量；有界真实解压增加少量格式代码，需保持CRC、本地头及负例。发布与选择分开增加一步确认，却避免候选编辑、重试或发布失败隐式改变项目；源停用与安全撤回分别表达维护影响。维护按需执行，不引入后台任务系统。
