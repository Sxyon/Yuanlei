# 项目主题双入口绑定与宿主一致性

状态：implemented
类型：feature
Owner：web/src/layouts/ProjectLayout.vue
关联 Feature：[项目主题](../../features/project-themes.md)
关联提案：[分段修复](../proposed/2026-10-15-project-theme-switch-repair.md)，其S05-R2表达部分仍未实施。

## 问题

既有服务已保存准确不可变版本与唯一Project绑定，但平台版本行未携准确引用，成功离开管理页；导航与正文缺少共同失效作用域。只保存绑定或刷新局部面板不能证明项目已采用该版本，无设置声明或故障主题还需要独立恢复入口。

## 决策

平台来源范围和分配目标独立，项目优先与准确版本优先共用Selection及原select/binding；项目设置锁定当前项目作为快捷入口。平台成功留页回读，进入项目为可选动作。只读check和最终PUT共用服务校验，不增加持久ready状态、绑定表或启用机制。无文件声明无需Workdir，有声明仍由原文件边界校验。

ProjectLayout拥有唯一绑定投影；Panel及所有路由正文消费账号、Project、版本、generation作用域，换版销毁旧页面和请求Owner。真实编辑Owner登记其草稿及提交状态，先处理再切换；另一标签有草稿时保留旧编辑并明确标示偏差。路由按稳定能力寻找真实业务页，保留准确对象及历史参数；无准确对象转目标总览，旧返回令牌失效。

409回读后重新确认；结果未知先核实，不能盲目重发或自动回滚；已知保存而回读／包加载失败准确提示并保留核实入口。应急基础界面不改持久绑定，平台承担显式恢复；失权清除旧正文与草稿。项目渲染错误屏障不吞平台或普通事件异常。

## 替代方案

强制刷新会丢草稿；只让设置页分配会把缺声明及故障主题困住；另建平台绑定或ready表会产生两个事实源；每主题复制业务页面会分叉权限、历史与状态。当前实现复用原Owner，代价是编辑Owner必须登记真实未保存字段，跨标签只能在重新核对时保护各自草稿。

## 后果

新发布不自动替换项目选择，预览无绑定副作用，共用Workdir的项目仍按Project独立绑定。默认九项能力及业务语义保留。本决定只闭合切换机制，调研内容组织及JSON／PNG双数据联合验例仍归S05-R2；不授予S06或协作／Andon启动权限。
