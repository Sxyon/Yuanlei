# 本次执行资料预览与不可变业务快照

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/project_work_context_service.py

## 问题

工作队列已保存描述与条件输入，但来源正文、蓝图及引用未形成可预览的执行资料。直接编码和外部委派也需要实际输入与可回看的当次依据。后续修改、排队及恢复不能改写既有执行的资料。

## 决策

yuanlei v33→v34 在 ProjectWorkExecution 与 ChannelDelegation 增加可空业务快照 JSON；旧记录保持空，不推断历史。共用组装服务保存选择、来源版本、实际注入文本、哈希范围和缺失/截断说明，不混入 runtime manifest。

工作描述与验收条件优先完整保留；来源决策采用工作已选批准修订，议题版本、蓝图、业务结果、文件、附件由用户指定，知识库与网页提供按需引用。固定文本预算不需要模型摘要；超出预算明确截断，必需要求超预算显式失败。支持范围内的 UTF-8 蓝图（256 KiB）保存完整原文与哈希；直接写入超限文件时透明保存前缀，最终实际注入文本独立保留；大文件读取前缀时仅称前缀哈希，不保证未保存字节可还原。

预览计算内容指纹；创建尝试或委派时在项目优先事务内重新组装，指纹不同返回冲突。未使用页面的工具按同一规则直接创建。接受、队列、重投和恢复复用原资料；正式执行会话中的允许根工具委派继承当次快照，子智能体委派禁令保持，普通对话指定工作使用新资料。真实执行器任务载荷包含正文。历史受当前项目可见性和资源边界保护。

## 替代方案

worker 启动时重读最新资料会改写已分配输入；仅保存 metadata 无法证明执行器获得正文；只接队列会留下直接委派旁路。选择两个真实执行 Owner 的可空快照和一个共享组装服务，避免假 Run、假尝试及通用上下文平台。

## 后果

文件读取与数据库事务不能构成跨存储原子事务，以创建时实际读取字节为事实；预览指纹检测创建读到的变化。资源引用不等于字节备份或业务证据。快照涉及当前可访问项目资料，不能扩大附件/知识库读取权限。P03 外部成功产物仍待补验收，P07 自动反馈不在范围。

## 验证

2026-10-06 在现有 Compose 环境升级并回读 yuanlei=34，保留已有数据。真实 PostgreSQL/HTTP 测试验证预览变化冲突、旧来源修订、原正文进入两类执行载荷、继承委派和新尝试区分、蓝图更名后的旧全文回看、路径越界及跨工作附件拒绝。迁移负向用例先删除两个新列构造 v33 状态，再升级和重入，回读旧执行及旧委派快照为空且原输入保留。

确定性模型回放的真实 API/worker E2E 四例通过，覆盖手动接受、自动接受、中断恢复和限流失败；回读 PostgreSQL 中实际 Message 正文、执行资料指纹、原验收条件及原蓝图。独立真实 worker 操作取消固化知识库的项目关联，最终 Run 和执行尝试失败，错误明确说明资料缺失，原快照保留。它证明访问变化结局，不声称模型读取了知识库正文。

真实页面完成资料选择、缺失文件提示、预览、分配、修改要求、蓝图更名和历史回看，随后回读历史接口及数据库；浅色和深色窄屏截图保存在本地验收产物目录，未提交用户数据或截图。组件测试覆盖迟到列表不能覆盖历史、切换工作丢弃旧响应、选择变化使指纹失效并保留输入。
