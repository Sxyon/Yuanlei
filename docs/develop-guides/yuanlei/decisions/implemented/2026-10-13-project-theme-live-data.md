# 项目主题真实业务、文件与可信返回接通

状态：implemented
类型：feature
Owner：docs/元垒系统架构规划设计/SYS-DB-001-Dashboard系统需求与架构设计.md

## 问题

已选主题需要读取当前项目真实业务与指定文件，并进入原业务办理后返回。全量列表后截取失去准确分页；当前目录页被当成完整集合会误换已选议题；自由文件路径绕过Project绑定；刷新或离开原宿主丢失主题上下文会中断使用。

## 决策

固定业务适配消费原治理与正式工作服务的有界查询，repository先过滤再计数／分页；原DTO、状态、权限及冻结来源快照拥有业务事实。摘要沿Project／ProjectSettings，讨论按准确topic_id；目录分页和筛选保留已选议题身份，准确对象读负责缺失与授权结论。议题表格显示当前页关联数，进入原议题宿主查看完整关系。

包内asset按有权不可变版本读取；项目文件按当前Project绑定alias及generation，在来源→Project锁内重查并由Workdir逐段no-follow读取实际JSON／PNG。浏览器只传alias及generation，响应MIME／size／SHA取同一字节，宿主独立核对；错误保留公开原因。读取不创建Conversation。

主题对象先核原API身份，再进入原工作台或正式任务页。返回令牌保存宿主捕获的阅读上下文，目的路由由平台固定生成；返回及显式刷新重读绑定和业务，只在同账号／Project／reference／digest／generation恢复页、选择、查询、滚动和焦点。HTTP前后核绑定及宿主generation拒绝旧结果；原业务404再次核Project范围，失权清空旧内容。六页布局、独立合成预览和原业务办理Owner保持现有分工。

## 替代方案

全量前端分页成本低但查询无界、过滤与计数不可靠；采用原Owner数据库分页。批量载入关联标题会无界放大数据量；当前页准确关联数加原宿主办理满足现有表格用途。通用Viewer要求额外会话或自由路径；采用现有绑定alias。复制治理界面会分叉状态／权限／审计；原宿主仅补可信返回接线。

## 后果

新增只读有界用例和窄文件入口，无新持久表、业务模型、通用写代理或运行时依赖。返回上下文局限当前浏览器会话，任意URL不能成为返回目的地；换账号／Project／版本／绑定后不恢复旧阅读内容。每轮读取额外核对当前绑定，增加有限请求和包校验成本；授权与当前选择的可信性优先于浏览器缓存。首批仅提供实际consumer需要的JSON／PNG。
