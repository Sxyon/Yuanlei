# 智能体工作台、用户收件箱与项目工作任务

状态：proposed
类型：feature
Owner：backend/package/yuxi/services/project_work_service.py

已落地的任务底座由[第一阶段决定](../implemented/2026-09-27-project-work-task-foundation.md)、[页面入口决定](../implemented/2026-09-28-project-work-task-interface.md)与[Feature](../../features/project-work-tasks.md)说明；项目任务完成及 Run 待答复通知由[收件箱决定](../implemented/2026-09-27-user-inbox.md)与[Feature](../../features/user-inbox.md)说明。本提案保存尚未完成的整体方向与验收边界。

## 问题

现有 AgentRunRequest 按用户、Agent、线程串行化聊天请求；`governance_tasks` 表达来源审核，不拥有可交接的长期执行任务。用户无法从每个数字员工的工作台看到跨线程待办、当前执行及最近完成记录，也没有一个持久收件箱汇总完成通知和等待答复的中断。项目需要独立于聊天请求、Durable Task 和治理审核对象的工作任务，使多个智能体依次参与，单任务同时只有一个执行者，并保留负责人、讨论、产物和可恢复的编号。

## 提案

- 项目工作任务是新的长期业务对象，拥有标题、详情、状态、第一负责人、项目与可选议题、父任务、附件和引用。任务下的 Issue 是独立问题单，拥有自己的状态和讨论；任务汇总各 Issue 的结论与产物。治理任务仍只负责既有来源审核和督查语义；两类任务不互相充当状态真相。既有数据不自动迁移，迁移规则须有明确的字段映射和验收后再决定。
- 项目可配置不可重复的缩写；议题可配置项目内不可重复的缩写。新任务创建时在同一事务内分配序号并固化展示编号。缺失议题缩写时先生成候选、验证格式与冲突，再固化；模型失败时创建显式失败，不生成临时编号。缩写变更不重写历史任务编号。未关联议题的任务使用项目范围编号；具体格式和号段在首个实现阶段固定为数据库约束和 API 契约。
- 单个任务可以由不同智能体依次执行；执行尝试与任务分表，记录 Agent、模型快照、触发者、Run ID、状态和时间。持久唯一约束保护单任务同时只有一个非终态执行尝试。任务级排队与 AgentRunRequest 的线程 FIFO 分开，派发复用现有 AgentRun 执行和租约；投递发生在任务及 Run owning transaction 提交后。
- 每个智能体的工作台从其任务执行尝试与队列读取当前、排队、最近工作。自动接受任务及默认模型是项目数字员工的配置；配置生效于新接受的任务，已固化的执行尝试不被后续修改覆盖。第一负责人独立于当前执行者，可更换并承担周期检查；检查频率、责任转移和失败提醒由持久调度事实与 worker 规则拥有，不能只由页面计时器实现。
- 用户收件箱在 PostgreSQL 保存接收者、来源对象、通知类型、已读与归档时间。Run 完成和需要用户答复的中断在所属状态事务提交后形成可重试通知意图；重复投递幂等，不展示相邻 Run 的结果。归档和已读独立，打开任务或 Run 能到达原始上下文。回答中断仍走现有 resume 链路，收件箱不成为第二个审批状态 Owner。
- 分阶段交付：先固化独立项目任务、Issue、编号、权限与评论；再接入执行尝试、单任务互斥及智能体工作台；随后接入 Run 终态通知、问询通知与用户收件箱；最后接通自动接受、默认模型与第一负责人定时检查。每阶段只有在其端到端证据闭合后才标记已实现，未完成阶段保留在本提案。

## 替代方案

- 扩充 `governance_tasks` 承载执行生命周期：会把 proposed 审核状态和长期工作状态混用，且与用户要求的独立任务体系冲突。
- 将 AgentRunRequest 当长期任务：Request 是一次消息的排队状态，无法表达跨智能体交接、子任务、负责人和讨论历史。
- 只按 AgentRun 反推收件箱与工作台：可以用于只读初版，但读/归档、任务接收、幂等通知与负责人检查需要持久事实；完成通知在过期 Run 回收时也不能依赖前端在线。
- 复用 Multica 作为任务事实源：外部系统不能拥有元垒项目业务状态；参考其“工作对象与每次执行分开”的交互原则，保留元垒第一负责人和本地权限边界。

## 风险

- 现有治理议题的缩写需要 yuanlei 域独立持久化，不能回写上游 business/knowledge；修改现有治理表时保留审核约束与旧 API 行为。
- 任务派发和 AgentRun 终态跨不同事务，必须定义可重试的 outbox 或 publisher 收敛，避免提交后进程崩溃造成漏投递/漏通知。
- Issue 已确认为任务下的独立问题单；Issue 编号、关闭条件以及与任务状态的联动仍需在实现阶段固定契约。
- 模型生成缩写涉及不稳定外部输出；候选校验、冲突处理和失败可观察性须通过真实 provider 探针补证据。
