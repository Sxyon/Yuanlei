# Dashboard 受控定义、项目实例与启用生命周期

状态：proposed
类型：architecture
Owner：backend/package/yuxi/services/project_dashboard_service.py

## 问题

U5已实现的宿主导航、管理与准确结果办理有真实证据。原静态HTML只有单项目文件和静态读取，尚无动态数据、模板派生、多实例和Agent草稿生命周期。局部动态图表或放宽iframe权限无法覆盖两项专项总纲的完整目标。

## 提案

采用[D0完整基线及D1—D6验收卡](../../../../元垒系统架构规划设计/归档/2026-10-10-重整前/第一阶段专项/Dashboard-D0设计基线与D1-D6验收卡-2026-10-09.md)作为推荐。治理工作台、列表、收件箱、Agent工作台与Dashboard能力分别有交付及验收；平台导航、项目管理和业务观察各自承担入口职责，日常办理在受信任页面执行。U5代码与既有权限保持。

首阶段推荐可信Vue素材和严格版本化定义，允许grid/stack结构组合及类型化映射；R2生成Vue由真实表达不足与成本证据触发独立增量。模板版本固定，项目实例定义/绑定修订、实例稳定版、项目业务首页分开；数据集修订及采纳是独立Owner。新持久结构只进入yuanlei，PG保存不可变定义/绑定和原子发布指针，文件字节沿用现有受权Owner。

Agent使用同service的规则发现、读取、CAS草稿、验证和发布工具；根项目Run保留scope/lease约束，子只交候选。manual默认、精确模板有限自动政策显式配置；自由组合自动启用和数据采纳需要独立范围。收件箱读取C0/C5问题投影，通知已读/归档不改变问题采用/恢复。此记录没有批准迁移、发布、运行代码或产品修改。

## 替代方案

静态文件可继续承担快照兼容与管理兜底；没有动态钻取的数据能力按实际静态范围验收。生成Vue隔离包支持自由算法，增加构建、依赖、协议和诊断成本，保留需求触发路径。文件定义加集中索引便于人工查看，但共享Workdir、版本事务及多实例指针需要额外一致性管理；推荐PG定义Owner和受权文件副本。全部人工启用会削弱自主维护，任意自动启用缺少可机械判定的授权范围；采用manual和显式fixed-template，数据采纳另管。

## 风险

受控素材可能不足以表达真实业务空间，需要保留证据触发的R2增量。新增持久结构、数据授权与自动政策带来真实迁移/权限成本，须在D3/D5前提交具体范围。C5未接通时收件箱只能显示当前能力和待接入范围。可逆宽度/密度/断点仍需人类阅读和真实设备验证。两个首批授权取舍集中于D0 §13，未接受推荐不得把此proposed记录转成implemented。
