范围、嵌入稿、组件/API 落点、增量与真实验收由[U4 实施包](../../../../元垒系统架构规划设计/第一阶段专项/信息架构与Dashboard-U4分项收敛与首个实施包-2026-10-09.md)拥有。此提案保存拟采用取舍及接受条件；产品未实施，用户尚未批准首包。

## 问题

平台全局入口、项目工作空间与项目 Dashboard 内容需要明确嵌入关系。宽平台菜单与项目菜单同时占位会压缩观察和办理；仅独立项目原型无法证明宿主恢复。结果详情需要准确定位同工作不同交付，保持提交时依据、当前差异、证据和办理意见，避免来源切换与旧要求导致误办。

## 提案

平台宿主维护全局导航和呈现偏好；项目布局维护身份及概览、工作台、工作、项目智能体与资料入口；Dashboard 内容只维护自身筛选、分析和准确对象钻取。默认采用平台窄栏与显式展开/固定，项目导航按需收起；窄屏和全屏只调整临时呈现。悬浮展开和拖动调宽不进入首包默认能力，待实证触发。

管理概览持续作为项目兜底；业务 Dashboard 与其可切换，不把办理表单移入图墙。治理工作台以蓝图、议题、有效决策和建议准入为主；正式工作拥有执行、结果与人工办理；项目 Agent 工作台分开接收、执行、异常、求助处理者和正式结果。独立人工工作入口不依赖治理来源或绑定 Agent。

结果详情沿用既有 project/task/result 身份及锚点，聚焦指定结果；直接提供工作标题、结果摘要、可核对的验收条件、交付文件与办理动作，历史和设置按需展开。后端验收与完成守卫保持；刷新/409/预览/结果切换保留准确对象意见，回来源恢复受控路由和观察上下文。

首包只改现有前端页面布局与连续性；动态运行时、模板版本、Agent 草稿工具及启用回退另案。64/204 宽度、阈值与视觉排序为可逆假设，合成检查不升级为用户观察或真实产品验收。

## 替代方案

- 平台自动收起与悬浮为默认：释放空间，但混淆手动偏好，对触屏不成立；菜单焦点仍需独立保护。保留细指针实验。
- 同时固定两套宽菜单：入口阅读稳定，但密集办理正文宽度明显减少。允许用户显式固定平台，窄屏转覆盖。
- 单层项目菜单替代平台外壳：项目任务集中，但全局入口和项目归属缺失，无法服务跨项目收件箱和全局 Agent 管理。
- 重写业务状态或创建新验收 API：当前 service 已有对象作用域、版本及完成约束；首包重排复用现有契约，减少语义迁移。

## 风险

旧 sidebarCollapsed 偏好到窄栏/固定态的迁移必须可逆；新项目布局保留既有 URL、route name 与锚点。短期意见缓存的登出清理和跨项目隔离须验证。原型同 DOM 可信外壳不能证明生产 iframe 协议；动态创作仍按加载机制独立定边界。

首包通过后也只能标记其界面分项实施；动态数据、模板、Agent 工具、启用/回退与真实嵌入收尾未闭合时，专项整体保持未完成。真实阅读观察触发的视觉调整允许回改，不改变后端业务不变量。
