## 现存问题与判断

1. **DeepSeek 的 Anthropic Messages 协议与 Base URL 未形成完整产品语义。** 开发环境曾手动把共享供应商地址改为 Anthropic 专用路径，随后一次任务执行成功；这是运行配置试验，不是分支修复。同一供应商切回 OpenAI 协议仍需改地址，与用户要求不符。已暂存的模型配置文档目前描述“协议不会自动变更 Base URL”，在解决设计前须重新审阅，不应把手动操作写成目标流程。先沿模型供应商配置到实际 SDK 请求定位 Owner，再决定属于 Yuanlei 新流程还是上游 Yuxi 缺陷；若属上游，按 fork 流程准备独立修复和 PR。
2. **外部执行器的超时和失败需要分清会话状态与任务状态。** 暂存补丁让 OpenCode 超时、退出原因进入会话状态并显示错误，尚缺真实执行回读。开发环境中的 OpenCode 版本问题按用户要求暂搁；若业务链完全不可用，报告阻断事实即可。失败尝试应保留历史，并提供可追踪的重新委派或恢复入口；项目任务的 `in_progress` 不能冒充正在运行的 AgentRun。
3. **一次新执行的 Agent 报告显示外部委派收集失败。** 报告包含托管工作目录路径被拒、产物汇总失败和委派任务未收敛；这只是 Agent 输出，尚未通过对应数据库、日志、协议结果独立证实。接手时先复现并核对请求、Run、外部会话和产物的同源关系，再判定是调用参数、Yuanlei 集成还是上游 workspace 边界问题。
4. **失败和中断的用户通知覆盖不足。** 当前收件箱主要覆盖首次完成和待答复问询。执行失败、失联投递及重试后的状态变化缺少完整的用户可见闭环；要按源状态提交后的幂等通知意图补齐，避免重复或错配相邻 Run。
5. **交接文档与事实存在滞后。** 阶段提案的总体验收表未随各子阶段的证据收敛；任务 Feature 已明确附件、缩写自动固化、负责人巡检缺口。任何功能完成声明都应回到对应 Feature、Decision、源码和真实 oracle 核实。

## 下一步计划

1. **先处理暂存补丁。** 核对 DeepSeek 文档与用户期望的冲突，审查外部执行器错误传播是否绑定正确会话和尝试，完成独立 Reviewer、相关真实链路验证后再提交；保留目前业务上的默认执行器选择。
2. **闭合协议与地址语义。** 对内置供应商按所选协议产生正确端点，同时保留自定义供应商明确输入的地址语义；以 Anthropic、OpenAI 协议切换和错误地址的负向用例验证。修改上游 Owner 前先读[元垒与 Yuxi 规则](../README.md)并确定差异归属。
3. **定位外部委派产物和恢复链。** 以真实执行记录复现收集失败，修正合法托管工作目录的传递；补齐失败任务的重新委派、历史失败可见性及失联投递恢复 E2E。若 OpenCode 当前环境不可用，记录事实并继续其他业务项，不升级容器工具版本。
4. **完成长期任务能力。** 接入文件附件及项目隔离校验、议题缩写模型生成与固化、第一负责人持久周期核查；分别补真实 HTTP、PostgreSQL、worker 与故障恢复证据。
5. **完成收件箱与管理体验。** 补执行失败通知和含真实通知的浏览器 E2E；检查看板、列表、甘特、新建与委派的实际 DOM 和最终数据库状态，修复易误导或不可操作的交互。
6. **收敛记录与交付。** 更新对应 Feature/Decision 的验收状态，执行最小相关 gate 后按风险扩大测试，并在 PR 中逐项列出已验证事实、风险与未验证范围。
