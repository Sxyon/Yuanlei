# 用项目工作台推进一项任务

本指南面向已经登录、拥有可见项目的用户。完成后，你可以在同一项目中保存蓝图、讨论并审核议题、记录决策、创建任务，最后查看执行和督查结果。项目工作台位于应用内的「项目概览 → 项目工作台」；跨项目入口是「督查板」。

## 1. 写下项目蓝图

进入项目工作台的「项目蓝图」，填写文档名并选择「新建蓝图」。在编辑区写下目标、范围、验收标准和执行计划，然后保存。选择已有蓝图时，页面会从项目 Workdir 重新读取内容；有未保存修改时，页面会阻止直接切换。

蓝图是项目 Workdir 中 `.yuanlei/blueprint/` 下的 Markdown 文件。项目数字员工可以在同一目录起草或修改文件。需要保留旧方案时，选择「归档当前蓝图」；归档文档会从当前列表移到「历史蓝图」，可只读翻阅。归档保存整份文档，不是每次编辑的版本历史。

## 2. 提出议题并形成决策

在「议题与决策」选择「提出议题」，用 Markdown 记录背景、候选方案和待讨论问题。创建后，议题进入待审核状态；打开议题即可修改正文并追加讨论回复。讨论结束后选择「通过并结束讨论」或「拒绝提议」。审核后的正文和讨论保留为只读历史。

在同一区域的「新增决策」填写结论和理由，并关联议题。项目概览中的关系图会根据已有议题、决策和任务关系展示节点；点击节点可查看详情或回到工作台。关系图是已存事实的视图，不单独保存图形状态。

## 3. 创建并委派任务

在「任务与本地执行」填写任务标题、交付物、验收条件和工作范围，可关联议题与决策，并选择项目数字员工。新任务先进入待审核状态；选择「通过」后，已指派的任务才会出现 Codex 或 OpenCode「委派执行」入口。

委派后，在任务下方查看本次执行的状态。执行结束时使用「查状态」和「回收」查看结果与产物路径；一次任务可以保留多次委派记录。编码执行依赖项目数字员工及其专属 Sandbox 配置，设置方法见[编码执行配置指南](../advanced/coding-execution-setup.md)，项目仓库协作见[Project Git 仓库](./project-git.md)。

## 4. 查看督查、汇报与概览

工作台的「督查与汇报」展示本项目待处理事项、失败或中断的执行、运行动态与已有汇报。顶部「项目概览」打开默认 Dashboard，其中展示蓝图、治理关系图、汇报和执行动态。项目数字员工创建静态自定义页面后，Dashboard 改为显示该页面；页面异常时会提示修复并回到默认概览。

应用内的「督查板」汇总当前用户可见项目的待处理数量，并可进入各项目工作台。汇报可记录产出 Run 与文件产物的引用；督查读视图不会改写任务或 Run 状态。周期汇报需要另行配置项目数字员工定时任务，工作台顶部提供「定时汇报」管理入口。

## 范围与下一步

项目蓝图、治理和督查只面向当前用户可见的有效项目。项目数字员工只能在绑定项目运行；审核决定提议能否成为正式治理事实。接入 Multica 后，外部议题与任务也会先进入待审核状态，远端结果不会自动替代项目决策。各模块的事实归属与失败边界见[项目治理、委派与督查机制](../mechanisms/project-governance.md)；差异生命周期见[元垒差异化功能索引](../develop-guides/yuanlei/features/README.md)。
