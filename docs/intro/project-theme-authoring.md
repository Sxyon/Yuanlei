# 制作和使用项目主题

本指南面向项目负责人和主题维护者。读完后，你可以在「项目 → 主题管理」复制或导入一个主题，修改受控定义，预览、发布并分配给项目；不需要阅读源码。

主题不会改变项目业务数据和权限。它只改变项目页面的组织、显示词汇、有限视觉选项，以及可信区块的组合方式。

## 先分清四件事

| 对象 | 作用 | 会不会影响项目 |
| --- | --- | --- |
| 来源 | 主题的归属；平台内置、我的主题或项目专属 | 只决定谁可见、谁可维护 |
| 编辑草稿 | 可修改的定义和候选 ZIP | 不影响已发布版本和项目选择 |
| 已发布版本 | 一次保存后的不可变快照 | 发布本身不会切换项目 |
| 项目选择 | 某个项目当前使用哪个准确版本 | 只有明确“应用主题”才改变 |

来源状态也要分清：**停用**只停止新发布和新选择，已有绑定继续加载；**安全撤回**停止该来源全部版本加载，原绑定和历史保留，需要填写原因。恢复来源不会自动更换项目版本。

## 1. 复制一个可编辑主题

平台内置主题只读。最稳妥的起点是复制一个已发布版本：

1. 打开「项目 → 主题管理」，选择「平台内置」。
2. 选择一个主题，打开「已发布版本」。
3. 在准确版本行选择「创建可编辑副本」，确认名称和归属。
4. 保存后会自动进入「我的主题」中的编辑草稿。

也可以从空白来源开始，但需要上传完整 ZIP；空白来源没有包定义，不能直接预览或发布。

## 2. 编辑草稿时能改什么

编辑器显示的是主题包的 `manifest` 和 `theme` 两段受控 JSON。只能使用系统已支持的字段，不能写任意代码、CSS、HTML、Vue、URL、SQL 或宿主路径。

常用的可编辑内容：

| 你想改的 | 字段 | 说明 |
| --- | --- | --- |
| 作者主题标识 | `theme.id` | 作者声明，不是来源 ID 或权限；复制时通常保持不变 |
| 主题显示名 | `theme.name` | 只影响显示；来源名称在建立／导入时单独设置 |
| 版本标识 | `theme.version` | 发布新内容时必须改成新值；同来源同版本不能换成不同字节 |
| 业务名词 | `theme.topicLabel` | 例如“议题”“课题”“战略规划”；只改界面词汇，不改业务对象 |
| 密度 | `theme.density` | `comfortable` 或 `compact` |
| 主色 | `theme.accent` | `teal`、`blue` 或 `slate` |
| 基础界面 | `theme.baseVersion` | 声明能力页或呈现配置时必须为`1` |
| 整体呈现 | `theme.presentation` | `baseline`、`focus` 或 `research`；后两者需要较新的组件能力 |
| 隐藏导航 | `theme.hiddenCapabilities` | 只隐藏导航呈现，不取消后端权限；不能隐藏总览 |
| 兼容声明 | `manifest.formatVersion`／`componentAbi`／`theme` | 当前分别为`1`、`1`—`3`、`"theme.json"`；按[兼容组合](../advanced/project-theme-reference.md#兼容组合)调整 |
| 页面 | `theme.pages` | 页面的顺序、标题、布局、能力和可信区块 |
| 作者声明 | `manifest.source` | 只是作者声明，不代表来源权限或可信身份 |
| 项目文件 alias | `manifest.files` | 声明项目需要提供哪些资料，不写文件路径 |
| 包内素材 | `manifest.assets` | 声明随 ZIP 携带的 JSON／PNG 及其摘要 |

完整字段、取值、页面／区块类型和示例见[项目主题配置参考](../advanced/project-theme-reference.md)。

### 页面、能力与区块

一个页面只能走两条路之一：

- **能力页**：填写 `capability`，使用平台可信的业务界面（总览、蓝图、议题、行动计划、工作、督查、资料、智能体、设置）。能力页不能同时放自定义区块。
- **展示页**：`capability` 留空，用可信区块组合内容。展示页至少需要一个区块。

支持的 `capability` 值：`overview`、`blueprints`、`topics`、`plans`、`work`、`inspection`、`files`、`agents`、`settings`。同一能力只能声明一次；没有声明的能力会继承基础界面。

支持的区块类型：`summary`、`records`、`topic`、`discussion`、`json`、`image`。每种区块只能绑定系统允许的业务资源或资料 alias，具体对照表见[配置参考](../advanced/project-theme-reference.md#区块类型与绑定)。

### 两类资料不要混

| 类型 | 放在哪里 | 适合什么 | 目标项目需要做什么 |
| --- | --- | --- | --- |
| 项目文件 alias | `manifest.files` 声明 alias 和 JSON／PNG 类型；文件本身不进入 ZIP | 每个项目自己的资料，例如调查数据、项目图片 | 分配或预览时把 alias 映射到该项目 Workdir 中的相对路径 |
| 包内素材 | `manifest.assets` 声明 path、类型和 sha256；文件成员必须在 ZIP 中 | 主题自带、所有项目共用的图标或示例图 | 不需要项目文件；按包内素材读取 |

只想改文字、页面和有限视觉选项时，直接在 JSON 编辑器里修改即可。要新增或替换包内素材，必须重新准备完整 ZIP：JSON 编辑器不能凭空生成素材字节。项目文件 alias 则不把文件放进 ZIP，目标项目使用时再映射。

### 最小示例

下面是一个只改显示词汇和总览的展示型定义。注意 `componentAbi` 为 1 时不能声明能力页或 `baseVersion`：

```json
{
  "manifest": {
    "formatVersion": 1,
    "componentAbi": 1,
    "theme": "theme.json",
    "source": "我的团队",
    "files": {},
    "assets": {}
  },
  "theme": {
    "id": "my-display-theme",
    "version": "1.0.0",
    "name": "我的项目主题",
    "topicLabel": "议题",
    "density": "comfortable",
    "accent": "teal",
    "presentation": "baseline",
    "hiddenCapabilities": [],
    "pages": [
      {
        "id": "home",
        "title": "项目总览",
        "description": "项目摘要",
        "layout": "overview",
        "capability": null,
        "blocks": [
          {
            "id": "summary",
            "title": "项目摘要",
            "type": "summary",
            "region": "main",
            "binding": { "kind": "business", "resource": "project" },
            "variant": "counts"
          }
        ]
      }
    ]
  }
}
```

要使用完整业务页面和能力导航时，`manifest.componentAbi` 至少为 2，`theme.baseVersion` 必须为 1；要使用 `presentation` 非 `baseline` 或 `hiddenCapabilities` 时，组件能力至少为 3。具体组合见[兼容组合](../advanced/project-theme-reference.md#兼容组合)。

## 3. 保存并校验

修改 JSON 后选择「保存并校验」。系统会检查字段、页面/区块引用、alias、素材摘要和 ZIP 成员。校验失败会指出位置，按提示修改后再次保存。

- 预览和发布只使用**已保存**的草稿修订；有未保存修改时不能预览或发布。
- 已发布版本保持原字节。已经发布过 `1.0.0` 后，如果内容发生变化，把 `theme.version` 改成 `1.0.1`、`2026-10-17-a` 等新值再保存和发布。
- 同来源、同版本、同字节可以复用已有发布版；同来源、同版本、不同字节会被拒绝，不能覆盖。
- 新素材必须通过「替换草稿 ZIP」提供完整包；只改 JSON 不能新增素材。

## 4. 预览

预览有两种，界面会明确区分：

- **真实项目预览**：主题声明了基础界面和业务能力时，选择有权项目，填写需要的文件 alias，进入该项目的真实页面。页面读取该项目自己的业务数据和资料，正文只读，不会保存项目选择。未填写的 alias 会显示“未绑定”，而不是用样例数据兜底。
- **合成预览**：只有展示区块的历史主题在主题管理内用合成业务内容预览。包定义和包内素材是真实的，但业务和项目文件内容是明确标识的合成内容。

预览不会改变项目当前主题。离开预览后，已保存的草稿修订和项目选择仍保持。

## 5. 发布

选择「发布新版本」。发布会生成一个不可变版本，记录版本标识、包摘要、大小和发布者；**不会自动切换任何项目**。

发布后用准确版本行的「预览版本」核对效果，再用「分配到项目」明确应用。发布新版本后，项目仍使用旧版本，直到你完成分配。

## 6. 分配到项目

在准确版本行选择「分配到项目」，或从主题管理顶部「项目主题设置」进入：

1. 选择目标项目。
2. 确认拟用版本。
3. 如果版本声明了项目文件 alias，填写当前项目 Workdir 内的相对路径。
4. 检查条件通过后选择「应用主题」。

应用成功会推进该项目的主题 generation，只影响目标项目。共用 Workdir 的其他项目不会被连带切换。要切回旧主题，重新选择旧版本并明确应用；旧映射和文件条件会重新校验，系统不会回滚项目业务数据或文件内容。

## 7. 导出和导入

- **导出**：在已发布版本行先看「包成员」，核对项目文件 alias、包内素材、摘要和不携内容，再选择「导出原包」。下载的是该版本原始 ZIP，不会从页面定义重新打包。
- **导入**：主题管理顶部「导入主题包」选择 ZIP。系统先做只读预检，显示版本、摘要、兼容性、页面、素材和需要重新绑定的文件 alias；取消不产生来源或草稿。
- 确认导入时默认新建个人主题草稿，也可以明确写入有权维护的既有主题草稿。导入只保存草稿，不自动发布或应用。
- 导入到既有主题会替换该主题的编辑草稿，历史和已发布版本、项目当前绑定不变。内置来源不能作为写入目标。
- 结果不明时先重新核实准确草稿，不要重复创建来源；旧草稿修订冲突会刷新目录，保留当前文件和预检摘要。

## 常见问题

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 保存提示字段错误 | 字段名、取值或 JSON 语法不符合契约 | 按错误位置修正；只改允许的字段 |
| 提示需要更高 ABI | 用了能力页、`baseVersion`、`presentation` 或隐藏导航 | 按[兼容组合](../advanced/project-theme-reference.md#兼容组合)调整，或从较新的内置版本复制 |
| 提示 alias 未声明或 MIME 不匹配 | `json` 区块绑定了非 JSON alias，或 `image` 区块绑定了非 PNG alias | 在 `manifest.files`／`manifest.assets` 中声明正确类型，并让区块绑定同一 alias |
| 预览显示未绑定 | 目标项目没有填写该文件 alias | 在预览或分配弹窗填写项目内相对路径；文件不存在或类型不符会被拒绝 |
| 发布提示同版本不同字节 | 改了内容但没有改 `theme.version` | 把版本改成新值，保存并重新发布 |
| 分配后项目没变化 | 只发布了新版本，没有执行分配 | 选择准确版本并明确「应用主题」 |
| 来源不可选 | 来源已停用或安全撤回 | 停用可恢复；撤回需要维护者填写原因后恢复，不能绕过 |
| 包成员缺失或损坏 | 主题文件域缺少原 ZIP 或摘要不匹配 | 用「存储检查与维护」核对；从可信备份恢复原字节，或明确选择其他版本 |

## 限制与安全

- 只支持受控 JSON 和 JSON／PNG 资料；不支持任意 JS、CSS、HTML、Vue 单文件组件、URL、SQL、宿主路径或凭据。
- 不能新增业务能力、业务字段或权限。`capability` 只能使用平台已有值；隐藏导航不等于取消权限。
- 包内素材会随包携带，作者写入的文字和图片不会自动脱敏。导出前请在「包成员」核对内容。
- ZIP、成员、展开内容、页面、区块、alias、单文件大小和 PNG 像素都有上限，详见[配置参考](../advanced/project-theme-reference.md#配额与限制)。
- 主题只改界面组织和有限呈现，不改变项目业务事实、状态机、历史依据、文件权限或项目选择之外的数据。
- 部署维护、备份和恢复由维护者按[主题文件维护与恢复](../advanced/project-theme-storage.md)执行；普通用户不需要操作数据库或主题文件域。
