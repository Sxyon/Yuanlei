# 项目 Git 操作快速入门

本教程面向第一次使用元垒项目 Git 功能的用户。在独立测试仓库中完成一次任务修改、审查、提交、推送和合并，再练习占用排队与失败清理。只使用测试仓库及测试分支，仓库需要包含初始提交。按[初始化](#初始化测试仓库与项目)、[直接修改](#直接修改工作空间)、[隔离任务](#隔离任务与合并)、[审批历史](#查看审批历史)、[恢复清理](#失败恢复与清理)分模块操作。

完成标准是 Gitea 目标分支实际包含练习文件、平台合并请求显示已合并、审批历史可追溯到提交与合并结果。管理员先完成[Git 部署配置](../advanced/project-git-reference.md)，普通用户按本文操作。

## 准备条件

开始前确认以下条件：

- 元垒 管理员已为 API 和 worker 配置 Git 加密密钥与 Gitea origin allowlist，并重新创建这两个服务。
- Gitea 仓库已有默认分支和至少一个 commit；空仓库不能创建任务 worktree。
- 当前用户拥有一个 active、selectable Project。
- Gitea API Token 具有用户读取权限（`read:user`）和仓库读写权限（`write:repository`），用于验证当前用户、读取仓库元数据和分支保护规则，以及管理仓库 deploy key。
- Gitea SSH endpoint 可从 元垒 API 和 worker 容器访问。

管理员配置项和容器网络示例见[Project Git 配置与分支参考](../advanced/project-git-reference.md)。

## 1. 准备 Gitea 信任信息

### 本地 Docker Compose 填写样例

此样例适用于 API、worker 与 `gitea` 服务位于同一 Compose 网络的开发环境。即使宿主机将 SSH 映射为 `2223:2222`，表单仍使用容器内端口 `2222`。浏览器通过 `http://localhost:3300` 打开 Gitea，connection 则通过 `http://gitea:3000` 调用 API。

| 表单字段 | 填写样例 | 说明 |
| --- | --- | --- |
| 名称 | `local_gitea` | 自定义连接名称 |
| API Origin | `http://gitea:3000` | 必须在管理员配置的 allowlist 中 |
| SSH Host | `gitea` | API 和 worker 可访问的容器服务名 |
| SSH Port | `2222` | Gitea 容器内 SSH 监听端口 |
| SSH known-host key | 下方命令取得的完整一行 | 包含主机、密钥类型和完整公钥 |
| Gitea API Token | `<新生成的 Gitea Token>` | 填写实际 Token，具有下方列出的权限 |

独立部署的 Gitea 使用 API 和 worker 可访问的实际地址，例如 API Origin 为 `https://gitea.example.com`、SSH Host 为 `gitea.example.com`、SSH Port 为 `22`。SSH endpoint 必须与 Gitea 返回的仓库 SSH URL 一致；管理员配置见[Project Git 配置与分支参考](../advanced/project-git-reference.md#开发-compose-的-gitea)。

### 取得完整 SSH known-host key

SSH known-host key 保存 **Gitea SSH 服务器的主机公钥记录**，用于确认远端服务器身份。记录由三部分组成，之间以空格分隔：

```text
主机标识 密钥类型 完整的 Base64 公钥
```

下面是一条完整格式的演示记录，使用虚构公钥，仅用于辨认各部分；实际填写时使用自己 Gitea 的输出：

```text
[gitea]:2222 ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIAABAgMEBQYHCAkKCwwNDg8QERITFBUWFxgZGhscHR4f
```

| 部分 | 演示值 | 含义 |
| --- | --- | --- |
| 第一部分 | `[gitea]:2222` | 与表单 SSH Host、SSH Port 一致；非 22 端口使用 `[host]:port`，22 端口直接写 host |
| 第二部分 | `ssh-ed25519` | 公钥类型，也可能是 `ssh-rsa`；保留实际输出的类型 |
| 第三部分 | `AAAAC3NzaC1lZDI1NTE5AAAAIAABAgMEBQYHCAkKCwwNDg8QERITFBUWFxgZGhscHR4f` | 完整公钥内容，保留实际输出的全部字符 |

**表单要粘贴整行，三个部分都要保留。** 只粘贴第三部分，或粘贴 `SHA256:…` 指纹，会导致 `ssh_known_host_key 与 SSH endpoint 不匹配`。公钥内容不能截断或用 `...` 代替。

从仓库根目录运行下面的命令，直接在 API 容器中读取候选记录，输出第一列就是 `[gitea]:2222`：

```bash
docker compose exec -T api ssh-keyscan -T 5 -p 2222 -t rsa gitea 2>/dev/null
```

命令选择开发 Gitea 支持的 RSA 主机密钥。复制以 `[gitea]:2222 ssh-rsa` 开头的完整一行。通过 Gitea 主机控制台或管理员公布的信息核对 fingerprint；`ssh-keyscan` 输出本身只代表远端返回的候选公钥。可用下面的命令计算候选公钥的 fingerprint，核对时使用它，表单仍填写完整记录：

```bash
docker compose exec -T api ssh-keyscan -T 5 -p 2222 -t rsa gitea 2>/dev/null | ssh-keygen -lf -
```

如果从宿主机扫描 `127.0.0.1:2223`，输出第一列为 `[127.0.0.1]:2223`。核对公钥后，只把第一列改成 `[gitea]:2222`，保留密钥类型和公钥内容，再填入 connection。

### 创建具有用户读取权限的 Token

在 Gitea **用户设置 → 应用 → 管理访问令牌** 中创建 Token。本地样例可打开 `http://localhost:3300/user/settings/applications`。选择以下权限，再生成并复制 Token：

| 权限类别 | 选择 | Scope | 用途 |
| --- | --- | --- | --- |
| user | 读取 | `read:user` | 创建 connection 时调用 `/api/v1/user` 验证当前用户 |
| repository | 读写 | `write:repository` | 查询仓库、分支保护规则，管理 deploy key 和合并请求 |

**user 读取权限必须勾选。** 只有 repository 权限时，Gitea 的 `/api/v1/user` 会返回 `403 Forbidden`，页面显示 `无法验证 Gitea connection`。此步骤通过 HTTP 验证 Token，修改 SSH 端口无法解决该权限错误。账号本身还需拥有目标仓库的相应权限。

Token 只在 connection 创建或更新时提交一次，页面和 API 响应不会返回原值。

## 初始化测试仓库与项目

### 创建专用仓库

1. 打开自己的 Gitea 网站，登录拥有创建仓库权限的账号。
2. 点击页面右上角“+”，选择“新建仓库”。
3. 仓库名填写 `yuanlei-git-quickstart`；若名称已存在，追加自己的练习编号。
4. 勾选初始化仓库，包含 `README.md`，默认分支填写 `main`，选择私有仓库。
5. 点击“创建仓库”。确认文件列表出现 `README.md`，分支选择器显示 `main`，提交列表至少有一条记录。
6. 在仓库分支选择器中输入 `practice-direct`，选择从 `main` 创建分支。此分支用于直接修改练习，`main` 用于隔离任务的合并目标。

### 在元垒创建项目

1. 登录元垒，点击左侧“个人空间”。
2. 展开“上传文件”按钮右侧的菜单，选择“新建文件夹”，输入 `git-quickstart`，点击“创建”。确认文件列表出现该文件夹。
3. 点击左侧“新建对话”，在输入框上方点击“选择项目”，再点“新建项目”。项目名称填写“Git 入门练习”，在项目目录列表点击刚创建的文件夹，确认路径后点击“创建并选择”。确认左侧项目列表出现该名称。
4. 打开项目旁的“项目操作”，选择“项目设置”。属性中保持“计划中”“无优先级”和默认负责人；开始、截止日期可以为空。
5. 在名称与描述区域填写说明，例如“专用测试仓库，练习 Git 提交和合并”，保存后重新打开设置，确认内容保留。

### 创建连接

1. 在“项目设置”进入“资源”，打开“Git 资源”，切换“Connections”。
2. 如果已有可用 Gitea 连接，直接复用；新平台点击创建入口。
3. 按上方已核对的信任信息填写名称、API Origin、SSH Host、SSH Port、完整 SSH known-host key 和 Token。
4. 点击“创建 connection”。确认列表显示名称及 SSH endpoint，Token 输入框已清空。
5. 若失败，先按本文准备条件检查 Token scope、服务器公钥和容器访问地址，再重试。

### 下拉选择仓库与分支

1. 切换“仓库”页签，选择连接。
2. 在仓库下拉列表选择刚创建的 `yuanlei-git-quickstart`。仓库 owner 和名称从 Gitea 读取。
3. 确认分支列表已经加载；新增时默认选中远端默认分支 `main`。直接修改练习改选 `practice-direct`。
4. 资源名称（Alias）填写 `direct`，目录填写 `direct`，使用模式选择“直接修改这个文件夹”，授权模式选择“受保护”。
5. 点击“绑定仓库”，等待状态由准备中变成可用。失败时查看错误摘要，修正后点击重试。
6. 在项目文件区打开 `direct/README.md`，确认该目录是 `practice-direct` 的完整仓库内容。模式与授权设置相互独立；“受保护”要求平台提交、推送和合并经过人工决定。
7. 再添加一条资源，选择同一仓库的 `main`，资源名称（Alias）填写 `isolated`，目录填写 `isolated`，使用模式选择“并行隔离运行”，授权模式保持“受保护”。等待资源可用。

两条资源属于同一仓库，但有不同目录、分支与执行方式。任务可以修改各自检出的完整仓库；目录名称只是业务分工，不限制仓库内修改范围。

## 直接修改工作空间

### 指挥智能体修改文件

1. 在左侧项目旁点击“在此项目中新建对话”，确认输入框上方选中“Git 入门练习”。
2. 保持“请求审批”，选择具有沙盒文件工具的智能体及可用模型。
3. 输入并发送下列指令。资源名称与前面配置一致；新建练习分支时，先确认 `practice-direct` 已存在。

```text
只使用当前项目的 direct Git 资源。先列出项目仓库，再申请准备此资源工作区，基线 practice-direct，类型 test，slug direct-lesson，用途为直接修改入门练习。等待需要的人工批准。然后在返回的项目资源目录创建 direct-lesson.txt，内容为 Direct workspace lesson，末尾换行。不要通过 shell 提交或推送。查看可信 Git 差异并报告后停下，交给我处理成果。
```

4. 智能体调用准备工作区工具后，如对话显示审批请求，展开参数，核对资源名称、基线和用途，再批准。
5. 等待这一轮运行结束。在项目文件区打开 `direct/direct-lesson.txt`，确认内容已经出现在项目空间。直接修改模式持续占用此任务或对话的实际目录。
6. 打开“项目设置 → 资源 → 占用与排队”，查看资源、当前任务或对话、目录、分支及运行状态。运行结束不等于释放目录。

### 人工提交与推送

1. 进入“项目设置 → 资源 → 仓库”，在 `direct` 卡片点击“查看改动与提交”。
2. 读取文件列表和 diff，确认只有练习内容；记住本次审查对应的 HEAD 和内容树。
3. 填写提交说明，例如 `test: 完成直接修改练习`，点击提交操作。平台检查本次审查快照，变化时要求刷新后重新确认。
4. 重新读取审查结果，确认未提交内容为空且 HEAD 已变化。
5. 点击推送操作，确认分支为 `practice-direct`。结束后在 Gitea 切换到该分支，打开 `direct-lesson.txt`，确认文件内容与提交记录。
6. 在“审批与历史”查看人工提交、推送的记录，核对操作人、批准依据、时间及成功结果；提交成功与推送成功是两个动作。

### 排队与释放

1. 保留第一个对话的目录占用，在同一项目另建对话，让智能体申请相同 `direct` 资源。
2. 进入“占用与排队”，确认第一个对话仍为当前占用者，第二个出现在等待序列，并显示队列位置。
3. 先处理第一个对话的修改、提交与推送；确认其根运行及子运行均已结束。
4. 在资源使用信息中执行释放占用。释放后刷新，确认第二个对话获得目录，继续其运行。
5. 第二个对话结束后同样检查成果并释放。执行失败时先读取现场，按[失败恢复与清理](#失败恢复与清理)处理。

## 隔离任务与合并

### 创建稳定任务或对话

1. 打开项目的“项目操作 → 项目工作台”，进入“项目工作任务”。
2. 点击“新建任务”。首次使用先填写项目编号缩写，例如 `GIT`；填写标题“隔离 Git 入门练习”，任务详情包含下方指令。
3. 选择项目智能体为第一负责人，点击“创建任务”。任务详情中选择执行智能体，点击“分配任务”；需要接受时在执行记录点击接受，再点击“进入执行会话”。项目没有智能体时先在项目智能体管理中创建并配置可用模型与沙盒。
4. 也可以在项目中新建对话直接发送指令。普通项目对话以对话作为稳定作用域；项目任务的连续执行、重试或转派则复用任务作用域。

```text
只使用当前项目的 isolated Git 资源。先调用 git_list_project_repositories 确认仓库，再调用 git_prepare_worktree，从 main 创建 test 类型、slug quickstart-guide 的隔离工作区，用途为新人入门验证。需要审批时等待批准。准备完成后在返回的工作区创建 lesson.txt，内容为 Yuanlei Git quickstart，末尾换行。不要通过 shell 执行 git commit 或 push。调用 git_review_workspace 报告未提交差异后停下，交给我通过项目资源界面提交。
```

5. 当对话出现“是否允许执行此工具操作？”，核对工具是 `git_prepare_worktree`，参数中的资源为 `isolated`、基线为 `main`，点击“允许”。
6. 等待智能体停止后，打开“项目设置 → 资源 → Worktrees”，确认新工作树为 ready，记录完整任务分支名称（默认以 `agent/` 开头，管理员可以配置前缀）。它是新建测试分支，项目资源目录 `isolated` 继续展示检出的 `main`。
7. 在该工作树查看改动，确认新增 `lesson.txt`，内容正确。新建另一个任务申请同资源时应出现另一条工作树；同一任务多轮使用原工作树。

### 提交、推送、发起请求

1. 在 Worktrees 对应记录展开成果操作，读取未提交文件和 diff。
2. 填写提交说明 `test: 添加 Git 入门练习文件`，点击“确认提交”，再在提示中点击“确定”。刷新确认未提交内容为空，新 HEAD 对应本次修改。
3. 点击“确认推送”，在提示中点击“确定”，确认该 `agent/…` 分支在 Gitea 出现且包含 `lesson.txt`。提交只是本地记录，推送才同步远端。
4. 切换“仓库”，在 `isolated` 卡片展开“Gitea 合并请求”，点击“刷新合并请求与任务分支”。
5. 选择刚推送的任务分支作为源分支，`main` 作为目标分支，填写标题“合并 Git 入门练习”和变更说明，点击“创建 Gitea 合并请求”。
6. 刷新请求列表，确认请求编号、源/目标分支、当前源/目标 SHA 和状态。点击请求链接查看 Gitea；开发 Compose 的链接若包含容器主机名 `gitea:3000`，在已经登录的 `http://localhost:3300` 打开测试仓库，进入“合并请求”并选择相同编号。独立部署使用实际浏览器地址，详见[部署参考](../advanced/project-git-reference.md#开发-compose-的-gitea)。
7. 查看 diff，确认 `lesson.txt` 是本次变更。若目标分支有新提交、源分支改变或有冲突，先刷新并处理；旧审查快照不会继续执行。
8. 请求显示开放且可合并时，点击“确认并执行合并”，核对确认信息后执行。
9. 刷新请求列表，确认已合并；在 Gitea 切换 `main`，打开 `lesson.txt`，检查最终内容。合并请求已创建或批准都不代表实际合并完成。

### 让智能体申请后续 Git 动作

1. 在同一执行会话让根智能体读取可信差异，再申请 commit、push。不要给沙盒注入 Gitea Token 或 deploy key。
2. 到“审批与历史”找到待人工批准的动作，展开查看冻结的 HEAD、内容树、diff 和提交说明，点击批准或拒绝。
3. 等待执行结果变为成功，再让智能体回读动作状态，继续下一步。
4. 推送成功后，可以指挥：“查看 isolated 当前任务的合法合并目标，并向 main 创建标题为‘合并入门练习’的合并请求；回读编号和源/目标 SHA。”根智能体使用 `git_list_pull_requests` 与 `git_create_pull_request`。
5. 再指挥：“基于当前合并请求的源/目标 SHA 申请实际合并，并回读结果。”受保护目标仍等待人工批准。
6. 自动授权资源按规则记录批准依据再执行，仍需核对最终成功记录和远端结果。自动授权代表允许 Git 操作，代码质量由项目采用的审核流程决定。

### 子任务与转派

1. 新建子任务时选择父任务，进入子任务详情的“子任务 Git 工作区”。
2. 默认“共用父任务工作区”；若需独立验证，执行前选择“从父任务已提交 HEAD 创建独立工作区”，保存。
3. 父任务先提交需要验证的内容。独立子任务从这一提交创建工作树，未提交内容不会自动复制。
4. 工作区模式在执行或分配后固化；不能通过切换模式改写历史归属。
5. 失败执行结束后，在同一任务选择另一项目智能体再分配，或重试该任务。保持同一任务，才能复用既有工作树与成果；不要另建任务冒充转派。

## 查看审批历史

1. 打开“项目设置 → 资源 → 审批与历史”，刷新列表。
2. 找到提交、推送或合并动作，点击“查看动作与时间线”。
3. 核对资源、任务或对话作用域、智能体、Run、申请时间、审批方式及理由。
4. 阅读冻结的审查 SHA 与 diff。人工批准显示批准人；自动批准显示规则依据和申请运行。
5. 按时间线查看申请、批准、开始执行和完成。pending、approved、running 都是中间状态；成功结果才表明动作执行完成。
6. 失败时阅读错误摘要，再回到工作树、Gitea 分支或合并请求查看实际状态。外部操作有不确定结果时，先回读再决定，避免重复操作。
7. 待人工批准的记录可批准或拒绝。批准后内容或策略改变会拒绝执行，需要重新审查并申请。

## 失败恢复与清理

### 保留现场并转派

1. 进入“占用与排队”，检查当前占用者、活动运行、heartbeat 和 lease 状态；进入 Worktrees 查看工作树状态。
2. 打开原任务详情的执行记录，检查错误和 Run。失败或 worker 崩溃不会自动抹去文件与任务分支。
3. 运行仍在活动状态时先通过原执行渠道取消或等待恢复结局；活动根运行及其子运行会阻止人工成果操作和清理。
4. 运行结束后点击“查看改动与提交”，检查现场。希望保留修改时人工提交并推送，或在原任务转派另一智能体接续处理。
5. 只释放目录占用不会删除任务、提交或远端分支；工作树回收则移除本地目录，包括忽略文件。先把需要保存的忽略文件转移到其他安全位置。

### 丢弃和安全清理

1. 确认练习修改可以丢弃后，在审查面板选择“丢弃未提交改动”，核对确认提示后执行。该操作无法撤销，忽略文件保留。
2. 刷新并确认工作区没有未提交修改。需要保留的提交先完成推送，回读远端分支 HEAD。
3. 对隔离资源，在 Worktrees 点击“安全清理”，阅读包含忽略文件的目录回收提示，再确认。
4. 等待异步清理结束，确认工作树目录移除；Gitea 任务分支和提交仍保留。后续同一任务可从保留分支重建工作树。
5. 对直接修改资源，处理修改后在“占用与排队”释放占用，保留项目资源目录。
6. 如果任务未提交、未推送或仍有活动执行，清理会拒绝并显示原因。先解决对应原因，再重新读取状态。

### 标记任务完成

1. 在任务详情或任务列表选择“已完成”。平台先检查未提交、未同步、未合并、未回收及未释放内容。
2. 弹出“任务仍有 Git 成果需要处理”时，选择“先处理成果”，在资源管理完成上述动作后重新标记。
3. 希望稍后处理时，明确选择“保留成果并标记完成”。任务完成会保留成果和占用，之后仍需人工处理。
4. 无法读取本地或 Gitea 状态时，提示会保留错误。先修复连接和现场，或明确选择保留；不能把状态读取失败当作成果已经处理。

## 知识库选项与项目管理属性

1. 在“项目设置 → 资源 → 知识库”选择自己当前有权访问的知识库，点击“保存知识库关联”。重新打开确认关联保留。
2. 打开项目任务详情，在“任务知识库”选择本任务需要的关联知识库，点击“保存知识库”。默认不选；任务有待接受或运行中的执行时不能改变选择。
3. 配置项目智能体时，知识库候选中“项目关联”标注便于识别；只选择需要的知识库并保存配置。任务选择叠加在智能体配置上，关联本身不自动授予权限。
4. 发起执行时仍按当前用户的实际权限检查。权限撤销后，项目关联和历史选择不会恢复读取权。
5. 在项目属性修改状态、优先级、负责人和日期，再保存回读。负责人仅记录责任归属；状态变更不会终止或禁止运行。截止日期不能早于开始日期。

## 练习结果核对

| 模块 | 最终应观察到的结果 |
| --- | --- |
| 初始化 | 下拉列表来自 Gitea；完整检出所选分支；资源状态 active |
| 直接修改 | 文件出现在项目目录；推送后远端同分支包含文件 |
| 隔离任务 | 不同任务独立分支；同任务连续执行复用工作树 |
| 合并 | 平台请求显示已合并；Gitea 目标分支包含练习文件 |
| 审批 | 人工或自动批准依据、审查快照、实际结果和时间线可查 |
| 排队 | 当前占用者和 FIFO 等待位置可查；释放后下一任务继续 |
| 恢复清理 | 失败现场可审查；未提交或未同步时拒绝回收；分支保留 |
| 知识库 | 显式选择保存；非关联或无权限候选不能加入任务 |

任务分支前缀由管理员配置，默认 `agent/`；已有平台使用其他前缀时，以 Worktrees 实际分支为准。练习命令中的源分支均从平台复制，避免手填或猜测。
