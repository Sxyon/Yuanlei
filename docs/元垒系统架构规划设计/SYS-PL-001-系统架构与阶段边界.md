# SYS-PL-001｜系统架构与阶段边界

本页解释个人优先的产品架构、核心对象与三阶段范围，供产品设计和专项接续使用。真实运行边界见[ARCHITECTURE.md](https://github.com/Sxyon/Yuanlei/blob/main/ARCHITECTURE.md)，完成与暂停事实见[目录入口](README.md)中的专项LOG。

## 产品与业务闭环

元垒作为个人及企业的AI中枢，在项目中连接方向、研讨、决定、工作、交付、验收与复盘。平台承载跨项目入口、聊天、收件箱及本人共享配置；项目承载自身业务、资源和主题界面。分类与标签表达领域，负责人表达责任。

项目允许直接创建人工工作；议题、决定和Agent均为可选来源。复盘可以更新蓝图、重议议题或形成新决定，原输入、批准依据和已接受结果继续保存。目标关系见<a href="图解/01-platform/platform-target.html" target="_blank" rel="noopener">系统目标图</a>，图中模块表示业务职责。

## 核心对象

| 对象 | 职责与边界 |
| --- | --- |
| 项目 | 长期经营或阶段交付的业务空间；UUID拥有身份，分类／负责人不授予权限；共用目录会共享文件字节 |
| 蓝图 | 方向、目标、约束与复盘；Workdir Markdown拥有正文事实 |
| 议题 | 问题、方案、持续讨论及证据；纳入资格、研讨进度和目标结果各自表达 |
| 决定 | 已批准选择及依据；草案、勘误、补充、替代、撤销分别保留版本与历史，可有多条有效决定 |
| 工作 | 一次业务范围、责任和验收条件；可无议题、决定或Agent |
| Context Pack | 本次要求、资料、依据及来源指纹；执行前冻结，同次派发重试沿原输入，新尝试明确重新组装；引用和hash不保证旧字节可重放 |
| 执行尝试 | 一次分配、接受、派发和执行；人工提交不虚构AgentRun，业务attempt与网络重试分开 |
| 结果与验收 | 准确交付及业务接受；Run终态、结果接受、工作完成、目标达成分别判断 |
| 项目主题 | 组织全部项目页面及办理；业务身份、状态、权限和审计由原Owner执行 |
| 协作与Andon | 准确委派、问题逐级处理、答复采用与恢复；完整目标冻结待接续 |

归档表示退出日常关注；拒绝、关闭、目标达成与删除沿各自业务规则执行。正式工作来源决定ID与冻结修订成对，当前决定不替换执行当次依据。机制和差异见[项目治理](../develop-guides/yuanlei/features/project-governance.md)、[项目工作](../develop-guides/yuanlei/features/project-work-tasks.md)及相关Decision。

## 事实与界面边界

PostgreSQL拥有业务身份、关联、修订、状态和结果；Workdir／对象存储拥有文件字节。业务关系图由关联派生，Neo4j继续承担知识关系。权限在后端依赖及repository查询最终执行，Context Pack引用、负责人字段、前端隐藏和主题词汇均不授予访问权。

主题采用受控定义与平台可信Vue能力组合，覆盖全部项目界面及详情／编辑／历史。平台明暗样式共享，项目主题改变组织与有限呈现；静态自定义Dashboard保留无脚本隔离边界。详见[主题设计](SYS-DB-001-Dashboard系统需求与架构设计.md)和[静态Dashboard Feature](../develop-guides/yuanlei/features/project-dashboard.md)。

## 阶段边界

| 阶段 | 预期结果 | 进入与完成条件 |
| --- | --- | --- |
| 第一阶段：个人日常闭环 | 项目、蓝图、持续议题、决定、工作、准确结果与Context Pack；人可维护的项目主题 | 按实际链路和专项验收判定；主题暂停、协作目标未完成，因此总体第一阶段仍有残余 |
| 第二阶段：持续业务按周期收敛 | 工作定义与周期实例、周期汇报、规则监控 | 日常闭环稳定且有真实重复需求后细化，避免永久in_progress代替周期归档 |
| 第三阶段：中小公司协作 | 组织归属、真实成员、共享权限、角色与审计 | 基于实际多人场景设计；共享文件／知识库／Agent及Context Pack引用均纳入后端授权，弱负责人字段保持责任标识 |

第二阶段的周期定义需明确时区、窗口边界、唯一周期键、重叠、漏跑、补跑和重试；暂停停止未来调度并保留已产生实例及历史。周期汇报的业务窗口与汇总执行尝试分别记录。监控需明确对象、频率、异常条件、通知去重和后继行动。目标、Proposal和多对多关系只在真实消费者需要时提取。现有定时Agent、规则巡检和一次性任务继续由各自Owner解释，当前没有统一替换承诺。

个人用户明确授予Agent的有限正式批准属于第一阶段目标，范围冻结在[协作设计](SYS-CA-001-协作接入与Andon系统设计.md)；组织审批与转授属于第三阶段。

## 验收与历史证据

跨阶段验收关注人工工作直达、治理到工作、准确Agent交付、旧依据复核、新尝试上下文、跨项目同名对象、失权／并发与复盘。局部主题成果不代表这些链路全部完成。历史平台证据及仍未完成的真实Codex／Multica出向验证见[平台证据摘要](LOG-PL-001-平台能力证据与待验边界.md)。协作冻结资源和真实Provider边界见[暂停状态](LOG-CA-001-协作接入与Andon暂停盘点与事实进展.md)。
