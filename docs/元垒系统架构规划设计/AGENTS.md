# 专项管理文档约定

- 当前入口由[目录README](README.md)拥有；归档只供历史追溯，不领取其中旧任务。当前SYS/DEV/LOG在本目录维护，图解与回执在图解目录。
- 专项任务先读[推进与设计汇报机制](DEV-MG-001-专项推进与设计汇报机制.md)，再读该任务的SYS/DEV/LOG；读取当前源码重建实际状态。
- SYS拥有需求、系统设计和取舍；DEV拥有实施包及技术约束；LOG拥有实际状态、用户确认依据、执行反馈和证据引用。按类型-专项-三位编号命名，修订同职责文件，不另造并行主规划。
- 涉及页面组织、核心操作、架构边界、范围变化时先交完整编号图及模块理念、替代比较、推荐和风险，供用户审阅设计。已有产品代码保留，未确认新设计时仅做隔离设计稿及独立已授权工程准备。
- 相关汇报的架构、关系、流程、序列和状态图使用archify，读取技能并交付校验后的HTML及证据；页面布局草图另备，图号与模块编号对应。技能不可用先报告，不静默替换。
- 确认依据记录原用户消息/会话和对应稿版本、范围；Agent建议、Reviewer通过、无回复和原型操作记录不能冒充用户确认。
- 每轮先汇报目标与设计变化、范围/风险，再汇报模块实现、取舍、依赖和证据。模板与否决条件由上述机制维护。
- 协作接入与Andon保持暂停，恢复须用户明确指令。管理文档调整不授予外部试验或正式业务权限。
