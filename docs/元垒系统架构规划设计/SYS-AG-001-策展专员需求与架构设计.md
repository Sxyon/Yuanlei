## 1. 问题与目标

### 1.1 背景

当前主题与 Dashboard 的工程能力已有实现，但缺少可重复的真实业务场景和数据来验证“项目事实→主题/Dashboard→项目使用”的完整闭环。用户计划先投入模拟业务生态，通过实际操作验证专项能力，再决定产品化范围。

构想的生态流程是：项目智能体产生项目数据；策展专员读取项目空间、项目资源和会话信息，完成汇总与规划；策展专员据此生成自定义主题和项目 Dashboard，用来展示业务数据、图表、重要信息和目标。

### 1.2 目标

建立“策展专员”的可讨论需求：

- 作为项目数字员工运行，严格绑定项目，使用调用用户身份和项目权限。
- 能读取项目事实：议题、决定、工作、督查板、项目文件、当前主题与 Dashboard。
- 能按项目事实生成主题草稿和 Dashboard 草稿。
- 能通过定时任务周期性汇总指定项目的数据，生成可复用的项目产物。
- Dashboard 要能漂亮、有动画、动态展示数据，视觉上有“活着”的感觉；色彩、字体和布局可按项目属性与个人偏好定制，不要求和平台风格一致。
- Dashboard 支持页面内全屏和浏览器全屏；户外大屏可用 kiosk 模式部署，作为部署配置记录。
- Dashboard 默认同时生成 PC/大屏和窄屏两套变体，由宿主完成窄屏/大屏切换。
- 生成结果默认是草稿；发布主题、应用主题、覆盖线上 Dashboard 保留明确的人工确认。
- 每次运行有可追溯的 Run、输入、产物路径、校验结果和失败原因。

### 1.3 非目标

- 不自动发布主题，不自动把主题应用到项目。
- 不新增通用插件框架、自动扫描协议或第二套权限系统。
- 不恢复已暂停的主题专项；主题契约或平台能力的变更需要单独授权。
- 首版不开放任意外部网络、同源权限、平台凭证或跨项目数据聚合；Dashboard 脚本只在受限沙箱内运行。
- 不在本阶段确定最终页面布局、视觉细节和完整验收清单。

## 2. 加工后的需求

### 2.1 角色与运行方式

策展专员是项目范围内的角色，可以绑定到一个项目；项目外的运行必须被拒绝。它可以使用项目工作目录、项目文件、项目会话和项目智能体资源，但不能读取其他项目的数据。

首版按“一个根智能体 + 可选只读子智能体”讨论。根智能体负责生成和写入；子智能体可承担只读汇总、资料整理和事实核对。当前 Dashboard 和督查工具明确拒绝子智能体运行时，写入必须留在根运行。

### 2.2 主题维护

主题维护需要覆盖：

- 读取当前主题、候选草稿、已发布版本和项目当前绑定。
- 读取项目事实和项目文件，形成本次主题调整依据。
- 生成主题草稿包，包含 manifest、theme.json、页面/区块定义，以及必要的 JSON/PNG 资源。
- 执行预检、契约校验、资源 alias 校验和预览。
- 输出变更摘要，说明修改了哪些页面、区块、数据绑定和资源。
- 由人明确发布版本、应用主题；策展专员不自动发布、不自动应用。

主题来源类型、是否允许策展专员创建项目专属来源、是否允许修改既有来源候选，仍需在实施前确认。当前主题服务已经支持个人来源和项目来源，授权由 service/repository 按用户和项目执行。

### 2.3 Dashboard 维护

当前 v0 项目 Dashboard 是 `dashboard/index.html` 的静态 HTML/CSS 页面，数据库保存 revision、hash 和大小；写入要求 `expected_revision`，拒绝脚本、`meta` 和页面导航，读取时用无脚本、无网络 CSP 的 iframe 渲染。它只出现在 `presentation: baseline` 的总览页“业务大屏”入口中；`focus` 和 `research` 呈现不会显示这个业务大屏。

当前嵌入规则：

- 主题页面通过 `capability: overview` 使用平台可信总览；主题可以改名、排序和选择呈现，不能替换总览内部组件。
- 自定义 Dashboard 作为总览内的“业务大屏”二级视图出现，只在 `presentation: baseline` 可见。
- 展示页和普通区块不能嵌入自定义 Dashboard；主题包不携脚本、CSS 或组件代码。
- iframe 固定使用 sandbox，CSP 为 `default-src 'none'`、`style-src 'unsafe-inline'`、`img-src data:`、`connect-src 'none'`，不提供网络和同源能力。
- 页面不允许 `<script`、`meta`、表单、frame、object 和非页内锚点链接。

目标形态与当前 v0 有明显差异：

- 视觉上要“活”：支持动画、过渡、动态图表、数据变化和交互反馈，不要求沿用平台视觉风格。
- 色彩、字体、布局和装饰可按项目属性、业务主题或个人偏好定制，允许五彩斑斓的视觉表达。
- 独立 Dashboard 可以使用自己的色彩、字体和布局；主题声明式页面仍受 `theme.json` 的 `accent`、`density` 和 `presentation` 约束。让主题页面也完全自由配色需要扩展主题契约，或把强视觉表达集中到 Dashboard。
- 支持页面内全屏和浏览器全屏；户外大屏可用 kiosk 模式部署，详见下节。
- 数据可以随定时任务或人工重生成更新；实时刷新作为后续能力讨论，不作为首版硬前提。
- 视觉表现不能以牺牲可访问性和性能为代价：支持 `prefers-reduced-motion`、足够的对比度、明确的加载/空/错状态和合理的动画帧预算。

屏幕策略：

- 默认同时生成桌面/大屏和窄屏两套 Dashboard；两套分别按各自屏幕目标设计，不要求大屏页面在窄屏下重排。
- 宽窄两套同批生成；增量生成成本低于用户在窄屏上体验受损的代价，窄屏变体不依赖用户额外说明。
- 宿主负责完整的窄屏/大屏切换：按断点自动选择对应变体；切换失败或某一变体不可用时显示明确提示，不显示半成品。
- 切换不改变项目绑定、数据权限和当前数据快照；同一轮生成的宽/窄变体应共享数据来源和生成时间，避免两套数据不一致。
- 切换保持滚动位置、交互状态和全屏状态；提供手动切换入口用于预览和演示。
- 窄屏变体的存储、发布和 revision 关系待确认：需要明确“同一版本包含两套布局”还是“两个关联页面/版本”。
- 该策略只适用于自定义 Dashboard；平台页面、主题能力页、弹窗和设置仍遵守现有窄屏要求。
- 断点由宿主拥有，专项确认后固定；不要求每个区块单独做窄屏适配。

全屏层级与户外展示：

| 层级 | 效果 | 实现方式 | 当前边界 |
| --- | --- | --- | --- |
| 页面内全屏 | Dashboard 铺满平台内容区，隐藏侧栏、导航和页头 | 宿主路由/状态 + CSS，提供退出入口 | 不隐藏浏览器边框 |
| 浏览器全屏 | 铺满当前屏幕，多数桌面浏览器隐藏地址栏和标签栏 | Fullscreen API，用户点击后对 Dashboard 容器或 iframe 调用 `requestFullscreen()` | 必须由用户手势触发；iframe 需要 `allow="fullscreen"`；不同浏览器表现略有差异 |
| 系统/Kiosk 全屏 | 真正无浏览器边框，适合户外大屏和无人值守 | 浏览器启动参数（如 `--kiosk`、`--start-fullscreen`），配合开机自启、自动登录、禁用休眠和断线重连 | 属于部署方式，网页不能强制开启或完全隐藏浏览器边框 |
| 多屏/视频墙 | 跨多个物理屏幕展示 | 操作系统或播放器层面处理 | 网页只能控制所在窗口，不能控制屏幕拓扑 |

全屏实现要求：

- 宿主提供统一的全屏入口和退出入口；进入/退出不丢失当前数据、滚动位置和交互状态。
- iframe 增加 `allow="fullscreen"`；是否允许脚本自身调用全屏由宿主策略决定，默认由宿主控制。
- 浏览器全屏必须由用户手势触发；不做页面加载自动全屏，也不承诺绕过浏览器安全限制。
- 户外大屏使用 kiosk 模式作为部署配置，记录目标 URL、浏览器 profile、自动登录、休眠、刷新和断线恢复方式；kiosk 不作为网页功能承诺。
- 全屏不改变数据权限；全屏状态下的脚本仍受 sandbox 和 CSP 约束。

脚本与安全边界：

- 动画和动态交互通常需要脚本。目标形态允许 Dashboard 在沙箱 iframe 内执行脚本，但脚本只承担呈现和交互，不获得平台同源、Cookie、Token 或项目接口访问权。
- iframe 使用 `allow-scripts`，不授予 `allow-same-origin`、`allow-top-navigation`、`allow-forms`、`allow-popups` 或 `allow-modals`；脚本运行在不透明源中。
- CSP 至少保持 `default-src 'none'`、`script-src 'unsafe-inline'`、`connect-src 'none'`、`object-src 'none'`、`frame-src 'none'`、`form-action 'none'`、`base-uri 'none'`；允许内联样式、脚本、`data:`/`blob:` 图片和字体，禁止外部 CDN 和网络请求。
- Dashboard 源码视为不可信内容：策展专员从项目数据生成 HTML/JS 时，项目内容可能包含提示注入或恶意脚本，不能因为作者是策展专员就信任。
- 应用前必须有人工预览和显式确认；预览要展示实际脚本运行效果、数据来源和外部请求检查结果。
- 如果首轮无法接受脚本风险，可以退回声明式主题页面或静态图片方案；这会牺牲部分视觉表现，需要产品明确取舍。

数据供给与刷新：

- 生成时快照：脚本和样式内联，数据随 HTML 一起写入；动画和交互可完整运行，数据在下次生成前保持不变。
- 只读宿主 bridge：宿主在 iframe 加载后通过 `postMessage` 或 `MessageChannel` 提供当前项目、当前用户有权读取的结构化数据；脚本只能读取，不能写业务数据、不能带凭证、不能发起网络请求。
- bridge 需要版本化消息协议、字段白名单、数据大小上限、过期/撤权处理和错误状态；不能把整个项目数据库或任意接口透传给页面。
- 运行时服务端接口：页面直接请求项目数据接口。首版不采用，网络、鉴权、数据最小化和防外泄成本明显高于前两种。

生成规则候选：

- 数据必须来自本次运行有权读取的项目事实或项目文件，生成物记录数据时间、来源范围和运行引用。
- 生成前先读取当前主题/Dashboard 和 revision/version，冲突时拒绝写入并保留现场。
- 生成物先经过主题契约、资源类型、alias、大小、脚本/外链策略和 HTML 结构校验，再进入预览。
- 指标和图表不得编造或补全缺失数据；缺失、过期和无权数据要显式显示，不能静默省略。
- 同一输入和同一数据快照的重复生成应可重复、可比较，避免每次运行产生无意义差异。
- 视觉验收覆盖宽窄两套：大屏验证动画、动态图表、全屏和 `prefers-reduced-motion`；窄屏变体验证切换、状态保持、空态和错误态；不要求大屏页面在窄屏下完整兼容。

### 2.4 项目数据协议

现有可复用的数据入口：

- 项目治理事实：督查板、议题、决定、工作、结果。
- 项目工作目录和项目文件：主题 manifest 通过 `files` alias 绑定 JSON/PNG。
- 命名 JSON 文档：`project_documents` 以 `(project_id, key)` 唯一，带单调 version，单份上限 256 KiB；当前有 HTTP 读写接口，尚未暴露给 Dashboard iframe。
- 主题包契约：页面、区块、资源 alias 和项目文件绑定均由 `project_theme_contract.py` 校验。

候选协议方向：

1. **脚本 + 生成时快照**：策展专员读取项目事实，生成自包含的 HTML/CSS/JS，把数据内联进页面；脚本可以播放动画、驱动图表和交互，数据在下次生成前保持不变。优点是视觉表现最强，当前安全模型只改 iframe 策略和 CSP；缺点是需要重新评估脚本风险、页面体积和生成质量。
2. **脚本 + 只读 bridge**：页面加载后由宿主提供当前项目、当前用户有权读取的结构化数据；脚本负责渲染和交互，数据可刷新。优点是可以“活”起来且数据可更新；缺点是需要新的消息协议、字段白名单、撤权和注入防护。
3. **声明式主题页面**：策展专员生成主题页面和区块，数据通过项目文件 alias 绑定；宿主用可信 Vue 组件渲染。优点是安全边界清晰、数据可随文件更新；缺点是现有区块类型有限，复杂图表和动画需要新增区块契约和 ABI。
4. **命名 JSON + 受信任渲染器**：策展专员写 `project_documents`，由平台受信任组件或新主题区块读取并渲染。优点是结构化、可校验、可版本化；缺点是需要新增读取契约、授权和前端组件，视觉自由度受组件库限制。
5. **运行时服务端接口**：页面直接请求项目数据接口。灵活性高，但网络、鉴权、数据最小化和防外泄成本最高，不作为首版方向。

首轮模拟建议采用“脚本 + 生成时快照”作为视觉主路径，同时保留声明式主题页面承载摘要、目标和重要信息。只读 bridge 作为第二轮能力，在脚本沙箱、撤权和字段白名单验证通过后再开放；运行时服务端接口不进入首版。

### 2.5 定时任务与运行证据

现有定时任务已经支持 `project_id`、`agent_slug`、cron、时区、启用/停用、立即运行和“上一次未结束则跳过”。新需求需要补充：

- 同一项目、同一呈现角色的重复运行不能产生重复主题来源或重复 Dashboard 版本。
- 定时生成与人工编辑冲突时，必须按 revision/version 拒绝并保留现场。
- 每次运行记录输入范围、数据时间、产物、校验结果、发布/应用状态和失败原因。
- 生成失败不能留下“看起来已应用”的半成品。

### 2.6 权限与操作边界

- 运行身份使用调用用户，不使用拥有更大权限的服务账号。
- 项目范围在 Run→Conversation→Project 链路重新校验，工具不得只信任提示词或会话参数。
- 主题发布、主题应用、Dashboard 覆盖等写操作在 service/repository 层最终授权。
- 策展专员默认只能生成草稿；发布/应用由人确认，或在未来通过单独授权的自动化策略执行。
- 工具面尽量收窄到策展专员所需能力；是否需要独立后端固定工具面，见待决问题。

### 2.7 项目内导航

Dashboard 的最近动态、蓝图等条目要能点进准确项目页面。导航通过宿主的受控导航协议完成，Dashboard 不直接改地址，也不获得同源或网络权限。

- 条目携带类型化目标：`topic`、`decision`、`comment`、`task`、`blueprint`；至少包含当前项目和对象 id，不携带任意 URL。
- 宿主校验当前项目、用户权限和对象存在性，再用 Vue Router 跳转；对象已删除、撤权、改名或不属于当前项目时显示安全提示。
- 全屏状态下跳转要明确退出全屏或保留全屏；返回 Dashboard 时恢复原状态。
- 数据快照中的 id 可能过期，宿主必须重新校验，不能只信快照。

当前数据边界：

- `get_project_recent_activity` 当前返回 topic、comment、decision，不包含任务；任务要进入最近动态需要新增数据源或扩展接口。
- 议题可用 `topic_id` 精准进入；决定通常用 `topic_id` + `decision_id`；没有关联议题的独立决定还需要定义落点。
- 回复动态当前指向顶层讨论（`comment_id` 取 `parent_comment_id` 或顶层 id），不能保证定位到具体回复；要精确到回复需扩展接口和前端定位。
- 任务已有 `ProjectWorkTaskView` + `task_id` 路由，可作为任务动态的落点。
- 蓝图用 `ProjectBlueprints` + `blueprint` 名称；蓝图改名或删除后由宿主提示，不使用旧快照硬跳。

首轮建议先覆盖议题、决定、任务、蓝图四类目标；回复是否精确到条作为待确认项。

## 3. 当前事实与约束

### 3.1 智能体执行后端

执行后端由 `backend/package/yuxi/agents/buildin/__init__.py` 的 `BUILTIN_BACKENDS` 硬编码注册；`get_agent_backend()` 按 ID 查表实例化；Agent 表保存 `backend_id`，不保存执行图。系统没有后端自动扫描机制。

预置角色由 `backend/package/yuxi/agents/presets/__init__.py` 递归扫描 `presets/**/*.py`，读取 `PRESET` 并拒绝重复 slug；启动时落成 DB Agent。预设只定义角色、提示词和配置，不能替代执行后端。

### 3.2 项目数字员工与定时任务

项目数字员工已经支持项目私有 Agent 创建、既有 Agent 绑定和项目级配置覆盖；运行时会校验智能体是否属于当前项目。定时任务由 `backend/package/yuxi/services/scheduled_agent_service.py` 管理，任务绑定项目、智能体和提示词。

### 3.3 主题

主题服务由 `backend/package/yuxi/services/project_theme_service.py` 拥有候选、发布、绑定和项目文件校验；主题契约由 `backend/package/yuxi/services/project_theme_contract.py` 拥有。当前支持声明式页面和区块、项目文件 alias、JSON/PNG 资源和项目绑定。

现有 Agent 工具面没有主题工具。主题能力只能通过 HTTP/UI 使用，不能由策展专员直接维护。

### 3.4 Dashboard

Dashboard 读写由 `backend/package/yuxi/services/project_dashboard_service.py` 拥有；页面入口固定为项目 Workdir 的 `dashboard/index.html`。当前策略只允许静态 HTML/CSS，拒绝脚本、`meta` 和非页内锚点链接；前端用 `createDashboardSrcdoc` 加入 CSP 后放入 sandbox iframe。当前 iframe 没有 `allow-scripts` 和全屏授权，CSP 的 `default-src 'none'` 也会阻断脚本。

`dashboard_read` 和 `dashboard_write` 是当前 v0 工具，只理解静态页面和 revision，不理解主题页面、声明式区块、项目文件 alias、Dashboard 草稿生命周期、脚本沙箱或全屏。它们需要在新规划中重新定义。

### 3.5 当前能力缺口

- 没有主题工具，无法读取、生成、校验或预览主题草稿。
- Dashboard 工具只支持静态 HTML 直写，没有草稿/预览/应用边界。
- Dashboard 当前不支持脚本、动画、动态数据或全屏；要满足“活的”视觉目标，需要调整 iframe 授权、CSP、前端展示和预览策略。
- Dashboard 业务大屏只在 `baseline` 呈现显示，自定义 `focus`/`research` 主题无法嵌入。
- 主题图表能力有限：JSON 区块展示数字和文本，PNG 区块展示图片，没有受信任图表或动画区块。
- 项目命名 JSON 文档还没有被 Dashboard 或主题契约消费。
- 还没有面向“策展专员”的预设角色、技能和定时任务模板。
- 现有项目工具还包括 `governance_board_read`、`governance_report_write`、`governance_topic_open` 等议题/汇报能力，尚未按策展专员职责做归属和必要性审查。

## 4. 推荐基线

### 4.1 执行壳

首版使用 `ChatbotAgent` 加一个策展专员预设角色，不新写执行后端。提示词收窄、工具子集和业务方法论通过预设、技能和项目覆盖实现。

只有在以下条件出现时，再考虑在 `backend/package/yuxi/agents/buildin/<name>/` 建立薄后端：

- 工具面必须固定，不能由用户配置扩展。
- 需要固定阶段和校验门，而不是自由工具调用。
- 需要明显不同的中间件、模型默认值或审批行为。
- 该角色成为长期产品，需要独立版本、测试和多变体。

### 4.2 能力分工

- **skill**：记录“读项目事实→形成调整方案→生成草稿→校验→预览→等待人工确认”的方法和边界。技能只影响提示词和方法，不授予工具或数据权限。
- **tool**：提供主题读取、主题草稿写入、主题预检/预览、Dashboard 草稿读写、项目事实读取等能力。
- **service/repository**：拥有授权、revision/version、文件边界、发布和绑定语义；工具调用在这里最终通过或拒绝。

### 4.3 首版产物

- 一个策展专员预设角色，绑定到模拟项目。
- 一个技能，描述策展专员工作流和人工确认点。
- 一组最小工具，先覆盖读取项目事实、读取当前呈现、生成主题草稿、生成 Dashboard 草稿、预检和预览。
- 一个定时任务模板，用于周期性汇总和重生成草稿。
- 一套模拟项目数据和验收证据。

### 4.4 工具全面审视

先做一次只读工具清单，再按首轮纵向切片实现确实需要的变更；不为了审查本身修改全部工具。

从 Git 历史看，`dashboard_read`/`dashboard_write` 是项目静态 Dashboard v0 的读写适配（提交 `5cbc3805`）；`governance_*` 是项目督查/治理场景的只读聚合、汇报和议题入口（提交 `481334d8`）。它们不是主题工具，也不自动属于策展专员。

当前相关工具与初步判断：

| 工具 | 当前能力 | 与策展专员的关系 | 初步判断 |
| --- | --- | --- | --- |
| `dashboard_read` | 读取静态页面状态、revision、hash 和 HTML | 需要，但要扩展到主题、候选、版本、项目文件、脚本策略和全屏状态 | 重命名或扩展 |
| `dashboard_write` | 用完整 HTML 直写页面 | 需要改成“草稿/预览/应用”边界，并明确脚本与数据策略 | 拆分或替换 |
| `governance_board_read` | 读取项目督查板、议题、工作与汇报 | 可作为项目事实输入 | 保留，按最小权限挂载 |
| `governance_report_write` | 写入项目汇报 | 汇报产出可能属于策展总结，也可能属于秘书角色 | 待定，避免职责混用 |
| `governance_topic_open` | 打开 proposed 项目议题 | 属于治理动作，不属于呈现动作 | 默认不挂载 |
| `delegation_*` | 外部执行器委派 | 非策展必需 | 不挂载 |
| `coding_*` | 编码会话管理 | 非策展必需 | 不挂载 |
| 文件系统工具 | 项目 Workdir 读写 | 生成 PNG/JSON/HTML 资源需要 | 保留，限制在项目 Workdir |

审查要求：

- 每个工具必须有当前 consumer、授权路径、幂等/冲突语义、失败面和可观察结果。
- 工具只做 service 适配层，授权、revision/version 和文件边界仍在 service/repository。
- 工具清单作为前置只读任务；脚本 Dashboard、主题工具、汇报工具等实际改造按纵向切片按需进行。
- 发布/应用工具默认不提供给策展专员；需要时单独授权并审计。
- 现有 `governance_*` 工具由项目数字员工/治理场景引入，不能因为都带“项目”就默认归策展专员使用。

| 问题 | 候选 | 当前建议 |
| --- | --- | --- |

| 脚本安全 | 无脚本；脚本沙箱 + 无网络；脚本 + 只读 bridge；运行时接口 | 脚本沙箱 + 无网络；bridge 单独评审 |

| 项目内导航 | Dashboard 直接改地址；宿主受控导航协议；纯展示 | 宿主受控协议，类型化目标，重新授权 |

| 首轮模拟范围 | 单项目单主题；多项目；完整生态 | 单项目纵向切片，验证后再扩展 |

## 6. 候选验收主张

以下主张只用于讨论，确认后再进入 DEV 和 LOG。

| 验收主张 | 失败面 | 语义 Owner | 直接证据 | 负向案例 |
| --- | --- | --- | --- | --- |
| 数字员工只能在绑定项目运行 | 跨项目读取或写入 | 项目数字员工 service、工具授权 | 真实 HTTP 和 PG 结果 | 其他项目 id 返回 403/404 |
| 主题草稿由项目事实生成并可预览 | 生成内容与项目数据不符 | 主题 service、主题契约 | 草稿包、预检结果、预览 DOM | 缺失 alias、非法资源、旧 revision |
| 主题发布/应用保持人工确认 | 策展专员自动发布或应用 | 主题 publisher、项目绑定 service | 前后绑定和版本记录 | 未确认调用发布/应用被拒绝 |
| Dashboard 脚本在沙箱内运行 | 同源访问、外部网络、读取凭证、页面跳转 | Dashboard service、iframe sandbox/CSP | CSP、iframe 属性、网络请求记录、DOM | 外链、fetch/WebSocket、top navigation、表单被拒绝 |
| Dashboard 视觉、全屏与屏幕策略可用 | 默认缺少窄屏变体、窄屏/大屏切换错误或缺少提示、减少动效不可用 | 前端宿主、Dashboard service、部署环境 | 默认产物检查（宽+窄两套）、断点切换、状态保持、缺失提示、真实浏览器大屏截图/DOM、页面内全屏状态、Fullscreen API 状态、kiosk 目标环境验证、`prefers-reduced-motion`、人工视觉审阅 | 默认缺少窄屏变体、切换丢状态、窄屏强行压缩大屏布局、动画无法停止、kiosk 无法恢复 |
| Dashboard 数据来源可追溯 | 跨项目数据、伪造指标、数据过期 | Dashboard service、项目数据服务 | 数据来源、页面内联数据、时间戳 | 未授权数据、缺失数据被静默省略 |
| 最近动态/蓝图可精准导航 | 跳错对象、越权、旧 ID 硬跳 | 前端路由、项目权限、对象服务 | 议题/决定/任务/蓝图真实点击、错误提示、返回状态 | 已删除/撤权/改名对象不跳转 |
| 定时运行不重复、不静默覆盖 | 重复来源、覆盖人工修改 | 定时任务 service、revision 校验 | Run 记录、候选/页面版本 | 并发运行、旧 revision 被拒绝 |
| 数据协议可校验、可追溯 | 数据缺失或类型不符 | 主题契约、项目文件校验 | manifest、alias 映射、文件 hash | 缺文件、错误 MIME、超限 |
| 工具清单与归属清晰 | 工具未分类、越权挂载、职责混用 | 工具注册表、service | 工具清单、挂载配置、授权测试 | 未分类工具、治理动作误挂策展专员 |

## 7. 下一步

1. 先确认第 5 节的产品判断，尤其是策展专员权限、Dashboard 视觉/脚本/全屏和数据新鲜度。
2. 做一次只读工具清单：Dashboard、主题、议题/汇报及其他项目工具，逐项标记保留、收窄、替换、废弃或暂不挂载；不在这一步改代码。
3. 做脚本 Dashboard 的安全与视觉小试：沙箱脚本、无网络 CSP、页面内全屏、浏览器全屏、kiosk 部署路径、默认同时生成宽窄两套、宽窄切换、`prefers-reduced-motion`、内嵌数据快照和性能预算。
4. 根据确认结果补 DEV 实施约束和 LOG 状态，不先写代码。
5. 用单项目纵向切片做隔离模拟：一份项目数据、一个主题草稿、一个 Dashboard 草稿、一次最近动态/蓝图导航、一次定时运行。
6. 模拟通过后，再决定是否扩展多项目、只读 bridge、自动发布策略或独立后端。
