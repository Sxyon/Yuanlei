# SYS-DB-001｜Dashboard 系统需求与架构设计

版本：1.1。职责：Dashboard 专项的需求、系统设计与产品验收标准。开发拆分见 [DEV-DB-001](DEV-DB-001-Dashboard开发任务与实施约束.md)，实际进度见 [LOG-DB-001](LOG-DB-001-Dashboard进度基线与执行记录.md)。本文描述目标设计，运行能力以源码与 LOG 证据为准。

## 1. 产品定位和范围

元垒是个人经营与工作平台。项目是平面的主要业务空间，分类与标签区分领域，负责人保持弱关联。第一阶段由个人维护，不增设公司组织树或团队审批资格。

Dashboard 专项包含两组相互关联的能力：日常信息架构与办理体验，以及项目专属可生成业务大屏。前者让人顺畅阅读蓝图、研讨议题、查看决定、安排工作、核对交付；后者通过可复用素材和模板展示项目业务事实、分析与导航。平台自身的全局仪表盘、知识域 Dashboard 与项目 Dashboard 具有不同范围，现有权限各自执行。

### 核心使用结果

- 进入项目即能看懂需要做什么，快速进入准确对象；大量正文、历史、配置不会抢占当前重点。
- 治理主流程能连续完成，正式工作也能独立创建，不要求每件事都先走议题与决定。
- 一个项目维护多个大屏，不同项目从同一模板派生后独立绑定和演进。
- 项目 Agent 能发现生成规则、组合合法页面、读取实际数据、保存/验证/预览，并在明确授权范围内维护生效页。
- 缺数、取数失败、生成错误、失权或升级失败均能解释，管理概览持续可达。

## 2. 第一阶段范围与延后能力

| 范围 | 第一阶段必须具备 | 具名延后能力 |
| --- | --- | --- |
| 导航与日常页面 | 平台/项目嵌入、治理、工作、收件箱、项目 Agent、准确结果、资料返回 | 新的全局业务门户、领域树 |
| 页面创作 | 受控结构组合，可信 Vue 素材，布局/参数/输入/动作可组合 | 任意生成 Vue/JS 隔离包；由真实表达缺口触发 |
| 库 | 内置、个人共享、项目专属模板；素材说明；固定版本派生 | 公开市场、组织共享审批 |
| 数据 | 当前正式工作/结果只读服务；项目有界 JSON 数据集和分析材料 | 通用 ETL、任意 SQL、外部数据连接器 |
| 维护 | 草稿、验证、预览、人工启用/回退；固定模板有限自动维护 | 自由结构组合自动启用、自动扩权 |
| 协作展示 | 使用已有工作、执行、结果事实；未接状态明确标示 | 暂停中的 Andon 逐级处理与正式授权增量 |
| 权限 | 本人及当前项目可见性、根 Run 归属、有限维护授权 | 组织 RBAC、授权转授、企业治理 |

延期项不作为本专项第一阶段完成条件，也不被记为已交付。原系统总规划中的协作目标仍保留。

## 3. 页面信息架构与导航

### 三层职责

关系与生命周期见<a href="图解/02-dashboard/dashboard-architecture.html" target="_blank" rel="noopener">DB-G02目标架构图</a>。图表示待实施设计，当前状态见LOG。

平台导航采用窄栏和显式展开/固定，项目导航可按需折叠；个人偏好由宿主保存。业务内容不能另建一套平台导航或改变全局聊天归属。全屏由宿主临时控制，保留退出、Esc 与管理概览入口，结束恢复原个人偏好。悬浮展开和拖动宽度是可选后继呈现改进，须证明操作收益后引入。

### 页面职责和信息层级

| 页面 | 第一眼要看到 | 主要操作 | 次级信息 |
| --- | --- | --- | --- |
| 管理概览 | 待核对交付、受阻/失败、需本人动作、工作进度 | 进入准确结果/工作/治理；切业务视图 | 蓝图摘要、有效决定、关系图、统计 |
| 治理工作台 | 蓝图阅读；议题列表与当前详情；当前决定和关联工作 | 显式编辑、讨论、原治理动作、创建/关联正式工作 | 讨论回复、修订、历史、归档维护、汇报 |
| 工作列表 | 工作编号/标题、业务状态、需本人动作、执行和结果摘要 | 新建人工工作、筛选、准确对象进入 | 看板/列表/甘特、日期、来源 |
| 工作详情 | 准确结果、提交时条件、文件、意见、办理 | 核对文件、接受/拒绝、管理工作 | 旧依据、执行尝试、引用、反馈、补充 |
| 收件箱 | 项目+工作身份、本人当前义务、准确交付入口 | 打开对象、切筛选；通知已读/归档 | 普通通知、归档通知、历史 |
| 项目 Agent | 待接受、运行、异常、交付，与工作验收分开 | 接受/撤回、打开尝试或结果 | 配置覆盖、模型、轨迹 |
| 业务大屏 | 实例身份、修订、时间、来源，再看主图和明细 | 筛选、刷新、全屏、进入准确对象 | 明细、分析依据、诊断 |
| 项目大屏管理 | 当前首页、所有实例、各自生效/草稿/来源/缺数 | 新建、派生、绑定、预览、启用、选首页、回退、归档 | 版本差异、历史发布、授权策略 |
| 模板/素材库 | 可用资源、输入要求、用途和版本 | 预览、派生、读取规则、提取模板 | 依赖、升级差异、归档资源 |

重要操作保持可发现，历史和低频维护按需展开。窄屏采用列表→详情→返回，保留选中与筛选。深浅主题、键盘焦点、空/错/加载、长标题与长正文都有明确状态。

## 4. 治理与执行的概念边界

蓝图说明方向和可观察目标；议题融合问题、候选方案、讨论和决定入口；决定记录被接受的选择；正式工作承担执行和验收。议题准入、研讨进度、结果确认各自表达自身事实。已批准决定的正文不可被界面重排直接覆盖，勘误、补充、替代和撤销沿用原机制。

工作业务状态与执行尝试/AgentRun 状态分开；Run 结束不表示工作已验收。当前一次性工作继续使用既有工作实例，周期工作定义、自动化和监控的统一属于后续系统演进，本专项只展示其已有事实。

界面切页、刷新和冲突保留本人准确对象的草稿及原依据。保存时校验读取时的对象版本；过期不能自动换为最新版本重放。蓝图属于文件事实，保存依据使用内容指纹与文件身份；共享目录产生共享文件效果，页面明确告知。

## 5. 自定义大屏的对象模型

| 对象 | 内容与身份 | 关键关系 |
| --- | --- | --- |
| 素材 | 产品可信组件、精确版本、输入类型、显示参数、动作 | 由产品注册；定义引用 `id@version` |
| 模板 | 可复用结构、输入槽、必要依赖、不可变版本 | 内置/个人共享/项目专属；不含实际业务行或凭据 |
| 实例 | 项目所属的大屏、名称、来源、生效/草稿指针 | 一项目多实例；相同 Workdir 仍独立 |
| 修订 | 不可变定义、绑定、依赖、规则版本、来源 | 修改追加修订；模板版本精确锁定 |
| 项目选择 | 当前业务首页实例与配置版本 | 同项目最多一个业务首页；管理概览独立 |
| 数据集修订 | 有界数据、单位、时间、来源、采纳事实 | 页面可固定修订或读授权 current；更新独立于页面 |
| 验证/启用记录 | 精确内容指纹、检查结论、实际操作者、授权、时间 | 验证绑定修订；启用原子改变指针并保留历史 |

定义和关系保存在 PostgreSQL `yuanlei` 域；文件字节由现有 Workdir/对象服务管理。项目目录文件可作为授权来源或导出副本，不能让共享目录路径代替项目/实例身份。旧静态 HTML 维持独立兼容入口、原版本和空 sandbox，不自动迁移成动态定义。

模板升级生成实例新草稿，已有生效页和其他项目不变。实例预览、实例启用和设为项目首页是三个不同动作；启用可根据明确参数同时设首页，必须同事务检查归属和版本。归档首页先选择替代或回管理；引用版本保持历史读取与回退，首阶段不永久清理受保护历史。

## 6. 生成规则与可信运行时

第一阶段采用受控结构定义，由产品可信 Vue Runtime 渲染。Agent 可增删和重排区域、组合 grid/stack、映射字段、选择可信图表/表格/分组素材、配置筛选与对象导航。规则禁止任意 JS、SQL、URL、自由表达式和动态依赖安装。

规则发现返回版本化能力：完整 Schema、素材输入和动作、可见模板、数据契约、错误位置、预算和启用方式。详细规则按需读取，不把所有规范硬塞进每次提示词。未知版本、组件、字段、单位或动作明确拒绝；能力版本升级不隐式更新旧定义。

必要素材至少包括指标、趋势图、数据表、分析说明、结果列表、按工作状态分组的观察。模板至少覆盖交付观察与经营观察。经营观察中的分析说明默认可选，数据缺失须能展示来源状态；模板定义可以将某槽明确设为必需，但不能让所有经营图都因缺少 AI 分析而无法启用。

预算在能力版本中发布。初始建议为定义 128KiB、40 个节点、8 个输入槽、布局深度 4、每槽分页 200 行；这些是实现时负控校准的起点。限制改变应版本化，不能根据某次生成结果临时放宽。

## 7. 数据、分析和资产

### 三类内容

1. 正式事实：项目、治理、工作、结果、执行等既有服务读取，定义不复制业务状态。
2. 业务数据：经过采纳的有界项目 JSON 数据集，至少支持月度与分类/区域观察；包含类型、单位、覆盖范围、时间、来源和修订。
3. 分析：Agent/人工观点，显示作者、时间和依据；候选数据明确标注，不能冒充正式业务事实。

每个数据槽返回自身状态、来源版本、as_of、完整性、分页和错误。区分空数据、未绑定、候选、过期、读取失败、无权；未知数值不填零。必要源在启用前重验不可读取时阻止新启用，已生效页保留其指针并显示局部错误和管理退路。

数据候选经过字段/大小/单位/来源验证，再由人或单独授权采纳；页面维护授权不包含数据采纳。源文件读取使用授权对象引用和内容指纹，不能扫描任意目录。资产经现有授权文件/对象边界获取，不接受宿主绝对路径、任意外链或浏览器秘密。

页面回退只恢复定义与绑定，不撤销业务数据更新。历史页面若绑定 current，应显示当前数据时间，不能将历史页面修订伪装成历史数据快照。

## 8. 宿主交互和返回

大屏只发观察与对象导航请求，业务写动作进入可信办理页。宿主与后端校验项目、实例、准确目标及关联关系，再解析为注册路由。素材动作的ID来自当前授权数据行；页面参数均属不可信输入，宿主与后端重新核对象关系和权限，不能因ID来自页面就信任。禁止任意URL。

对象导航支持已有工作、准确结果、执行、议题和决定。协作问题/尝试仅在其 Owner 提供真实接口与权限时开放；`collaboration.read/1` 保留兼容，未接字段显示 unavailable/partial。

返回上下文包含原项目、实例/修订、筛选、时间、选中对象、位置、焦点及全屏状态。宿主登记 uid 绑定的短期不透明令牌，业务页只携带令牌；服务器重新校验当前权限。令牌仅保存导航状态，不能授予永久数据访问。

返回同修订恢复原观察；已升级时提供“原观察版本 / 当前版本”，明确历史标记。过期、归档、失权或结构不兼容时解释原因并回管理；账户切换/登出清除浏览器状态。真实管理页返回也须保留选中议题、准确决定修订及工作列表筛选。

## 9. Agent 维护、授权和生命周期

关系与生命周期见<a href="图解/02-dashboard/dashboard-architecture.html" target="_blank" rel="noopener">DB-G02目标架构图</a>。图表示待实施设计，当前状态见LOG。

工具能力按用途分为目录/规则发现、实例读取、草稿保存、验证预览、启用回退；HTTP 与工具共用同一 service。后端从真实 Run→Conversation→Project、uid 和 worker lease 解析范围，模型传入 project_id 不能决定权限。子 Agent 只提交候选，由根核对接收，不直接取得项目发布权限。

维护方式分为：默认人工启用；显式授权固定模板/素材版本、允许参数/源/预算/次数/期限内自动维护；自由结构组合自动启用保留为后继能力。授权内合法修改无需逐次确认，超范围保留草稿并解释。启用不授予正式决定批准或外部执行权限。

验证报告绑定修订、定义/绑定指纹、规则依赖、当前权限及有效期。启用同事务核对 head/active/config/policy 和授权消费，冲突保持稳定页。旧报告不能用于新修订。启用、设首页和回退各自具有稳定operation_id，重复相同意图返回原操作结果，异输入拒绝。固定数据修订验证准确版本；current数据槽重验绑定/契约/可见性，不锁住持续变化的全部数据值。回退重新验证同实例曾启用稳定修订，追加启用事件，不移动草稿 head，也不擦除历史。

## 10. 独立验收场景与收尾标准

| 场景 | 必须观察的产品结果 |
| --- | --- |
| 日常治理 | 阅读/编辑蓝图→讨论议题→批准决定→建议新建/关联正式工作；旧操作和历史保留，过期保存不覆盖 |
| 人工工作 | 无议题、无 Agent 创建→提交交付→准确核对文件和条件→办理→返回 |
| Agent 工作 | 接受/运行/异常→准确尝试/结果→办理；运行和业务完成清晰分开 |
| 跨项目 | 同名工作、共享目录、同模板实例分别读取准确归属，切账户不留旧数据 |
| 项目大屏 | 至少两个项目、两个模板、多实例、单首页；固定版本派生、升级失败稳定页不变 |
| 真实动态观察 | 实际源刷新→显示时间/单位/缺数→准确结果办理→回原实例/修订/筛选/位置 |
| Agent 生成 | 实际项目根 Agent 读规则→生成合法定义→修错→保存/验证/人工启用→回读；候选与事实分开 |
| 有限自主维护 | 精确政策内维护自动生效；撤权/过期/越界/并发不改稳定页；子候选只能经根接收 |
| 故障和回退 | 非法定义、数据异常、渲染错误、失权、归档和旧令牌有明确退路；回退保留草稿与历史 |
| 可用性 | 真实长正文/密集记录、390 窄屏、主题、键盘和用户连续使用，观察反馈被处理 |

产品链路、相关负向测试及真实页面/数据回读均满足后，Dashboard 专项可独立收尾。未实现 Andon 在界面明确标示，其联合验收留待专项重启，不伪造事实，也不纳入此处完成声明。
