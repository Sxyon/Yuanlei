## 1. 产品变化与实施边界

蓝图、议题/决定、建议准入、汇报使用原工作台路由的稳定栏目。栏目切换保留已挂载输入；旧 query 与 hash 打开对应栏目和准确对象。蓝图默认阅读，编辑为显式动作，历史按需展开，现有文件管理动作继续使用原接口。

议题支持标题/正文查找、准入筛选与归档显示。阅读顺序是议题问题、当前批准决定、关联正式工作及建议，再进入讨论、历史与维护。决定保留准确修订及复核提示；从当前决定创建正式工作时带入原关联，人工建议仍可独立创建。

建议准入保留新建工作和关联已有工作两种方式，编号配置、重复准入、旧依据与跨项目限制由原服务守卫执行。全部原治理业务操作及 URL 保持。此包无新增 schema、治理状态、后端业务语义或执行权限；动态 Dashboard、模板和 Agent 工具属于 D3—D5 的后续包。

草稿按已认证用户、项目和对象隔离，保留原修订依据；成功清理对应提交，失败和冲突保留。登出、账户切换、确认失权清除。对象 404 先由项目读取接口确认项目可见性，对象消失而项目仍可见时保留旧稿供复制。选中另一议题不能使旧编辑器写入新对象。建议准入的人工复核勾选不随草稿恢复，避免把旧核对冒充当前核对。

## 3. Owner、草稿约束与协作衔接

页面组合由 `web/src/views/ProjectInspectionBoardView.vue`拥有，历史、讨论、结果确认及建议准入复用其 project 子组件。草稿实现由 `web/src/utils/governanceDrafts.js`与 `web/src/stores/user.js`拥有；浏览器会话存储不可用时使用进程内缓存，关闭页面后的持久性降低，不伪装为后端持久。草稿只恢复输入及原版本依据，权限、状态与是否可准入均重新读取服务。

既有治理、工作准入与蓝图 API 继续拥有状态及授权；本包不增加服务守卫。确认和讨论处置保留原预期版本，冲突后明确提示重新核对，显式清弃才采用当前依据。提交中的输入或引用变更不被迟到成功清空。蓝图写接口没有 CAS，当前产品仍存在并发覆盖风险；若需修复须提交独立后端增量。

共享协作投影以 [collaboration.read/1 Schema](https://github.com/Sxyon/Yuanlei/blob/3c5ee33c64f82fcb5214f29e7b7198730bdeed55/backend/package/yuxi/delegation/schemas/collaboration-read-v1.json)为设计字段 Owner，[联合样例](样例/collaboration-read-v1-joint.json)验证准确 question/revision/node/attempt/result 与处理者、等待执行者、恢复事实的区分。D1 保留现有治理动作，并未接入该 query 的运行时或新宿主写动作。真实协作投影与返回闭合由 D2、C5 和 D6 联验承担，不能凭样例宣称已实现。
