### 4.1 必须单独闭合的子 Agent 执行树缺陷

当前创建端 `subagent_run_service.py:256` 使用 child_thread_id 写 runtime_scope_id；worker `run_worker.py:189` 要求它等于创建者的原始 runtime_scope_id。`inherit_run_scope` 另写执行范围映射，但上述原始字段校验没有使用该映射，因此两个 Owner 对同一执行树范围的解释冲突。新增 E2E 正是在进入模型前读到 invalid_runtime_scope 并限定 xfail。

这不是模型截断修复新引入的问题；但它也不能作为普通“环境跳过”忽略。应单独领命修复实际创建/范围解析/校验边界，保留父子身份及跨项目授权约束，不能简单删除 worker 守卫。至少证明真实父→子 Run 请求到达模型、输出绑定正确、合法继承可运行而跨树/跨项目拒绝，并在修复后让现有截断 E2E 真正执行到目标断言。

它不阻塞独立 OpenClaw 一次文本协议探针，也不阻塞 UI 首包；但会阻塞对平台多层 Agent 执行与 Andon 链路的可信验收。模型修复可按已验证的核心能力认定，所有子 worker 场景仍未闭合。原全量 Skill 超时也需独立定位；当前不能写“整体工程测试全部通过”。
