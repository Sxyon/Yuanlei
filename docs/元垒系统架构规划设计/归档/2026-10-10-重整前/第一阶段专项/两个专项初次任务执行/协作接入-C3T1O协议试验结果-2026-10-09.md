## 3. 停止、清理与证据保留

一次 6 秒 agent.wait 返回 timeout 时运行仍在输出，该 timeout 只证明等待截止。下一次 agent.wait 取得准确终态；请求 timeout=60 的实际强制截止未被触发，取消次数为 0。准确取消、超时终止和恢复仍为 Not run。

清理前 sessions.list 仅有本卡 session，done、无 active Run，无 pending input。使用 expectedSessionId、expectedLifecycleRevision、expectedSessionUpdatedAt 的原生 sessions.delete，关闭 lifecycle hooks，deleted=true；再次列表 totalCount=0。原生 agents.delete(deleteFiles=true) 返回 failed=[]、removedBindings=0，数据库、Agent 子目录、sessions 和 workspace 使用 trash。原路径内容消失；仅余新建空根目录，精确 rmdir 后也不存在。最终配置无专属条目、保存/运行修订一致、条目外配置指纹等于基线。

平台删除保留了废纸篓内容，sessions.delete 还生成原生压缩删除归档；没有清空废纸篓或共享平台日志。因此结论是原生可见对象和活跃路径清理成功，无法宣称不可恢复擦除。原生配置发布的 sentinel、备份及共享审计元数据保留；不为清理本卡而删全局文件。

本地保留 0600 去敏 RPC 记录、输入、原生终态、持久消息、独立 oracle、清理回读及哈希清单；附件位置通过会话交付，不进入仓库。模型凭据、全量日常配置、用户资料及私有 transcript 均未作为报告或协议实现依据。保存文本证据是本地文件写入，没有证明远端文件产物交付。

## 4. Multica 独立结论

指定 sxyon 工作区的既有 Agent/runtime 绑定保持一致；只读 agents/runtimes 返回 200，目标 idle/online。device_info 为非 JSON 字符串，metadata 为包含 capabilities/version/cli_version/launched_by 的对象；运行投影及这些元数据未提供可核查 sandbox、isolation、permissions、resource_limits、execution_timeout、container_id 或 vm_id 边界；版本仍沿用现有实际读验的 codex-cli `0.155.0-alpha.16.4` / Multica CLI `0.6.0`。部署版本差异与源码能力继续由 [C0/C1](协作接入与Andon-C0C1事实与讨论-2026-10-08.md) 和 [C2](协作接入与Andon-C2端到端方案比较-2026-10-08.md) 解释。

主机/daemon/device 标识和 online 不能证明目标容器、账户、工具/MCP 任务凭据权限或绝对截止。本机默认 daemon stopped 也不能证明在线 runtime 停止。缺少这些实例 Owner 的部署证据，T1-M 保持暂停派发；只阻塞 Multica。已完成的 [collect 止损](../../../../../develop-guides/yuanlei/decisions/implemented/2026-10-08-multica-collect-stoploss.md) 按 6a672f4 结项，可信交付退出条件仍有效。

## 5. 推荐的最小实施任务

暂定推荐 Gateway 原生文本 Adapter，复用现有 DelegatedExecutor 注册、DelegationService 和 Result Owner；[聚焦 proposed Decision](../../../../../develop-guides/yuanlei/decisions/proposed/2026-10-09-openclaw-text-delegation.md) 记录取舍。本轮没有实现或批准产品接口。受控 CLI 保留运维替代研究，不引入新 fallback 或通用连接中心。

| 增量 / Owner | 可领命范围 | 必须验收 / 未证明部分 |
| --- | --- | --- |
| 具体 Gateway Adapter / delegation | 使用显式既有目标配置；每 operation 创建新 session，持久冻结 agentId、sessionKey、sessionId、生命周期修订和准确 runId；派发前落库，接受不明时仅对原标记查证 | 拒绝同名旧 session、错 Agent/session/run、非终态、空/静默/截断/错误输出；禁止重发造成新调用。接受响应丢失与进程重启待隔离验证，不承诺 exactly-once |
| 当次结果 / collect | 等准确终态，回读持久 assistant，验证 runId、sessionId、可见处置和正式文本；保留 messageId、内容指纹、来源、原始 usage；本地 Workdir 文本与远端 artifact 分开 | terminalReply 可作对照；仅有它、delta 或 description 不满足持久来源。重复/并发回收及 wrong-run 负控用真实 PG/Workdir；不把模型自述当来源 |
| Result Owner / 本地验收 | 成功映射 completed，导入既有待验收结果，保留 source 唯一幂等；text 为正式输出，supplement 独立保存并按需读 | 现有 summary 同时用于结果摘要，不能直接拿它承载“可选补充”。准确来源/补充持久位置需要最小 owning 契约与 schema 评估；新增结构进 yuanlei 域。执行完成、回收和业务接受分开 |
| 配置 / 运行权限 | 长期 Agent 由远端管理，本地只引用连接与目标、冻结当次有效模型/策略；准备探针不是产品自动创建配置的依据 | 管理 token 留后端受控边界，不能入模型或前端；本轮 scope 组合不证明运行仅 read/write 已达到平台最小授权，需逐方法策略核对 |

现有 DelegationHandle 没有 agentId/sessionKey/生命周期修订专用位置，_handle 也不恢复请求 metadata；不能只塞临时内存后宣称持久绑定。实现任务先在现有 request_json/handle/result_json Owner 内确认最小持久契约，必要时仅扩充实际消费者需要的字段，不建立万能 AI 接口。新增公开行为需同步 Feature/Decision，并在产品直接入口与重启后回读验证。

先完成准确文本派发—观察—可信回收—待验收闭环，再扩展过程/求助；第二平台的真实试验只验证已形成的最小映射和结果抽象。首次产品入口隔离试验需要新的具体写入授权，本卡对象已清理且本次一次额度已用完，不能重复运行原卡。

后续目标保留：逐级问题/答复按问题与等待尝试匹配、迟到答案不得唤醒新尝试；答案采用、解除阻塞、执行恢复和任务完成分别留事实。原运行续接未验时只承诺明确新尝试。限定授权先证明具体草案，随后支持范围/期限内新草案及撤销、过期、旧决策版本与副作用前拒绝；组织审批链仍留第三阶段。本轮没有建设完整 Andon 或正式授权批准系统。
