## 1. 本轮范围与结论

目标是核对元垒语义 Owner、两个实际样本的版本与只读能力，并用场景解释身份、交付、过程补充、逐级求助和限定授权。验收依据是源码、版本命令和真实只读协议响应；平台文档只作为候选能力证据。本轮不改产品代码、不安装升级、不发任务、不调整配置、不批准正式业务决策，也不选择框架或冻结接口。

元垒已有持久委派、子运行、同 Run 输出、批准历史和结果验收基础。跨平台 Andon 的稳定问题、直接处理者、逐级返回、送达与恢复确认，以及智能体限定批准授权尚需研究。C0 已完成初步摸排，用户指定的 Multica 工作区已只读定位，服务完整构建版本与当次输出准确性仍待确认；C1 是可讨论场景，真实闭环均未试验。

元垒源码 HEAD 为 `5ac4a3c0c27dd5df76c6283d76642fc78783e33a`；评估基线 `ef65969` 分别标识，本文重新核对关键 Owner，不沿用评估测试数字。工作树已有 Dashboard 专项文档修改，未改动该专项文件。

## 3. 元垒 Owner 与已有边界

| 语义 | 当前真实 Owner | 已实现与缺口 |

## 4. 两个样本的配置与协作能力

| 研究维度 | Multica | 本地 OpenClaw | 仍需证明 |
| --- | --- | --- | --- |
| 连接与配置 | URL/认证/workspace/project；Agent 配置与 runtime/daemon 绑定由平台拥有 | Gateway 认证/作用域、Agent、workspace、模型与工具策略由本地平台拥有 | 共同管理连接与可用范围，专属配置保留原 Owner；不得把凭据送进业务上下文 |
| 接入路径 | 现有 HTTP 适配可演进；平台工作项与 Run 分离 | Gateway 原生 RPC、受控 CLI 是两个待比较路径 | CLI agent 执行会发任务，未调用；Gateway 也需限制到所需 scope，当前管理 CLI 成功不证明最小权限成功 |
| 身份 | 本地 operation → issue → assignee Agent → task/Run → runtime | 本地 operation → Agent → sessionKey/sessionId → runId → runtime | 一个 issue/session 可多次运行；必须绑当次身份，不能取 latest 或首个 activeRunId |
| 交付 | 参考源码有 issue task-runs 与 task messages 读入口 | 本机随包文档有会话历史、Run 等待与子任务完成返回 | 都未读取真实交付；文件需验证可访问边界、版本/字节和来源；URL 只是引用 |
| 过程补充 | 运行消息与执行轨迹可作候选来源 | history、事件、announce 可作候选来源 | 作者/运行/时间来源需保留，执行者自述测试不等于独立验证；未形成元垒补充契约 |
| 求助与续接 | 平台是否有准确运行等待/回复接口未验；issue 评论不自动等于恢复 | 随包文档有 sessions_send/yield、嵌套完成回报；实际工具策略与等待目标未验 | 完成回报不同于阻塞求助；回复接口接收不同于恢复确认；新尝试与原 Run 续接分别命名 |
| 故障恢复 | 元垒委派租约保护本地流程，远端执行恢复未验 | 随包文档描述部分持久输入与子任务重启恢复，也说明 active steering 队列不保证重启持久 | 逐路径核对入库、幂等、重启及晚到答案；不能给全平台统一“可恢复”标签 |

Multica 官方区分协调平台与 runtime 执行边界：[How Multica works](https://multica.ai/docs/how-multica-works)。评估参考的客户端具备 [task-runs/messages 与 Agent/runtime 入口](https://github.com/multica-ai/multica/blob/fbd3470eacc1a643f101d703875fb59a019facf7/packages/core/api/client.ts)；相邻检出也有这些入口。实际服务 Agent/runtime/task-runs 读取结构已验，messages、当次结果关联和交付准确性未验。

OpenClaw 研究以实际安装包 `2026.9.8` 的随包文档为版本参照，在线文档仅交叉参考：[会话协议](https://docs.openclaw.ai/gateway/protocol/rpc-session-control)、[会话工具](https://docs.openclaw.ai/concepts/session-tool)、[子任务](https://docs.openclaw.ai/tools/subagents)。当前 Gateway 列表实测返回精确活动 Run 字段；spawn/send/yield/恢复与子任务逐级 announce 均未发起。内部未暴露后代留在 OpenClaw 局部树，不扫描私有 transcript 充当稳定接口。

## 5. C1 场景与可观察验收

下列均为候选试验脚本，尚未运行；A 为项目智能体，B 为直接委派者，C 为受托执行者，H 为用户。字母只解释责任，不预先决定用本地嵌套子运行实现。

| 场景 | 具体问题与路径 | 后续必须回读的结果 |
| --- | --- | --- |
| 准确交付 | A 委派 B 整理供应商比较，B 在指定平台一次运行交付表格与来源 | 固定资料、operation、目标 Agent 与远端 Run 明确关联；输出与文件属于该次运行；唯一待验收，H 接受后才改变业务结果 |
| 可选补充 | B 同时报告数据缺口、检索范围与失败尝试 | 主交付可直接验收；补充按需展开，作者/运行/时间和原来源保留；上级总结引用原文而不覆盖 |
| 直接上级处理 | C 问“含税还是未税”；B 从已批准资料回答“统一含税” | Q 指向准确等待尝试和问题版本；B 有依据且在范围内；不升级给 A/H；验证送达、执行采用及恢复 |
| 两层上报 | C 发现数据缺一年；B 无权改变比较范围，附缺口交 A | 同一根 Q 保留 C→B→A 转交；A 若有批准依据可答，否则给 H；A→B 后 B 转为 C 的执行答复，范围不扩大 |
| 用户补充 | A 也无法确定缺失年份是否可接受，H 给出明确口径 | 用户答复沿 A→B→C 返回；提交、送达、收到、恢复、解决分别观察；无确认接口时保留未知 |
| 正式变更 | 批准范围必须覆盖三年，现需改为两年；H 已授 A 一次限定替代决策权 | A 核查授权及当前决策版本后新增替代决策；原批准历史保留；B/C 显式采用新依据，原 Context Pack 不重写 |
| 越界/撤权 | 相同问题要求改预算上限，授权仅允许资料口径；或批准前授权已撤销 | 正式批准被执行边界拒绝且继续上报；审计保留授权检查、实际动作与拒绝原因 |
| 相似并发问题 | 两个 C 同时问“能否少一年”，对应不同工作与尝试 | 不用自然语言匹配；回复各自 Q/版本/原等待对象；一个答案不解除另一等待 |
| 旧答案与崩溃 | Q 发出后任务取消/重新委派；或 B 收到答案后重启 | 旧答案不恢复新尝试；重试不重复批准或外部动作；晚到历史保留，当前处理者、待送达及拒绝原因可查 |

问题处理链与运行父子树分别记录关联：B 的 Run 可以结束，责任链仍需可继续；显式移交后才改变处理者。问题只暂停受影响分支，独立分支能否继续由 B 按已知依赖判断。UI 分别呈现“上级处理中”“待人答复”“已有答复未恢复”，Dashboard 不把所有子问题计成人的待办。

## 6. 可核查授权与审计：待比较的表达

用户已允许“明确授权后智能体批准部分正式变更”，具体授权实例尚未创建。C1 研究两种真实替代：针对单个 Q/委派、准确草案版本的一次授权；针对项目与决策类别、期限和资源上限的有限授权。前者易审阅但频繁授权，后者减少重复但撤销、范围判断及并发额度更复杂。也可在边界宽泛时由用户批准具体草案，由智能体执行后续动作。此处不定案，也不设计任意策略语言。

核查需回答：谁授权、授予哪个准确智能体/运行责任主体、允许何种动作与对象/版本、适用期限或尝试、资源上限、是否允许再授权、何时撤销。平台登录凭据、父节点关系与 prompt 自述不能提供这些业务事实。

批准时在治理副作用 Owner 校验最新授权、项目可见范围与 expected_revision；原批准的幂等重试需识别同一动作和依据。审计分别记录授权人、实际批准智能体及 Run、使用的授权修订、决策前后版本、原因与结果；不能只借用 user.uid 留成“用户本人批准”。用户撤销与批准并发的先后需要明确事务规则。委派链只能保持或收窄权限，再授权是否允许需显式事实。

治理批准完成之后仍需准确送达执行依据、记录采用和后继尝试；未送达、未采用与未恢复均保持可观察。后续负向试验至少包含缺授权、过期/撤销、项目或类别越界、额度越界、旧决策版本、重复批准及伪造授权来源。
