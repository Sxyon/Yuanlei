# SYS-CA-001｜协作接入与 Andon 系统设计

版本：1.0。职责：保留协作专项的需求与目标设计，供恢复时审阅。实施边界见 [DEV-CA-001](DEV-CA-001-协作接入与Andon冻结落地细节.md)，当前暂停与事实见 [LOG-CA-001](LOG-CA-001-协作接入与Andon暂停盘点与事实进展.md)。本文的目标机制不代表实现或能力声明。

## 1. 目标与范围

元垒可以把准确工作委派给不同 AI 平台/程序，通过可信来源取得正式交付和必要过程补充；执行者遇到缺资料、异常或授权边界时优先交直接上级处理，上级结合自身上下文答复或继续上报，返回逐级匹配原问题、等待尝试与答复。整个过程可持久回溯。

第一阶段个人使用，允许用户明确授权后由 Agent 批准部分正式决定变更。组织 RBAC、企业审批链和转授属于第三阶段。人、元垒内部 Agent 与外部协作者共享业务义务，实际执行能力和权限由各自提供者证明。

首批提供者为 OpenClaw 和 Multica，公共契约以两类真实消费者推动。接入新平台应实现具体 Adapter 和能力报告，不能复制整套业务状态；不为假想平台提前实现所有认证和 transports。

## 2. 核心对象及职责

| 对象 | 职责 |
| --- | --- |
| Provider | 实现协议/版本和能力，拥有真实外部动作语义 |
| Connection | 本人的连接、凭据引用、允许地址、项目许可、版本 |
| Target | 准确远端Agent/workspace/session范围及核验状态 |
| Operation | 一次业务委派意图的稳定根身份 |
| Attempt | 一次实际调用、冻结输入/目标/配置、远端绑定与交付来源 |
| Formal delivery | 本次满足约定的结果，进入原Result Owner待验收 |
| Supplement | 独立过程总结/必要说明，可按需读取，不能覆盖已接受正式正文 |
| Question/revision | 稳定问题与不可变修订，描述缺项/影响/已查依据/需要什么 |
| Handling node | 当前哪一级承担处理和返回义务，绑定自身输入/权限/Run |
| Answer/action | 明确适用范围的答复及持久送达动作，匹配等待尝试 |
| Grant | 用户赋予准确主体和范围的有限正式变更权 |

业务 attempt 与网络重试次数分开；新模型调用成为新 attempt，不能把旧成功材料挂到新调用。重复收件证据与逻辑问题身份分开，同key修订有CAS。

## 3. 接入分层及设计原则

业务用例使用统一委派入口，Adapter负责将业务任务转为平台公开动作和准确回读。配置形状由各提供者小型类型化结构承担，共享连接/目标/版本/密钥原则；不建立所有字段混装的万能JSON配置中心。

工厂负责按已注册 Provider创建实现；策略承担不同平台的交付/求助/续接能力差异；业务编排与平台运输分开可采用桥接式结构。只在已有消费者需要时使用这些模式，不为了模式名称另建层级。

长期远端配置默认由平台自身维护，元垒保存引用和核验结果；接入不默认接管日常配置、安装升级或网络。能力发布区分已真实验证、仅检查、未知、不支持，并绑定版本/目标/范围。

## 4. 下发给协作者的规则

版本化任务包包含：operation/attempt、准确目标、工作与验收条件修订、上下文快照和指纹、输入、直接处理者、预算/权限、交付格式、补充预算、Andon模式、问题和答复匹配字段、缺授权处理及停止条件。

协作者实际看见的正文须包含规则和相关 Schema，保存渲染后的输入指纹并与远端公开输入核对。只保存在元垒数据库不算下发。提示词说明不能取代工具/连接/执行器的权限边界。

版本不支持、未知必需字段、非法预算/来源明确失败。Adapter不得靠日志关键词推测 blocked、把非结构输出静默变成约定的结构结果。

## 5. 正式交付、补充、风险与来源

Formal delivery关联准确工作条件和context；运行完成只证明运行终态，结果仍由人或既有业务验收确认。来源核对实际 target/session/run/message、输入与输出指纹及终态，不采纳模型自报ID。

Supplement包括摘要、受控详细文本/引用、完整性和观点级别；可信作者/Run/时间由后端注入。摘要预算随任务约定，超长保存原文及不合规事实，显示摘录；可选补充缺失或摘要超预算不直接否定合格正式结果。

非阻塞 notices 明确分类并显示 `blocking=false`；严重资料缺失、权限不足或影响本次正确性的问题进入 blocked及Question。形式合法仍需业务校验，不允许模型自行宣布验证通过。正式正文变更形成新交付，不能编辑补充覆盖已接受事实。

详细报告受平台输出/附件能力限制。提供者有短输出限制时，公开该限制并拒绝截断材料，不能利用协议的较大总预算宣称该平台支持长报告。

## 6. Andon 直接处理与逐级返回

目标关系与逐级返回见<a href="图解/04-collaboration/collaboration-target.html" target="_blank" rel="noopener">CA-G04冻结架构图</a>。逐级处理与匹配返回另见<a href="图解/06-andon/andon-return.html" target="_blank" rel="noopener">CA-G06时序图</a>。当前Andon未实现；图不授予恢复或试验权限。

上级能在原目标/范围/预算/工具权限内提供解释或安排；改变正式批准依据需要对应Grant或人动作。各级保留来源答复和转译差异、适用范围、实际处理者。不得越级直接把所有问题交人，也不得把自己的新假设当上级原话。

处理节点有准确Owner、版本、lease和接替；父Run结束、崩溃或退出不丢义务。处理Run通过正常请求/FIFO或明确受控恢复路径派发，不回调绕过调度。已排队处理者被撤权/替换时不能继续以旧身份提交。

## 7. 求助模式、返回采用和恢复

| 模式 | 使用方式 | 可声明范围 |
| --- | --- | --- |
| delivery-only | 仅取准确交付，不能在线求助 | 不声明Andon可用 |
| blocked-return | 协作者输出受阻材料并自然终态；上级处理后创建明确后继尝试 | 新尝试采用答案；原Run没有恢复 |
| native-question | 提供者有已验证request/wait/resolve，可匹配原生问题 | 仅声明已证版本/目标的原生等待恢复 |
| notification-only | 只能报告状态或通知 | 不显示已送达/采用/恢复成功 |

答案携带 question_id/revision、answer_id、from/to node、wait_attempt、适用范围和输入增量。送达、采用和恢复是独立事实：传输接受不等于实际输入绑定；模型自述最多是asserted；可验证行为证明才达到verified。执行失败不因采用成功变绿。

终态受阻后的后继attempt保留predecessor/root和旧等待关系，重验当前目标/条件/权限；旧答案不能恢复新问题或错误尝试。未知接受结局不自动重发；取消请求、确认终态、真实副作用停止分别记录。

## 8. 持久记录和时间线

PostgreSQL拥有问题、修订、处理节点、转交/答复事件、送达动作、采用和恢复关联；Redis承担短期投递、缓存和lease辅助，不拥有最终义务。outbox在业务事务后投递，重启可重建待办。

事件记录因果父节点、实际actor、Q/版本、attempt、源/目标node、答复ID、授权与输入/转译指纹。原问题修改保留旧版；相似不同来源问题不合并。唯一动作键防重复送达，迟到owner不能覆盖新owner。

界面按问题展示“谁处理／需不需要我／答了没有／送到哪里／采用没有／执行是否继续”；工作详情读补充与准确结果；收件箱人类待办按当前人类义务去重。通知已读/归档独立，不能注销问题。

共享读Schema为 `collaboration.read/1`；handler、recipient、waiting executor、human obligation区分。动作只给准确对象导航，办理时重新校验权限与版本。Dashboard消费同一投影，不另造问题事实。

## 9. 个人有限正式授权

授权递进：具体既存草案一次；明确列举草案集合；一个可机械检查的类型化变更类别内生成新草案。Grant包含项目/主体/决定基准/版本、字段范围、数值关系、禁止变化、额度/期限/次数和撤销。

实际批准由治理Owner校验和执行，记录实际Agent及用户授权来源，不能伪装用户UID。批准和授权消费同事务；旧基准、撤权、过期、越界、重复意图、并发消费拒绝。

类型化类别需治理载荷Schema与canonical diff，规范正文可核对一致；自由文本语义不能只靠模型分类批准。类别由真实需要选择，首例并不自动成为通用预算规则。组织转授与审批链继续留第三阶段。

## 10. 安全、异常与能力验收

连接秘密不进任务正文、日志或前端；允许地址、当前可见性、精确关系、当前连接/目标修订、lease及副作用许可在执行前校验。目标核验与真实调用缺乏远端原子冻结时只允许明确专属资源，公开限制。

Provider的请求失败、接受不明、来源不明、已证输出但结构不合规各有可观察状态。保留核对入口，不能把状态手工改为成功或已停止。清理只作用试验专属对象，不能回写整份旧日常配置。

重启后的验收目标仍是：产品准确交付；直接上级真实处理；多级返回与重启接替；个人有限正式授权；真实界面与回溯；第二真实Provider与按文档独立接入。这些目标在暂停期间不执行、不登记已交付。
