# 信息架构与 Dashboard：U0/U1 首轮事实与讨论

日期：2026-10-08；源码检查基线：`5ac4a3c0`；[主规划](信息架构与Dashboard专项规划-2026-10-08.md)所列评估基线为 `ef65969`。本页供用户与专项参与者持续讨论使用，保存有来源的检查结果、待观察场景与未定事项。产品事实仍由源码和 Feature 拥有。

目标是明确页面职责、信息层级、生成能力及数据边界，并用实际操作校准问题。验收是每项事实可回查、推断与观察分开、未知项有下一步。本页保存 U0/U1 证据；当前已进入 [U2 第一轮整体比较](信息架构与Dashboard-U2整体方案比较-2026-10-08.md)。组件选择、定稿、产品实现与发布尚未授权。

已确认的信息需要见第 5 节；本页建议与正式产品 Decision 分开。U0 已有默认概览、工作详情及隔离人工单结果链路证据，未覆盖场景单列；U1 概念已进入 U2 比较，尚未收敛。

浏览器在公开首页两次点击登录发生命令超时，直接导航到登录页后正常渲染。该现象暂记为观察工具问题，未据此认定产品按钮故障。登录阶段未代用户提交登录表单或同意协议；登录由用户完成。该阶段未生成 Dashboard 或执行验收；后续授权的隔离人工验收见第 5 节。

用户已选定首条链路为“项目概览发现待验收 → 查看交付文件 → 办理”，并亲自完成登录。只读操作记录为：登录后对话页 → 展开项目 → 项目操作菜单 → Dashboard → 工作进展中的现有工作 → 工作详情。展开项目先显示对话，Dashboard 与工作台通过项目操作菜单进入；入口可达，发现成本待用户反馈。

实际默认概览在首屏显示四组卡片、较大的项目头部，关系图在其下；稀疏数据下卡片底部留有较多空白。首个样本待验收为空。打开其历史完成工作后，DOM 显示“历史完成，未记录验收依据”与“尚无业务结果记录”；讨论中出现产物路径文字，结果区没有对应交付链接。该样本只能观察历史完成与讨论的分层，不能证明从正式结果到文件的路径。报告内容为执行者历史自述，本轮未验证其中缺陷或产物真实性。记录保留抽象场景，排除用户名称、ID、原文与路径。

讨论建议：按“当前判断 → 必要摘要 → 具体办理 → 依据和历史”安排信息，先明确阅读层级，不冻结布局。Dashboard 的首层关注当前需判断的事、管理状态和关键变化；摘要应保留数量口径、来源、时间和目标对象。工作详情优先支持当前动作，旧要求、旧尝试与维护设置保持可回查。蓝图全文、关系图、近期决策各占多少注意力，需要实际样本校准。

默认概览已有四组：[默认组件](https://github.com/sxyon/Yuanlei/blob/main/web/src/components/project/DefaultProjectDashboard.vue)展示待处理、工作进展、待验收与执行异常，以及关系图、有效决策、蓝图、汇报、反馈与历史异常。[统计 Owner](https://github.com/sxyon/Yuanlei/blob/main/backend/package/yuxi/services/inspection_board_service.py)定义待处理为待准入议题、尚未转正式工作的建议及草稿决策；待验收单列结果份数与工作数；执行异常按每项工作两类入口的最新尝试派生，旧异常单列。受阻取正式工作 blocked，逾期排除 done/cancelled。不能把这四组直接加成一个总待办数。

统计按 UTC 日期判断逾期，并返回统计日期和时区；前端展示该说明。Asia/Shanghai 用户对当天截止的理解是否一致，是待讨论的业务日期问题，暂未改口径。项目 board 返回 generated_at，但默认概览没有显式呈现该读取时间。

## 3. 模板、实例、数据与技术限制

| 概念 | 研究边界 | 当前能力 |
| --- | --- | --- |
| 展示素材 | 指标、图表、列表、布局等的输入、行为与空错状态；静态图片/图标另行识别 | 已有 Vue 组件与图表依赖，不等于已有可供智能体发现的素材库 |
| 模板 | 可复用结构、输入与导航契约、适用场景和版本 | 默认 Vue 概览可作范例；尚无 Dashboard 模板版本/派生契约；蓝图文档模板是另一对象 |
| 项目实例 | 某项目采用的结构版本、自主修改与该项目绑定 | 当前保存单个静态 HTML 入口及 revision/hash/大小；未发现草稿、发布指针或历史回退管理 |
| 项目数据 | 来源、业务含义、项目范围、单位、时间与访问权限 | 默认概览读取授权管理事实；命名 JSON 具有独立持久 Owner，未注入 iframe |
| 渲染运行时 | 加载、受控读数据、合法导航、错误兜底 | 主应用可信 Vue 与无脚本自定义 iframe 为两条路径，未提供动态 bridge |

内置、个人跨项目共享、项目专属是待研究的来源范围。提取共享模板应提取结构与契约，排除原项目业务数据和凭据。模板版本、实例派生与当前启用版本分别讨论；模板升级如何影响现有实例尚未选定。

当前技术事实由[项目 Dashboard Feature](../../../develop-guides/yuanlei/features/project-dashboard.md)、[service](https://github.com/sxyon/Yuanlei/blob/main/backend/package/yuxi/services/project_dashboard_service.py)、[工具](https://github.com/sxyon/Yuanlei/blob/main/backend/package/yuxi/agents/toolkits/buildin/dashboard_tools.py)与[iframe 壳](https://github.com/sxyon/Yuanlei/blob/main/web/src/utils/dashboardFrame.js)相互核对：

- 自定义入口为 Project Workdir 的 `/dashboard/index.html`，UTF-8 内容上限 1 MiB；writer 拒绝 script、meta 与非页内锚点 href。
- iframe 使用空 sandbox 属性，无脚本/同源权限；CSP 禁止网络连接，只允许内联样式和 data URL 图片/字体。外部图片、脚本图表、Vue 与 fetch 数据均不具备当前加载能力。
- 浏览器 HTTP router 只有读入口。dashboard_read/dashboard_write 在根 Project Run 中重建项目范围并重新检查授权与 worker lease；子智能体调用被拒绝。
- 文件拥有页面字节，yuanlei 元数据拥有 revision/hash/大小；写入锁定项目、比较 expected_revision、原子替换并回读。磁盘失配或不安全内容通过 repair_required 暴露；revision 是并发控制证据，不能当作已有历史版本库。
- ready 自动显示自定义页；empty/repair_required 才进入默认管理概览。Dashboard API 失败显示错误，代码没有在这一分支直接显示默认概览；这是现有可用性边界。
- 默认概览在页面加载/返回激活、项目切换或点击刷新时读取数据；没有发现该页面的周期刷新或实时数据订阅。蓝图错误单独显示，board 错误阻断默认概览。
- 页面展示 revision、hash 和 bytes 属于技术信息。日常用户需要看到怎样的更新时间、来源、健康状态，留作信息层级讨论。

[前端依赖声明](https://github.com/sxyon/Yuanlei/blob/main/web/package.json)已有 Vue、Ant Design Vue、ECharts、D3、G6 等，只记录技术基础；不据此选定新库或渲染方式。Vue 页面生成、受控定义、静态快照三类路径仍留待 U2 比较。

## 4. 问题地图与讨论顺序

| 问题 | 已有证据 | 待讨论或观察 |
| --- | --- | --- |
| 默认与专属大屏怎样衔接 | ready 会替换默认概览，平台壳仍可进入项目工作台 | 管理概览与业务大屏各在什么时刻使用；是否需要稳定的管理入口与返回关系 |
| 第一眼该看什么 | 四组管理摘要之后仍有图、蓝图、决策和汇报 | 用户先找待办、风险还是全貌；哪些摘要值得保留首层 |
| 结果办理是否准确连续 | 后端链接到 `#work-result-<id>`，详情等待加载后滚动到对应 DOM；文件另开 Workspace | 单结果 DOM、准确锚点及独立预览返回已验；多结果、旧要求、不同尝试和窄屏未验；标题出视口与要求折叠的观察见第 5 节 |
| 维护与当前办理如何分层 | 要求编辑、人工结果提交、历史结果与多项设置同页 | 人工事项与开发交付分别需要什么最短路径，哪些设置应按需展开 |
| 已读与已解决怎样表达 | 通知打开前标已读，三个文件夹按阅读/归档分类 | 待答复或未恢复事项是否仍可找到；现有通知状态与业务状态如何关联 |
| 时间和数字是否可信易懂 | 逾期使用 UTC；结果份数与工作数分开；board 有读取时间 | 当天截止语义、数据取得时间、静态内容日期、旧值/缺数/示例如何表达 |
| 智能体怎样持续维护大屏 | 根项目工具只写静态页且校验 revision；未发现草稿/发布生命周期 | 首个业务样本、维护触发、预览启用与回退需求；自主维护的授权粒度稍后讨论 |
| 复用什么才有价值 | 已有组件，缺少素材发现、模板派生及绑定契约 | 两个实际项目共享哪些结构，哪些是专属；先找重复需要，再讨论库界面 |
| 协作求助展示什么 | [协作专项](协作接入与Andon专项规划-2026-10-08.md)要求区分上级处理中、待人答复、已答复未恢复 | 先接收 C0/C1 的真实状态能力，避免把执行中断或全部子任务问题计为人的待办 |

初始走查计划（已由第 5 节隔离测试补齐单结果链路）：先走一条“默认概览待验收 → 准确结果 → 交付文件 → 返回结果”的只读链路。用户说明每一步想判断什么、实际看到什么、哪里停顿。只查看验收入口，不提交验收。先确定一个项目和一份现有结果，避免以虚构全状态页面替代使用观察。

初始后续计划中的独立人工事项已证明无需先建议题或配置智能体。收件箱待答复及恢复、真实业务大屏数据来源与钻取仍未验；候选场景和原型安排转入 U2 主文档，单结果链路不重复执行。

用户确认没有待验收样本，并授权新建项目独立测试；已执行的合成测试见第 5 节。用户已反馈办理所需五项信息（第 5 节），无需再次确认。主题、窄屏、多个结果与尝试仍未验，进入 U2/U3 场景比较与原型计划。

当前按追加授权进入 U2 整体比较；保留未验范围并用合成场景推进研究。本页没有确定信息架构、组件、存储或发布方案。

## 5. 独立人工交付流程验证

用户授权在新项目测试。测试使用独立目录、无真实业务数据的 UTF-8 Markdown 文件及人工正式工作；不关联议题或决策、不指定数字员工、不发起智能体或外部委派。测试项目、工作、结果与文件保留在应用内，供后续讨论复查；运行 ID、账号与截图不写入仓库。

| 步骤 | 实际操作 | 回读证据 |
| --- | --- | --- |
| 创建项目 | 新建对话 → 选择项目 → 新建项目 → 新建独立目录 → 创建并选择 | 新项目出现在侧边栏；默认 Dashboard 四组为空 |
| 创建人工工作 | Dashboard → 项目工作台 → 项目工作任务 → 新建任务 | 首次设置编号缩写，填写工作描述与验收条件；详情显示待办、独立工作、暂无执行记录 |
| 准备交付 | 个人空间 → 测试项目目录 → 上传文件菜单 → 上传合成 Markdown | 文件列表回读名称、353 B 大小；文件内容最终由预览核对 |
| 提交结果 | 详情填结果摘要 → 添加证据 → 填项目相对文件路径 → 提交待验收 | 结果卡片显示人工提交、要求修订 1、待验收、文件可访问 |
| 从概览定位 | 重新加载 Dashboard → 点击待验收条目 | 待验收为 1 份结果/1 项工作；工作仍待办；链接含准确结果锚点，页面滚动到对应卡片 |
| 核对依据与文件 | 展开提交时验收条件 → 查看文件 | 新标签页直接预览 Markdown，标记与结论可读取；原结果标签保留锚点和展开状态 |
| 办理与终态 | 返回原结果 → 填验收意见 → 接受并完成 → 重载详情 → 重新读取 Dashboard | 详情显示已接受、已完成、验收意见与时间；Dashboard 待验收归零，已完成工作为 1，关系图保留已接受结果 |

本次 Passed 仅覆盖单份人工结果的真实浏览器链路。通过重载读取页面验证持久返回结果，没有直接查询数据库；未覆盖智能体自动导入、文件丢失、旧要求冲突、多个结果、断线、收件箱通知或其他用户授权。源码限制与这些未验路径继续分开记录。

实际操作引出的讨论项：

- 空概览的工作卡片只有“更多”，创建正式工作需经过工作台与工作列表；应讨论是否在空状态提供明确的新建入口。
- 首次人工工作创建需设置项目编号缩写。来源与负责人均可留空，但列表空状态文案强调数字员工执行；应讨论人工事项的默认引导。
- 结果的文件证据需要手输路径，文件上传位于个人空间另一路径；应讨论已有文件选择与上下文衔接，暂未设计文件选择器。
- 待验收条目以编号和完整结果摘要作链接，当前摘要较长；应讨论工作标题、交付摘要和时间的层级。
- 准确锚点滚动到结果卡片，但工作标题在可见区域外；提交时条件默认折叠。应讨论办理首屏是否同时呈现工作身份、依据、交付和动作。
- 文件在个人空间新标签预览，原结果保留。预览内没有回到该结果的业务入口，返回依赖标签切换；应讨论文件核对时是否需要更连续的办理上下文。
- 接受并完成后，待验收归零，历史结果仍可查。应保留这一语义；普通人工交付不依赖智能体运行成功。

新建项目后首次客户端跳转曾出现地址已进入 Dashboard、可见内容仍为对话页，重载后正常。暂标为待复现的导航/加载现象，没有定位根因，不归因于组件或路由实现；后续切换均读取真实页面再继续。

本轮只新增测试数据与研究证据，没有产品代码变更。用户已确认一项 U1 信息层级要求：从待验收进入结果时，应能直接识别工作标题、结果摘要、验收条件、交付文件和办理动作。其含义是办理所需信息可取得、身份和依据连续；不指定布局，也不要求长条件和文件全文铺在首屏。具体布局、文件预览方式和跨页面返回方案继续比较；这一要求不等于界面或技术定案。

## 6. U2 必要只读补充

源码基线仍为 `5ac4a3c0`，无新的业务操作。以下为 Inspected，未新增对应浏览器通过结论。

- [AgentFilePreview](https://github.com/sxyon/Yuanlei/blob/main/web/src/components/AgentFilePreview.vue)按文件接口结果展示图片、PDF、Markdown/文本、HTML、加载、错误与不支持提示，带全屏能力；[Workspace](https://github.com/sxyon/Yuanlei/blob/main/web/src/views/WorkspaceView.vue)使用该组件。结果面板未直接装配它，复用需要重新确认只读 props、文件授权与返回上下文，不能据组件存在宣布办理内预览已完成。
- [文件选择器](https://github.com/sxyon/Yuanlei/blob/main/web/src/components/ProjectFilePickerModal.vue)通过个人空间文件树选择路径并回传附件；不等于交付证据已关联或项目文件可任意互用。人工结果仍沿第 5 节路径填写，候选集成需在证据持久化与 owning 文件边界验证。
