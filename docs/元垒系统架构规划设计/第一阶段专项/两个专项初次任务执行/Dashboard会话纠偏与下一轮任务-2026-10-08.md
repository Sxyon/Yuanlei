## 3. 本轮同时覆盖两条主线

第一条是日常操作：项目导航、默认管理 Dashboard、工作台、工作列表和详情、收件箱、智能体工作台。说明各页的主要动作、第一层信息、按需展开内容和跨页连续性。

第二条是项目 Dashboard 能力：默认样板、素材库、模板库、项目实例、项目数据、运行时，以及智能体读取、生成或派生、验证、启用、更新和回退。不能因为验收页有问题，就把专项缩成验收页改版。

继续坚持个人先用、项目扁平、标签分类承担领域区分；团队成员、组织审批和跨用户模板权限留第三阶段。共享模板现阶段是内置和同一人跨项目复用，结构共享不携带项目业务数据或凭据。

Dashboard 是观察、分析和导航入口。办理页面承担业务动作；必要的轻操作可以研究，但不能把所有表单移入大屏。

## 4. 首先建立完整的问题与场景地图

自主整理已有证据，补齐必要的只读检查。对已核实事实不要重复执行整个流程。缺少实际样本时可以使用明确标注的合成数据设计候选，不制造业务事实；未来真实验证仍单列。

至少覆盖以下场景，每个场景写清用户目的、目前路径与困难、候选路径、所需数据以及未验项：

| 场景 | 必须解释的问题 |
| --- | --- |
| 打开项目 | 第一眼看什么；管理概览与业务大屏怎样选择；进入维护和工作的入口是否稳定 |
| 人工独立事项 | 如何直接创建工作、交付和办理，不强制先建议题或配智能体 |
| 研讨到执行 | 蓝图、议题、决策、正式工作如何关联展示，怎样看当前依据和历史 |
| 交付验收 | 多份结果、旧要求、不同尝试怎样准确定位；怎样核对文件和返回当前办理 |
| 跨项目收件箱 | 已读和已处理如何区别；已答复但未恢复怎样保留入口 |
| 智能体执行 | 如何辨认接收、执行、异常、求助处理者和需要人介入的事项 |
| 项目业务大屏 | 数据来源、时间、更新、缺数、过期和钻取怎样表达 |
| 智能体维护大屏 | 从模板或自主设计到草稿、验证、启用、竞争更新和回退怎样完成 |
| 模板复用 | 同一模板两个项目的结构、数据绑定和版本怎样分开 |

主题、窄屏、长标题、密集数据、空/错/加载作为共同检验条件。不要求每一种状态都由我陪同点击。实际访问条件缺失只阻塞相关验证，不阻塞其他研究。

## 6. 交付完整的候选方案和明确推荐

### 6.1 信息架构与交互候选

形成二至三套有实质差异的跨页面方案。每套用同一组场景展示导航、页面职责、信息层级、关键操作和返回路径，配页面关系图、关键页面线框及一次办理时序。不要用三套配色充当三套方案，不为凑数量制造明显不合格的方案。

比较维度包括发现入口、切换次数、上下文保持、多人以后扩展的余地、密集信息处理、移动端适用性、现有页面迁移成本及维护成本。数量和点击次数可以辅助，不能替代正确定位与判断质量。

可从以下暂定建议开展比较，但需要给出理由与反对证据，不能直接视为我选定：稳定项目导航；管理概览与专属业务大屏可以切换且不丢失兜底入口；工作详情以当前动作和交付为中心，历史和设置按需展开；文件采用轻量预览和独立打开的组合，而非所有文件一种方式。

特别解释为什么不直接问我“预览还是新标签”：Markdown、图片、PDF、大文件、长文对照和窄屏的需求不同，应先提出具体组合方案、支持范围与失败行为，再讨论真实分歧。

### 6.2 Dashboard 能力候选

分开比较渲染、数据交互、存储、模板复用及发布方式，最后说明推荐组合。信息架构方案和技术方案可以组合，不绑定成无法局部调整的套餐。

| 维度 | 要比较的真实取舍 |
| --- | --- |
| 渲染 | 受控定义与可信 Vue 组件；生成 Vue 代码经构建和隔离加载；静态快照与平台受控导航。比较自由度、图墙表现、可验证性、依赖与维护 |
| 数据与导航 | 各方案如何按当前项目受控取数、刷新、显示语义和时间，如何跳到准确对象；后端如何执行现有权限 |
| 素材与模板 | 素材如何被发现和使用；模板结构、输入与版本；项目派生、模板升级和共享提取如何工作 |
| 存储 | 当前项目目录过渡方案与集中索引/定义管理各有什么代价；文件字节、定义、版本、绑定由谁拥有 |
| 智能体维护 | 工具输入怎样演进，草稿与当前启用版本如何区别，竞争更新、验证失败和回退如何处理 |
| 发布 | 人预览启用、明确配置的自动启用、可信模板有限自动启用，各自怎样服务自主维护和安全边界 |

当前静态 HTML 限制是现状，不能把它当作未来无动态能力的目标；未来 Vue 能力也不能通过解除全部限制取得。自主维护不自动变成每次修改都人工审批。对这些取舍给出推荐及需要试验证实的条件。

## 7. 把推荐转成下一步建设安排

推荐后按依赖和模块形成可执行增量，而非列概念清单。每项说明用户能得到什么、涉及现有页面/服务或工具、实现约束、兼容边界、验证方式、前置项及验证失败的退路。

可以按以下顺序组织研究安排，并据比较结果调整：先确定页面职责与稳定入口；用关键办理页面和默认管理概览验证信息层级；用一个项目业务大屏验证数据和导航契约；验证模板派生与智能体草稿维护；再扩充素材和模板管理。说明哪些视觉、交互和基础能力可以并行，哪些必须等加载契约。

同时提交下一轮原型计划：选哪些场景、采用哪些明确标注数据、要验证什么不确定性、观察到什么会推翻推荐。本轮无需完成全部可交互原型，但不能把“后续再看”当原型计划。
