## 2. 当前需要用户掌握的判断

项目入口的可发现性、卡片/列表的信息密度、新增/编辑是否自然；主题是否能体现项目自己的组织与术语。加载技术、存储目录和协议等必须先调研、小试并给推荐。执行者负责界面设计与技术论证，用户判断目标、关键边界和取舍。

用户可随时提出新方向或指出不合理之处，执行者立即识别影响、停止受影响后继并修订。每段只要求当前关键选择有足够信息，不要求用户预先替未来所有任务拍板。

## 3. 汇报怎么读

日常先看“进度：可观察结果；问题：影响、选项和推荐；计划：下一小段及条件”。关键选型看“现状、问题、方案、建议、请示”，每方案附真实采用者与验证范围。页面稿先看整体编号，再看模块理念，最后看关键分歧。未接数据、未持久化、未实施均醒目标记。
