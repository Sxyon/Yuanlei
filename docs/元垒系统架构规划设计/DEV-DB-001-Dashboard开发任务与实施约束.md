## 2. 通用实现约束

- 复用 Vue、现有 Ant Design Vue、ECharts 与 CSS 变量，不更换 UI 框架，不先引入可视化拖拽编辑器。
- 页面通过 `web/src/apis` 调用服务；真实授权、对象关系与并发写检查在后端 service/repository 或 owning 文件边界执行。
- 新增结构进入 `yuanlei` 域，由 migrator 幂等升级；版本以提交时现值递增，不能写死长期 v38。
- 每个新机制有当前页面、工具或服务消费者；不一次提前建立整张规划表清单或通用政策引擎。
- 定义、草稿、稳定页、业务数据、操作历史分别维护；接受结果、正式批准、任务启动不放入动态大屏桥。
- 正常写操作保留本人输入，过期提交明确冲突；不得自动换 expected 版本重放。
- 相关 unit 证明规则，HTTP/PG 证明真实授权与事务，实际浏览器/文件证明使用结果。涉及 root Run/worker 的包加真实 worker 证据。
- 产品代码按仓库规范独立 Review；每批记录实际 commit 和证据。执行中的新范围反馈写 LOG，改变需求再改 SYS。

## 3. DB-T01｜治理工作台收尾和蓝图安全保存

**使用结果：** 可以连续读蓝图、研讨、查看批准决定、创建/关联工作；并发和旧深链不会改错对象。

**修改落点：** `ProjectInspectionBoardView.vue`、project 下历史/讨论/建议组件、`governanceDrafts.js`、`governance_board_api.js`；蓝图增量在 `project_blueprint_router.py`、`project_blueprint_service.py` 与 owning Workdir 原语。

**子批与实现：**

1. 核对现有 D1 实现及残余，不重复重写分栏和草稿。用真实隔离对象验证旧修订/comment 深链、归档/重开/拒绝复议、决定勘误/替代/撤销、建议 create/link 与汇报入口。
2. 蓝图加载同时保存内容 hash 和文件 identity；恢复草稿保留其原依据。扩展普通写入请求模型和 API 封装，调用已有带预期 hash/identity 的 service/文件替换原语。读取后的编辑覆盖必须有预期依据；新建使用原创建接口，避免把缺依据更新混为创建。
3. 冲突显示当前版本与原草稿的比较/复制出口；只有显式重读/放弃后才能改用当前依据。共享 Workdir 和删除重建的同名文件也要拒绝过期覆盖。检查其他普通写调用方，避免同一编辑入口可绕过新约束。
4. 真实账户切换、登出、失权和项目/对象 404 场景回验；普通单对象消失时仅提供仍可见项目内的复制出口。

**界面：** 阅读为默认，编辑按钮明确；当前决定、关联工作优先；历史/低频维护展开；390 窄屏保留列表返回。输入草稿不显示“已保存”。

**验证与出口：** 两个浏览器/调用方读取同一蓝图，先保存者成功、后保存者409且文件字节保持先保存内容；同名替换身份变更拒绝；旧深链准确；全部旧操作至少各一个适用真实页面场景；跨账户缓存清除；主流程及 PG/Workdir 回读一致。

**退路：** 保留旧 URL/对象组件和可复制草稿；受保护写失败不退回无条件覆盖。此包不新增治理状态机、蓝图修订数据库或通用 diff 编辑器。

## 4. DB-T02｜工作列表、管理概览与准确交付入口

**修改落点：** `ProjectWorkTasksView.vue`、`DefaultProjectDashboard.vue`、`ProjectWorkTaskView.vue`、相关 `project_work_api` 与工作/结果 query 服务。

**子批：** 工作行信息重排→注意事项过滤与概览卡→准确结果/尝试导航和返回。

**功能和实现：**

- 每行显示编号/标题、业务状态、需本人动作、负责人标识、准确尝试状态及待验收结果。分别查询业务和执行事实，前端不从“最近 Run”猜结果。
- 保留看板/列表/甘特、日期与旧管理动作；人工新建常驻，无 Agent/议题/决定合法。
- 待验收、受阻/失败、逾期过滤有明确来源；若当前列表缺准确结果字段，由现有 query 最小追加，记录字段来源与边界，避免每行独立 N+1 查询。
- 概览卡进入准确 task/result/execution，卡片数与列表筛选使用相同服务口径；空、错、刷新保留分开。

**界面：** 标题和需要做的动作优先，技术来源/轨迹展开；点击工作与点击某份结果区分。返回恢复项目、过滤、排序、滚动。

**验证与出口：** 两项目同名工作、两份交付和旧条件准确；人工工作完成完整链；过期结果链接明确报失效；失权不残留；计数能从实际对象回读，不将失败 Run 当失败工作。

## 5. DB-T03｜跨项目收件箱和通知处理边界

**修改落点：** `InboxView.vue`、inbox API、`user_inbox_service.py` 和已有对象可见性查询。

**子批：** 项目身份与分组→已有真实办理入口→筛选返回与失效处理。

**功能/界面：** 第一层区分“需我处理 / 交付入口 / 通知”；每行有项目、工作、准确对象和动作说明。通知已读、未读、归档独立筛选；标记已读/归档不改变工作验收和异常状态。

当前缺人类义务投影的场景明确显示未接入，不能用“通知未读”生成新的业务待办。仅接真实已有操作，暂停中的 Andon 入口不造绿色状态、不造可答复按钮。保留版本化投影消费位置，重启时按真实契约追加。

**验证与出口：** 从跨项目入口进入正确结果，处理后返回原筛选；同名不同项目不串；已读/归档不使未办交付消失；对象不存在/无权有明确提示，真实换身份清理缓存。

## 6. DB-T04｜项目 Agent 接收、异常与交付分层

**修改落点：** `ProjectAgentsView.vue`、`ProjectAgentWorkbenchView.vue`、项目 Agent/work-execution API 与现有 query。

**子批：** 员工选择/队列→运行/异常/交付→配置次级与准确返回。

**功能/界面：** 待接受、排队/运行、异常、交付分组；业务工作与执行状态分开。接受/撤回/重试沿原用例，交付点击 result，运行点击准确 execution。模型和自动接受配置放次级，当前责任与操作醒目。缺外部问题链时具体显示限制。

**验证与出口：** 一个现有 Agent 工作经历接受→运行→异常或交付→准确详情→队列返回；旧尝试输出不会冒充新尝试；队列与工作状态来自实际服务；现有用户授权与配置语义保持。

## 7. DB-T05｜版本化定义、项目实例与草稿管理

**修改落点：** 新增 Dashboard 定义/service/repository/Schema；基于 `ProjectDashboardView.vue`、`project_dashboard_api.js` 新增项目实例管理入口。新命名随本包提交确定。

**子批：** 定义与数据契约→最小迁移/API→管理页面可创建/编辑草稿。

**实现细节：**

- T05先实现真实消费者需要的instances、revisions、project config；验证报告、启用事件及授权消费由T07/T11随真实消费者补齐；模板版本引用可空，库由 T09补，维护政策由 T11补。精确外键和后续演进在迁移方案写明。
- 定义 Schema 包含版本、输入槽、布局、素材版本、映射、格式、动作；注册可信素材和 `work.results` 读契约，禁止 URL/JS/SQL。
- 项目范围从当前用户和 owning project 重建；共享 Workdir 不共享实例状态。草稿追加不可变 revision，保存携带 expected_head 与 operation_id；重复同输入返回原修订，异输入拒绝。
- 管理页列所有实例的草稿/生效/来源状态，可以创建交付观察草稿、编辑显示参数、读取准确修订、查看机器错误。未启用者明确标草稿。

**验证与出口：** 真实 HTTP/PG 创建→保存→重读管理页；非法类型/版本/素材/预算/跨项目拒绝；旧库升级幂等、旧静态页保留；并发 head 仅一个成功。单独完成此包只能登记草稿能力，不能写“动态 Dashboard 已完成”。

## 8. DB-T06｜可信 Runtime 与实际结果取数

**依赖：** T05。**子批：** 可信组件装配→授权数据读→预览和槽状态。

**实现：** Runtime 将 `component@version` 映射为审查过的 Vue 组件，统一通过 API 数据服务请求；数据源、分页和过滤在后端白名单执行。首屏实现指标、准确结果列表及工作分组，真实来源为现有 query；不手抄 fixture 进入正式数据。

每槽显示 as_of、版本、单位、完整性、分页；缺绑定/空/候选/过期/故障不同。实例渲染错误被局部隔离，管理入口在宿主保留。迟到响应按 uid/project/instance/revision/request sequence 丢弃。

**界面：** 预览有项目、实例、准确草稿修订和水印；窄屏顺序随定义且控件可操作；未知状态不显示零。

**验证与出口：** 实际工作结果变化后刷新取到真实新数据；独立负向非法源/过滤、串项目、越预算、失权、坏组件；PG/HTTP/DOM 一致。未启用预览不改变项目首页。

## 9. DB-T07｜手动启用、回退、首页和宿主返回

**依赖：** T05/T06。**子批：** 项目验证→原子启用/首页/回退→准确导航与返回。

**实现约束：**

- 验证绑定定义/绑定hash、规则/依赖、数据契约、权限及有效期；启用前重验必要绑定是否仍可读取。current数据槽不要求每个数据值永久不变，固定修订槽须核准确修订；缺必要源拒绝新启用。
- 启用检查精确 head/active/config，同事务写启用事件及指针；operation_id绑定动作/参数/调用主体及精确版本，重复同输入返回原结果、同键异输入拒绝；首页引用本项目合法稳定实例。实例启用和设首页默认分开显示。
- 回退目标必须是同实例曾启用稳定修订，按当前规则重新验证；追加事件、不改草稿 head、不回滚数据。
- 素材事件→宿主注册动作→后端对象关联/权限→准确可信办理页。首版支持实际已有工作/结果/执行/议题/决定；问题/外部尝试动作留待协作真实路由。
- 按 SYS 短期 token 登记观察状态；服务端登记 uid、项目、实例、修订和准确对象，业务页仅传 token。过期/失权回管理，历史修订读仍检查当前权限。

**界面：** 生效与草稿并排说明；启用前看差异与实际数据状态；错误保留当前页；返回新版时明确可选历史/当前，不悄悄改观察依据。

**验证与出口：** 手动启用后真实页面读取 active；准确 R2→文件/办理→恢复月份/修订/位置；并发启用409；伪 return 参数/跨项目/旧报告/归档首页拒绝；Redis不可用退路；回退稳定版真实可读。

## 10. DB-T08｜项目业务数据、分析与经营一屏

**依赖：** T06/T07。**子批：** 有界业务数据候选→人工采纳→真实经营图表。

**实现：** dataset service/repository 保存项目修订、字段/单位/as_of/来源/hash和采纳。首版 monthly 与 classification/region JSON 两种契约，以及独立 analysis 类型；字段、行/字节上限发布在规则中。导入只读用户选定授权文件对象，禁止任意目录扫描。

候选校验失败可定位行/字段；采纳有版本守卫。数值事实与分析分开，分析可选；删除分析模块后仍能形成合法纯业务图。固定 revision/current 模式显示准确数据时间；页面回退不回滚数据。

**界面：** 项目大屏管理增加数据源/候选入口，预览标“候选”；经营页显示趋势/分类表、缺数、单位、分析依据。源缺失提供绑定/修复入口，稳定页故障不自动改发布指针。

**验证与出口：** 两项目不同数据、单位错误/非法字段/旧文件hash/跨项目/超限被拒；人工采纳后图表真实更新；无分析合法；无效候选不冒充正式数值。给出真实业务样板或明确合成 UAT 数据，不把合成业务资料当真实经营事实。

## 11. DB-T09｜模板素材库、多实例和版本管理

**依赖：** T07；经营模板的真实数据验收另依赖T08。**子批：** 库与派生→多实例/首页→升级/提取/归档。

**实现：** 内置、个人共享、项目专属范围；不可变模板版本与素材依赖；同模板不同项目独立绑定；项目至少两个实例、最多一个当前业务首页。模板 v2只生成显式升级草稿，既有 v1不变。

模板提取删除实际数据、项目绑定、凭据和敏感来源；保留逻辑输入要求。项目专属提取为个人共享需要显式动作并清理引用。归档资源不毁引用历史，受保护删除拒绝；首页归档必须替代或清空首页回管理。

**界面：** 库有用途、预览、输入要求与版本；项目管理列生效/草稿/模板来源/缺数，预览与设首页不同按钮；升级显示映射变化及数据缺口。

**验证与出口：** 两模板、两项目、各自多实例；同目录不串状态；v2升级缺字段失败、v1稳定；提取不泄露行数据；历史回退与归档保护实际 HTTP/PG/DOM通过。不是只加两项内置枚举。

## 12. DB-T10｜真实项目 Agent 生成与候选交付

**依赖：** T09（含T07）。T10a页面生成与子定义候选先执行；T10b业务数据候选依赖T08，并复用T10a已验证的真实Agent规则消费与候选交付工具出口。两子批共同满足T10出口，分别登记，避免页面生成等待数据导入。

**实现：** 目录、实例读、草稿保存、验证、启用工具消费统一 service。动态定义工具与旧 HTML read/write 参数显式区分，禁止自动猜格式。实际 root Run→Conversation→Project、uid、worker lease 控制工具范围；子 Agent 不直接发布，只返回可校验候选。

规则提供两个模板、自主组合、错误修复、数据候选与正式事实边界例子；工具返回精确对象版本、错误位置、preview和验证ID。根接收子定义候选后核对项目/来源/版本，再由根保存。业务数据候选可生成，人工采纳与页面启用分开。

**界面：** 项目管理能看到 Agent/Run 来源、草稿、验证错误、预览和待本人启用；聊天反馈不能替代 active 指针回读。

**验证与出口：** 真实已有项目根 Agent 经实际 worker发现规则→生成两种结构之一→保存→修错→验证→本人启用→浏览器实际读取。子工具负控、失 lease、两个 Run CAS、跨项目/旧报告均拒绝；人工写 JSON或直接调用工具单测不能算真实生成闭环。

## 13. DB-T11｜固定模板有限自动维护

**依赖：** T10a和T09。页面有限维护不等待T10b数据候选；完整收尾仍需要T10b。**子批：** 个人授权表单与事务→真实范围内自动启用→撤权/冲突负控。

**实现：** 精确模板/素材版本、允许修改的字段/参数和 source、期限/次数/预算、是否允许首页切换和回退。数据采纳另列政策，不随布局授权默认开启。策略消费、权限重验、版本守卫、启用记录同事务。

授权内不重复问人；越界保存草稿并显示失败原因；未知素材、跨项目、模板升级、新导航类型拒绝。自由组合可保存并人工启用，自动启用不在本包扩展。

**界面：** 本人可看授权范围、实际使用次数、到期与撤销；每次自动变更可看实际 Agent/Run、差异、验证与稳定版本；能撤权并人工回退。

**验证与出口：** 实际 root Run在已明确授权范围内变更并启用一次，准确消费/actor回读；撤权/到期/越界/重复operation/旧config/并发不会错误启用。测试授权使用明确隔离对象，工程开发不默认授权日常项目自主发布。

## 15. DB-T13｜连续使用验收和专项收尾

**依赖：** T01—12 的完整出口（包括T10a/T10b），协作增量保持暂停登记。

**顺序：** 治理→人工/Agent工作→准确交付→收件箱→模板派生→项目绑定→实际大屏→返回观察→Agent生成→有限维护→故障回退。
