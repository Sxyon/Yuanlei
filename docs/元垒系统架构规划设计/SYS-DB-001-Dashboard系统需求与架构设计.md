# SYS-DB-001｜项目主题需求与设计

本页保存项目主题的产品范围与稳定取舍，供设计、维护和后续验收使用。工程落点见[DEV](DEV-DB-002-项目主题实施指南.md)，当前状态及用户确认见[LOG](LOG-DB-001-Dashboard进度基线与执行记录.md)，操作和字段分别见[使用指南](../intro/project-theme-authoring.md)与[配置参考](../advanced/project-theme-reference.md)。

## 目标与覆盖范围

同一主题机制承载日常管理、精简观察和课题调研等组织方式。全部项目页面、准确对象详情、编辑、历史和办理位于当前项目主题中，覆盖总览、蓝图、议题与决定、行动计划、工作与结果、督查与汇报、资料、项目智能体、属性与资源设置。公共主题库、本人共享凭据、全局聊天和跨项目收件箱由平台承载，跨界入口明确可见。

主题作用于完整项目体验。可信业务能力组件复用原API、权限、业务状态和审计，界面按主题重新组织。静态自定义HTML Dashboard继续保持独立无脚本展示；受控主题包采用JSON与声明素材，不携自由JS、SFC、任意请求、SQL或宿主路径。<a href="图解/34-theme-overview-20261018/project-theme.html" target="_blank" rel="noopener">当前主题架构图</a>展示这些边界。

## 产品组织与交互原则

默认完整主题按“思考、行动、资源”组织九类能力：总览／蓝图／议题，行动计划／工作／督查，资料／智能体／设置。决定在来源议题内办理，同时保留无来源决定及跨议题查询的准确索引。名称和顺序可由主题改变，业务对象身份保持。

| 区域 | 保留的设计结果 |
| --- | --- |
| 项目入口 | 平台项目列表支持卡片／列表与搜索；新建一次保存完整管理属性。图标复用上传，slug首次设定后不可变且全局大小写不敏感唯一，UUID继续拥有路由身份；Workdir编辑只读，弱负责人不授权 |
| 全部项目页 | 项目导航提供页面身份，操作条保持紧凑；搜索／筛选和新建同栏。准确对象详情保留真实标题，元数据与低频维护按需展开 |
| 总览 | 展示需关注工作、蓝图摘要和最近动态；蓝图标题与片段共享准确链接，动态定位准确议题／决定／回复，信息有界，完整内容进入原对象 |
| 蓝图 | 保留单文档详情和多文档折叠两种布局；选择器定位准确文档，主体切阅读／编辑，历史只读并可返回原布局、选择、草稿与阅读位置 |
| 议题与决定 | 正文持续可读，下接折叠决定和混合动态；讨论／执行／历史筛选只作用动态。草案编辑、批准、勘误、补充、替代和撤销沿各自真实状态办理 |
| 行动计划 | 复用原工作建议模型，表达预期结果、计划内容和来源；转为或关联一个正式工作。create／link幂等及冲突由原Owner执行，多工作计划模型留后续判断 |
| 工作与督查 | 工作详情优先依据与准确交付审核；督查优先待介入异常及汇报。Run结束、结果接受和工作完成分别呈现 |
| 设置与资源 | 本人Git连接在用户设置维护，项目保存引用；属性和资源为独立业务卡片，资源审查内嵌，风险动作与审批历史可查 |
| 导航与返回 | 保留旧URL的准确对象、修订、评论、类型及hash；回到当前主题能力页，恢复查询、选择、滚动和焦点；主题设置浮层独立可达 |

正文阅读宽度、适当密度、可见焦点、明暗样式、窄屏与空错状态由可信组件维护。弹窗沿现有组件补齐分组、错误、危险确认和草稿离开保护。批准设计的准确原型与确认回执保留在<a href="图解/21-full-project-theme-20261013/review.html" target="_blank" rel="noopener">设计基线</a>及[确认记录](图解/21-full-project-theme-20261013/design-approval.json)；原型中的统计与操作为合成，产品事实以真实Owner和LOG为准。

## 受控定义与能力继承

主题通过受控定义选择已注册可信能力、有限布局、词汇、密度和资源。未定制能力在同一主题壳中继承明确版本的基础界面。默认、精简、调研三套组织共用此机制：精简可隐藏部分主导航，准确对象及办理仍通过完整可信能力到达；总览保持可见。隐藏功能只改变发现方式。

当前formatVersion、componentAbi和baseVersion由正式契约及[配置参考](../advanced/project-theme-reference.md)维护。历史不可变ZIP与既有Project绑定继续有效，升级需显式选择。主题词汇仅替换平台提示、标签和导航，用户标题、正文、讨论、原因与历史快照保留原文。新的能力／动作必须有真实消费者和版本兼容判断。

## 来源、草稿、版本与项目选择

主题来源拥有库身份、归属、可编辑草稿及版本历史。内置只读，“我的主题”仅供本人项目复用，项目专属限定有权Project。包内作者文本、theme.id和digest表达声明与字节；后台身份由服务生成。

草稿保存校验并推进候选revision；发布登记不可变版本；分配才推进Project唯一绑定及generation。编辑或发布不升级已使用项目。平台主题管理支持完整管理与准确版本分配，项目主题设置提供快捷选择与恢复，两入口使用同一服务和同一绑定。具体制作顺序见[使用指南](../intro/project-theme-authoring.md)。

只读预检与最终应用共用条件：来源可选、当前Project有权、版本及依赖兼容、必需文件有效、预期generation一致。应用时重新校验并回读。切换前保护真实未保存字段，宿主按用户、Project、准确包和generation隔离导航、正文与异步响应。另一窗口的旧结果不能覆盖新上下文。

## 双数据、真实预览与故障

业务数据沿原治理、工作、结果等Owner读取和办理；Project文件由逻辑alias映射到目标Workdir相对路径，经Project授权、no-follow、大小及实际媒体校验读取。包内素材与Project资料分开，Project级alias不暗示逐议题附件关系。

完整能力及混合主题预览在有权Project的同一真实宿主中读取准确候选revision或发布version，临时文件映射与持久绑定分开。正文inert只读，主导航可切页；结束预览重新读取持久选择。历史纯区块预览保留明确合成标识。实际授权由后端拥有。

未绑定或包故障时展示可信基础界面及明确恢复入口，保留原绑定和错误原因；失权清空内容并返回平台。停用阻止新发布／选择，旧版继续加载；安全撤回停止加载并保存原因。草稿冲突保留输入，结果不明先回读准确身份、修订和摘要。存储检查与清理分开，清理只作用锁内复核的未引用普通包及临时残留。

## 原包迁移与退出边界

准确已发布版本导出存储中的原ZIP及摘要；导入先只读预检，确认时重传、重新解析并核对摘要，保存目标可编辑草稿。导入、发布、应用分别确认。未编辑原包在兼容目标实例发布并再导出时保持逐字节一致；编辑后按新内容和新版本管理。

目标实例生成本地来源／版本身份，重新授权Project及alias。ZIP仅携定义与声明素材，业务行、身份、凭据、Workdir路径、绑定映射和generation留在各自环境。作者自行写入素材的内容随原包携带。未知依赖、越权、旧修订、同来源同版本异字节及错误文件明确拒绝，结果不明先核实。

完整验收要求两套不同数据库、主题根、身份与Workdir的正式隔离实例，经过正式migrator及应用startup，再验证A导出→B草稿→目标预览→发布→分配→目标业务办理返回→重启→显式切回，核对A及B对照项目保持。当前完成与缺口只在[LOG](LOG-DB-001-Dashboard进度基线与执行记录.md)登记，暂停不补记最终通过。

后续按明确需求评估Agent专用生成／维护工具及有限自主发布授权、素材／模板库、更多格式、团队权限和第三方平台适配。原S07核心界面强化已经前置，后续改进由真实反馈驱动。协作与Andon保持暂停。
