# SYS-DB-001｜项目主题与 Dashboard 需求及设计方向

版本：3.1，2026-10-17。读者：用户、设计与开发执行者。本文拥有产品方向和当前待验证问题；实施见[DEV-DB-001](DEV-DB-001-Dashboard开发任务与实施约束.md)，事实与阶段判断见[LOG-DB-001](LOG-DB-001-Dashboard进度基线与执行记录.md)。R3技术路线已获用户采纳；当前实施指南见DEV-DB-002，调查材料只供归档追溯。前版细节见[历史快照](归档/2026-10-11-渐进推进前/README.md)。

当前接续由第16节“S06迁移、专项收尾与试运行交接”拥有；第15节保留真实消费与切换边界，第14节保留已批准页面与交互基线。第10—13节保留历史依据，不再领取“主题阅读＋旧管理页”方案。当前默认主题样式由用户指定为基础版本；这项指定不代表S04／S05整体验收通过。

## 1. 产品方向：项目主题

元垒维持个人先用、项目扁平管理、负责人弱关联，组织权限放第三阶段。项目主题是项目的表现与组织方案，覆盖 Dashboard、工作台、议题、讨论、决定与任务入口，包含布局、局部导航、显示名称和内容呈现。主题不局限于颜色，也不局限于首页大屏。

同一套议题能力可在不同项目中显示为“议题”“课题”“战略规划”。主题声明显示名称和用途，业务仍使用稳定对象身份、状态与接口；改名不自动产生一种新业务类型。并非所有战略规划内容天然都适合议题，涉及蓝图或目标的内容仍归真实职责。正式批准、替代、撤销、任务接受等语义与权限由原业务Owner执行。

先建设主题基础框架，再强化默认主题的人机交互。基础阶段的“默认”“调研”是用于验证不同组织方式的两个具名样板，不宣称默认主题已达到最终日常管理体验。

## 2. 项目管理入口

平台一级导航新增“项目”，与“智能体”并列。项目管理包含二级入口“项目列表”“主题管理”。项目列表顶部有搜索、新增项目、卡片/列表切换；参考智能体管理的现有设计语言，按项目信息重新安排密度，不复制所有属性。

卡片默认突出图标、名称、简短描述和主要进入动作，slug及其他元数据按价值安排。列表提供核心默认列、合理默认宽度和可调列宽，列选择及偏好范围在当前设计中说明。长名称、空描述、大量项目、空/错/加载和窄屏均须展示。

新增项目表单参考新增智能体的体验，目标字段为名称、图标、slug、描述及现有项目属性。已有可选归属保持可选；名称/slug校验、现有Workdir创建意图不能被“非强制”笼统取消。字段缺失先在设计稿标新增，不做假保存。slug是否可变、唯一范围和旧链接迁移由当前字段调研确定。

主题管理展示内置、个人公共、项目专属资源及其版本、可用/停用状态、来源和维护入口。全局主题管理与项目选择/配置有不同范围，最终导航如何返回项目由样板验证。停用不默认破坏已绑定项目，处理方式在加载阶段验证。

## 3. 前端先行与已采纳技术

S01项目入口已验收；S02 R3路线已获用户采纳：现有Vue可信组件注册＋受控JSON及内容资源。后续按同一包、数据、保存和迁移契约实施，不再启动候选选型。具体工作落点、支持范围和各段验证由[DEV-DB-002](DEV-DB-002-项目主题实施指南.md)拥有，研究仅供归档追溯。

下一实施段S03先在独立预览入口形成默认/调研两主题六页，复用现有Vue组件与样式。模拟数据明确标识，验证组织差异、切换和返回；持久保存、真实数据与迁移分别在S04—S06按既定路线接通。尚未接通的操作显示未接通，不将演示成功写成产品能力。S03按第10节R1确认范围实施，实际证据及用户阶段判定由LOG最新节拥有。

可信平台组件承担加载、导航和业务动作；生成内容限于受控定义与声明资源，不获得自由脚本、任意接口或业务写权限。格式与能力边界按指南第3节执行，增加自由执行或授权范围须明示新的范围与代价。

## 4. 文件存储、公共与专属资源

目标是两主题各有可管理的文件包、明确身份及版本，可加载、切换、编辑和维护。公共主题受保护，与用户/项目可写内容隔离；项目智能体生成主题进入该项目的候选来源，不直接覆盖公共资源。

文件字节与项目业务身份分别核对，不能因两个项目共用Workdir就共享主题启用状态。指纹用于检测字节一致性，不等于可信来源或授权；受保护资源还需写权限与来源校验。公共/个人/项目候选按来源授权进入受保护服务文件域；发布版本不可变，PG保存版本引用与Project绑定，候选修改不自动启用。提交顺序与恢复由S02贯通试验验证并在DEV-DB-002第5节明确；S04按同一模型落地实际DDL/管理，不重新选择保存方式。

主题包与业务报告分开。项目交付报告等文件通过现有Workdir/对象边界在项目资料中管理；业务验收、状态、权限仍由现有数据库事实维护。具体报告落点及引用方式需要核对已有实现后接入，不能从需求推定现有文件已经完整。

## 5. 两类数据协议与宿主交互

系统数据维度覆盖项目属性、议题、讨论、决定、工作/任务、执行与准确交付，由现有业务服务按项目和用户范围供给。项目资料维度读取明确授权的项目文件，例如指定JSON、图片、HTML、Markdown及报告，表达来源、类型、版本/指纹、时间和读取错误。

主题需要声明数据需求、呈现及可用动作。DEV-DB-002第6节明确固定宿主数据适配及Project授权＋Workdir窄文件用例，第3节明确同项目/包版本/页返回与迟到响应隔离，S05据此实现生产服务和权限验证。报告文本不能代替任务成功事实，缓存不能替代权限检查，主题传入项目或对象ID不能决定可见性。

页面应能解释未绑定、空数据、缺文件、过期、无权和加载失败。点击治理或办理动作进入原业务能力，准确对象与返回位置保留；是否可在主题内嵌可信办理组件由真实验证确定。用户指定的项目文件不等于允许扫描全部目录或读取任意路径。

## 6. 导入导出与后继能力

数据协议初步验证后，主题导出包含可迁移结构、资源、逻辑数据需求、版本/依赖声明和指纹，不默认打包凭据、用户身份、业务行和真实项目绑定。导入显示缺依赖/待绑定，重新校验并预览，不默认启用。

“不同平台”首个可验证含义是两套元垒实例或环境之间迁移。任意其他产品直接执行主题需双方兼容运行时/协议或适配器，在调研中说明可移植边界，不能承诺一个包天然在所有平台运行。源平台项目ID和路径不能原样变成目标平台授权。

蓝图、议题一体详情、决定与任务及全部项目管理UI纳入本轮全项目主题设计，不能以S07后继理由省略；平台跨项目收件箱保持平台职责。真实Agent生成、有限自主维护、模板升级/多实例等原目标保留为后继待细化需求；其是否属于本轮基础框架收尾须在阶段评审明确，不按旧T卡自动开工。协作/Andon保持暂停。

## 7. 方向稳定，细节逐段形成

持续目标是：项目管理可发现，主题可维护，默认/调研能独立加载切换，两类数据可准确呈现，主题可跨环境迁移，最终日常页面适合人思考和维护。当前阶段只明确其可验证结果和不能破坏的已有事实。

每个关键阶段依据真实页面、文件、协议与故障证据决定保留、调整或替换方案。技术细节和后继拆分更新到DEV，用户决定与证据写LOG。过程可随时触发中断重审，具体机制由[DEV-MG-001](DEV-MG-001-专项推进与设计汇报机制.md)维护。

## 8. DB-S01｜项目入口设计审阅 R1

读者：设计审阅者与后续实施者。R1为初次审阅稿，当前P1—P4已确认，落地修订以第8.8节为准；目标是让用户发现、整理、创建、编辑并进入项目，验收依据是入口关系、信息可读性、字段真实能力及持久化回读。假设一期仍为个人拥有项目、扁平管理、负责人弱关联。协作接入与Andon暂停，主题运行时、组织权限、议题与决定状态机属于范围外。

### 8.1 完整页面全景与阅读顺序

### 8.2 P1｜平台与项目导航

P1.1在“新建对话”和“智能体”之间新增“项目”，保留个人空间、收件箱、知识库·技能、督查板及超级管理员数据总览入口。权限规则沿用现有路由依赖，不新增管理角色。建议新增登录用户路由`/projects`，二级“项目列表/主题管理”使用`?tab=projects|themes`，复用PageHeader的标题、tab与加载状态模式；切换tab使用路由query，刷新或返回可恢复位置。

P1.2区分平台项目管理与项目工作空间。管理页不挂具体project_id，不显示某个项目的局部导航。P1.3标题或“进入项目”进入现有`/projects/:project_id/dashboard`；现有ProjectLayout继续拥有概览、工作台、工作、项目智能体和资料路径，资料沿用工作区`open=workdir_path`。对话中的项目选择器及聊天侧栏快捷入口保留；项目管理不替代对话选择，也不改变Conversation的项目归属。项目内增加“返回项目列表”路径，保留管理页搜索及视图；主题管理从项目入口进入时携带该项目UUID，返回该项目而非邻近或最近项目。

推荐平级一级入口，原因是管理行为需要稳定可发现位置，并与智能体管理区分对象。替代是只扩大聊天侧栏项目区，改动较少但管理入口仍依赖对话上下文；另一替代是在项目详情侧边栏放管理页，会混淆“所有项目”与“当前项目”。平台其余入口的命名、顺序及项目内页面内容保持现有职责。

### 8.3 P2｜项目列表

P2.1左侧说明当前列表，右侧依次搜索、视图切换、新增；搜索框桌面宽300px，窄屏独占一行。搜索在当前可见集合内匹配名称、slug、描述、分类与标签，不使用未授权项目；空查询恢复全部，零匹配提供清除搜索。默认按Project.updated_at降序，同值以UUID稳定排序。这个时间表示项目记录更新，不表示任务活动。类型/分类/标签的高级筛选可继续复用既有ProjectFilters，但R1先不堆叠筛选器或建设自定义列系统。

P2.2卡片默认视图突出icon与名称，名称最多两行且按词/任意长串换行；完整标题通过title及进入后完整页头读取。描述两行，空描述显示“暂无描述”；slug是次要标识，未设不生成假身份。卡片只显示用途类型、分类与管理状态，底部更新时间、编辑和进入项目。负责人、优先级、日期不在卡片平铺，编辑时查看。卡片主按钮与标题进入同一UUID的概览；编辑独立打开P3，不因卡片空白区点击误入项目。

![P2列表与默认列宽](图解/11-s01-entry-20261011/browser/P2-table-light.png)

P2.3列表用身份信息及管理维度做横向比较，默认总宽1020px：

| 默认列 | 宽度 / 下限 | 阅读层级与行为 |
| --- | --- | --- |
| 项目 / 描述 | 320 / 240px | 名称两行、描述一行、slug弱显示；标题进入项目 |
| 类型 / 分类 | 140 / 100px | 用途在上、分类在下；标签留给搜索与编辑 |
| 管理状态 | 120 / 100px | 使用work_status，不能把Project.active当进行中 |
| 弱负责人 | 160 / 100px | 显示有效名称或无负责人；失效关联显示不可用，不猜姓名 |
| Workdir / 更新时间 | 180 / 100px | 相对路径可折行，时间在下；编辑中查看完整路径 |
| 操作 | 100 / 固定 | 编辑、进入；不在本轮新增删除入口 |

列宽按钮只调整前五列，提供滑杆及键盘操作、恢复默认；名称上限600px，其余320px。默认不建设列选择、拖拽配置或跨用户偏好数据库，宽度仅当前管理会话保留。宽屏弹性分配剩余空间，窄屏只在表格容器横向滚动，整页不溢出，并提示切回卡片。替代为全自动列宽，控件更少但长标题会挤压属性；全列拖拽/配置功能更强，但会扩大交互与偏好维护面。R1推荐有界手动调整。

P2.4加载展示骨架和读取提示；第一次空状态突出“新建项目”；搜索无结果提供清除；首次加载失败显示重试且不显示假零数量。刷新失败保留上次列表，显示旧数据与刷新错误。48项场景证明滚动和搜索；大量项目的接口分页需要另据实际规模确定，本轮不宣称已有分页。视图与搜索保存在管理页会话/返回上下文，不改变真实项目选择。

### 8.4 P3｜新建与编辑

P3采用760px居中表单，标题、关闭及底部提交稳定，内容区独立滚动；窄屏单列。基本身份、目的、Workdir和用途默认展开，管理状态/弱负责人/优先级/日期收在“更多管理属性”。名称与目录在首次创建必填，其余默认或可选。完整属性一次提交，避免用户在创建后逐个页面补字段。以下为待实施的产品目标，原型没有调用settings接口，因此未演示读取/提交失败、未保存提醒、绑定智能体负责人和失效关联；原型已演示本地字段校验及内存创建/编辑。编辑先读取settings，失败时给重试，不展示可提交的空表单；提交中防重复，失败保留输入，关闭有未保存提醒。

### 11.3 错误、停用与恢复推荐

推荐来源停用阻止新候选发布和新项目选择，既有绑定继续加载其不可变版本；恢复来源后可继续选择。安全撤回必须提供原因，阻止来源全部版本加载和新选择，保留版本、原绑定与追溯信息。恢复撤回须显式维护操作及原因；版本原字节不改变。入口在来源维护页，内置来源不授予普通用户修改／撤回权限；具体平台内置维护走发布与部署Owner。

缺包、ZIP摘要不符、解析失败、撤回和无权分别报告准确原因；失权清空内容。项目可进入原可信项目页或显式换版本。保持失败绑定以支持诊断与恢复；临时打开原概览只表示退出主题，不保存默认版本。备份恢复后通过相同版本ID、generation、ZIP／资源摘要与alias映射证明恢复，不从页面“加载成功”推断一致性。

候选保存与发布使用来源锁及预期revision，项目选择使用Project锁及expectedGeneration；文件写成功但PG失败留下完整未引用文件，旧选择保持。发布中断的临时文件不可加载，维护对账与发布在相同来源锁下处理，数据库不可用时拒绝清理。阈值在真实包和边界样本测定后写入parser，不沿用研究数字。

### 11.4 替代比较与确认范围

推荐“来源目录＋同来源候选／版本详情＋项目选择页”：维护者先判断可编辑内容与历史，项目使用者只选择已发布版本。把候选和项目启用混在一张大编辑表会弱化提交影响；统一来源列表只配标签虽更短，但内置只读、个人复用、专属项目的可操作范围不够清楚。保留来源范围筛选，版本身份只在选择及追溯所需位置显示。

已确认P1—P5入口和页面组织、候选保存／校验／预览／发布的分步提交、项目文件映射及准确版本确认、停用与安全撤回影响和S04正式页“待S05接通”的呈现。按R1实施这些关键操作。表名、接口名称、文件原语及常规阈值测定由实施者沿真实Owner调整；核心路线、权限或阶段范围变化单独报告证据与影响。R1确认不代表S04阶段通过，完成后由用户审阅真实效果再判断S05进入。

### 12.1 业务事实与有界呈现

项目摘要读Project及ProjectSettings；议题、决定与准确议题讨论由原治理服务供给；正式任务由原ProjectWork服务供给。新分页用例在对应repository先筛选、计数，再按稳定顺序offset／limit取页，原全量API及既有消费者保持原契约。议题表格显示当前页准确有效决定／正式任务关联数，点击进入原议题上下文查看完整关系，避免为标题展示无界加载全部对象。正式任务始终与治理工作建议分开，冻结来源版本仍由原任务source快照拥有。

### 12.2 两类资源及当前绑定

包内asset取已授权不可变版本声明的字节。指定文件只取当前Project绑定alias：每次重新认证、核Project可见性、来源及当前version／generation，再在来源→Project锁内读取Workdir普通文件；浏览器不能补入宿主路径或身份。文件预览不创建Conversation。首批可信组件读取JSON／PNG，其他格式待真实consumer提出，六页不增加凑格式的组件。

响应MIME、长度及SHA-256取同一实际字节，客户端独立核对；包内资源另与manifest指纹比较。未选主题、未绑定alias、未声明alias、缺文件、读取无权、类型／容量／边界错误及旧generation保留不同原因。失败不隐式改绑定；修复文件后显式重新读取，切版本或失权清除旧内容。内置调研PNG仍是标明固定合成示例的包内说明资源，不能解释成项目访谈统计；当前项目JSON是另一个明确来源。

### 12.3 原宿主办理与可信返回

议题／决定进入ProjectInspectionBoardComp的准确topic_id／decision_id；正式任务进入ProjectWorkTaskView的准确task_id。主题先按原API核对对象身份及项目，办理继续由原业务页及其权限、状态机、来源快照和审计执行。主题没有通用写代理。

宿主捕获用户、Project、版本reference／digest、绑定generation、页面、选择、查询、滚动及焦点，浏览器只携不透明返回令牌。原宿主页头“返回项目主题”只能生成当前Project主题路由；返回重新读取实际绑定和事实，仅在同用户／Project／版本／generation恢复上下文。显式刷新同范围也恢复原页；切项目、版本或绑定修订使旧上下文失效。HTTP前后重查绑定与宿主请求generation共同拒绝旧响应，授权失败清空旧内容。

这条返回机制只保存浏览器阅读上下文，不拥有业务状态或授权。原办理页可以继续使用原入口；S06迁移仅交接实际format／ABI和资源／绑定要求，不携返回令牌、身份或业务行。

## 13. 项目级主题作用域纠偏（2026-10-13）

### 13.1 原需求与当前缺口

项目主题覆盖项目日常页面组织、局部导航和显示名称，这是第1节及第10.1节原目标。已选主题只在概览内独立页生效、项目主导航仍进入原聚合工作台，不能判定该目标达成。第11／12节记录的独立挂载与第1／10.1节存在范围冲突；其局部页面确认不证明用户撤销上位目标。当前S05数据／资源与返回实现保留，产品入口闭环未完成。

“保留原业务Owner”要求保持业务权限、状态、审计及准确办理能力，不要求原聚合页面继续垄断日常工作台入口。“S07强化默认体验”用于后续改善信息层级与操作，不推迟基础主题作用域。蓝图、工作建议、督查等尚未被主题覆盖的能力要保留明确可信入口，不能通过删除原工作台造成能力丢失。

### 13.2 推荐职责，待完整导航稿评审

平台外壳拥有全局入口和当前Project身份；已授权项目绑定决定当前主题。项目级宿主统一组织日常阅读导航与主题页面，同一ThemeHost和真实数据适配继续消费包；从项目列表进入、项目主导航、页面刷新及可解释的旧链接均需遵循这一职责。主题管理负责来源／发布／选择，不作为日常使用的强制绕行入口。

原业务组件／页面继续办理准确议题、决定、任务及未覆盖管理能力，明确“阅读工作台”与“准确对象办理／补充管理”的用途。新建议题、研讨回复、修改和决策办理等原日常动作必须有清楚可达的可信入口；是否在主题壳内嵌可信编辑组件或进入独立准确详情由完整设计比较，不能把主题只读表达限制扩写为整个平台只能回旧聚合页操作。主题内对象点击进入原Owner；办理后回项目级宿主的原页／选择，不重新进入另一套同名工作台。平台资料、智能体、正式工作入口保持职责，是否留独立栏位由整体导航稿判断。

推荐为日常概览／工作台等明确有限入口职责，使默认与调研不同page ID都能落到正确页面，不硬编码主题名或数组次序，也不注册包提供的任意平台路由。入口映射先调查当前消费者，在宿主映射与包的有限语义声明间比较并推荐；只有确有需求时对S03契约／ABI及S04版本加载补小增量，字段和布局尚未拍板。不由一次源码诊断锁定新增模型。

旧inspection同时承载无对象聚合页、准确topic／decision、工作建议与历史锚点，逐类处理。无对象入口推荐进入当前主题工作台；带准确对象或管理锚点的链接保留原业务上下文与权限，必要时加可信返回。禁止将所有inspection地址一律重定向。未绑定项目保持现有可信能力；撤回、损坏、失权分别显示原因，不偷偷改绑定或用旧数据兜底。

### 13.3 必要产品结果

绑定后，从项目列表进入并点击项目主导航的“工作台”，无需先打开概览里的主题按钮，就可使用当前主题的日常组织。切默认／调研后导航与对象身份一致；新标签／刷新／旧链接按明确规则工作。准确对象办理和未覆盖管理能力仍可发现，返回恢复来源。取消绑定或错误状态有可信退路且不改变原业务事实。第三个不同page ID／顺序的合法主题检验入口机制，不能仅两个样例特判。

这些是原目标的补闭环要求，具体新页面和路由取舍仍待稿件审阅。数据权限、包不可变版本与来源身份沿现有Owner，S06暂不领取，恢复条件由DEV／LOG维护。

#### 有限入口与路由推荐

新增平台拥有的主题页地址推荐为`/projects/:project_id/theme?page=<pageId>`，page为当前已校验包的精确成员；使用query避免既有不透明页ID被误当多段宿主路径。省略page时，v2取声明home，v1取明确主题入口索引。不存在的page显示“页面已不存在”与当前页列表，不能无提示落到首数组项。平台主导航RouterLink、ThemeHost页事件和浏览器前进／后退共用此地址，Host仅保留内容区及当前选择，只有一个页状态Owner。

`/projects/:id/dashboard`继续作为项目列表与旧概览入口，由有权绑定选择当前home或未绑定原概览；`view=management`、既有`view=business`作为平台有限显式原视图，原能力保持。旧`view=theme`按有效返回token的page或当前home进入新宿主。不新增包路由注册、通用菜单DSL或任意跳转地址。路由page／topic等标识只选对象，后端授权仍决定可见性。

URL表达当前page及必要选定topic_id；原queries／滚动／焦点按用户、Project、reference／digest、generation保存浏览器上下文。刷新重读相同版本后恢复；新标签按URL进入同页并授权读取选择，未携本标签查询／滚动时使用正常初始状态，不宣称跨标签恢复本标签来源。切主题保存成功进入目标home，清空旧页／查询／对象内容；取消选择返回原页且不写绑定。返回有效同范围时才恢复；同页重读观察业务／文件变化，迟到成功及错误均不能覆盖新范围。

裸inspection分流只适用于确实没有准确对象或其他上下文的入口；带theme_return且没有其他业务意图时先核来源，合法返回沿来源页处理。原管理链接始终带明确栏目hash，例如`#topics`，不会被裸入口规则拦回主题。历史链接没有来源token时用“当前主题首页”，不猜用户来自哪个主题页。对象不存在明确对象错误，Project失权清空受保护范围；对象查找和历史修订维持原Owner优先级。

#### 是否需要S03契约增量及旧包兼容

当前Page仅有id／title／description／layout／blocks，Theme没有入口职责；ThemeHost初次读取取pages[0]。宿主可按页面定义生成全部主导航，不能可靠推断home／workbench。对当前合法调研定义重排并改为独立ID，现有纯契约仍通过：首项变为证据资料，两个reading页分别为证据资料／课题脉络。layout、标签、组件组合都不是稳定入口意图。此[独立v1定义](图解/20-project-theme-entry-r1-20261013/v1-independent-definition.json)是调查证据，不是新正式包或产品验收。

推荐确需小增量：在theme定义增加`entryPages: {home: pageId, workbench: pageId}`，两个键均必需且每键只能指一个现有页，允许两个职责同页；未知键／不存在页／重复JSON键／任意URL字段明确失败。其消费者只有项目进入与裸工作台的宿主分流；主导航仍消费既有pages，不另外建菜单或职责注册系统。两个样板和第三个不同ID／顺序的定义一起证明角色落点，不按default／research识别。所述结构为待审设计，未更新Schema或ZIP。

建议新包formatVersion=2，componentAbi保持1：增加包入口语义，但没有新增可信组件或输入／事件ABI；旧运行时会拒绝format2，不能称为对旧加载器透明兼容。新运行时保留format1解析与完整边界，format2严格要求entryPages，不支持版本仍拒绝。版本显示名另取新值，不与formatVersion混为一谈。真实PG版本表当前有format_version=1且component_abi=1的CHECK，故format2还需一次最小yuanlei Schema迁移：扩大支持格式到1／2、ABI仍1，升YUANLEI_SCHEMA_VERSION并走既有storage-migrator；仅改CREATE TABLE IF NOT EXISTS不会更新已存在约束。此增量不加表、不加绑定或入口字段、不更新历史版本行，immutable trigger保持。部署升级前旧运行时拒绝新格式；新迁移／parser均就绪后才发布新包。现有不可变ZIP／版本行／绑定／资源摘要保持，发布新版本后经明确选择更新绑定generation，不做自动迁移、静默重绑或改写历史包。新包仍不能携Project身份、路径或批准状态。

v1正常加载后，全部页面直接进入项目主导航，各页可准确阅读和办理；没有入口声明的裸项目入口显示“该版本未声明首页／工作台，请选择页面”的索引，不猜首项。此路径比直接首页多一次点击，是保持全部既有包可读且不伪造意图的明确代价。内置两套新包发布后，用户可明确切换获得直接home／workbench；项目专属／复制旧包同样可在候选补声明、改版本并发布，不要求为所有历史包写特判。v1直接page URL不经过索引，未声明不伪装为包损坏。若用户要求全部旧包无操作就有精确首页，只能增加经过确认的绑定级映射；它引入第二处持久入口事实，本稿不推荐、不提前实施。

真实替代：只动态列出全部页、没有home／workbench声明，契约不变但裸入口只能索引，难以达到直接日常首页；按主题名／page ID／pages[0]／组件推断省修改，却会在第三包或重排时误入；绑定级映射保留v1，但入口事实与包分离、增加持久维护；整页重写或内嵌全部办理交互会扩大状态／草稿风险。本稿推荐有限包职责＋原准确办理，代价是一次format升级、旧包索引、主导航变长及平台创建／返回接线；收益是可携意图、单一入口Owner和保留原能力。

## 14. 全项目主题重新规划 R2（2026-10-13）

### 14.1 范围决定与被否定方案

用户明确：项目维度开展的全部界面都通过主题组织，蓝图、工作建议、督查、治理及对象办理均需重构；旧界面用于跑通流程，不能作为固定设计。界面密度／交互会改变注意力与判断，本轮先做全景设计。第13节“补充管理入口回原页面”及P06 R1“准确办理沿旧页”的推荐被否定，保留历史证据。UI全面重构不等于重建业务模型，原权限、状态机、数据、审计、文件边界与可复用服务继续拥有业务事实。

全部项目页面包括首页／大屏、蓝图、议题与讨论／决定、工作建议、正式工作及结果验收、督查／汇报、项目资料、项目智能体／执行工作台、项目属性／资源设置、项目主题候选与选择，以及创建／编辑／历史／详情／空错。平台全局聊天、共享账号／凭据、跨项目收件箱及公共主题库属于平台职责；从项目跳入这些页面明确标示跨界，不能借“平台能力”把项目内配置留在旧页。

### 14.2 推荐架构与替代比较

推荐“完整内置基础主题＋可信业务能力组件＋受控主题组合”。平台外壳管全局导航，项目宿主管项目身份／授权版本／URL意图／返回／草稿边界；主题定义组织项目导航、页面／详情／编辑区域、显示别名、有限布局和密度token；可信能力组件负责正确表单、原状态可用动作、DTO与错误、历史和审计呈现，调用原业务API。包可选已注册能力／有限动作，不携自由JS、任意请求、身份、批准结果或自定义业务状态机。

可信业务能力必须拆出读取／编辑／操作／历史等适合复用的界面单元，重新设计视觉与信息分层；把旧Vue长页套一个主题外框不算完成。当前六类只读组件不足全项目使用，不继续以此上限排除管理。能力词汇只按实际模块消费者增加，不建设没有用途的通用低代码表单或工作流引擎。

| 路线 | 得到什么 | 代价／判断 |
| --- | --- | --- |
| 动态导航＋旧页办理 | 较快迁移入口 | 信息密度和旧布局未改变，用户已否定 |
| 完整基础主题＋可信能力组合（推荐） | 管理和办理全部在主题，复用原业务并让不同主题有一致正确性 | 需拆分旧页面状态、表单与草稿，逐模块验证 |
| 每套主题自由Vue／JS重写业务 | 表达自由 | 每包复制权限／状态／测试责任，突破现有受控路线，不作为首批 |

默认完整主题承担所有已有项目能力。自定义主题可重排／命名／覆盖能力视图，未定制的模块按明确版本继承基础主题的可信界面，继承页仍处于当前项目主题壳／token／导航内，不跳回旧UI。紧急撤回／损坏时由有权内置完整主题提供受限应急界面并醒目标示，不改绑定或冒充启用成功；失权只清空并回平台入口。主题隐藏功能不形成权限，也不能使关键能力无可发现入口。继承版本、覆盖优先级和能力缺失在首个真实模块试验后细化，尚未有生产实现。

### 14.3 信息架构：思考／行动／资源

推荐三组项目导航：方向与思考（总览、蓝图、议题），行动与反馈（行动计划、工作、督查），项目资源（资料、智能体、设置）。组名和显示名按主题变化，业务身份不变。决定不与议题竞争一级入口，主要在来源议题中维护；无来源决定、跨议题查询仍有当前主题的可发现独立索引／详情，具体布局在模块包细化。总览／大屏是项目主题的一页，不能再次代表全部主题。

议题详情按2026-10-14反馈采用连续正文：正文下方折叠决策，再下方混合讨论／执行／历史动态。正文持续可读，动态筛选不切走正文；讨论和决策详情可折叠。普通研讨、重议、纠偏与正式重开分开；批准、勘误、撤销、替代和草案编辑分开。蓝图以文档阅读／编辑为中心，行动计划以预期结果、计划内容和转为／关联工作为中心，低频不采用操作收在更多中，督查以待介入异常／处置为中心，正式工作详情优先当前依据与交付审核。

### 14.5 密度与视觉规则

采用UI/UX Pro Max本地技能及现有平台规范。其初次检索匹配营销漏斗／不适用字体，重试仍有营销Pattern，本稿拒绝该部分；采用经产品判断适合的Flat Design、克制品牌强调和清晰分层。密度查询未准确命中，渐进披露依据技能Quick Reference而非伪称检索成功。保留Vue／Ant Design Vue和Lucide；中文使用系统字体，不新增远端字体、图标库、GSAP或FormKit。

阅读正文16px／行高约1.8，列表14—15px；主标题约26px、模块约19px、元数据12—13px。示例采用4／8间距体系、白／浅灰表面、有限边框和青绿色强调，调研采用低饱和蓝色；生产映射现有token，新增token需说明。舒适／紧凑只调整目录与行距，不能缩小正文和重要操作到不可读。暗色独立检查，不保证反色自然可用。

一页默认一项主要动作；目录最多展示标题、状态及一两条定位信息，完整正文／日志不常驻。议题正文常驻、决策折叠、动态按时间混排；复杂配置用折叠／二级区域；不同对象数不是越多越好。正文控制阅读宽度，桌面目录与内容主从，窄屏先目录再内容或明确切换；不得套三层永久侧栏，平台窄栏与项目导航可显式收起，鼠标悬浮不是唯一操作。UUID、hash、调试与内部枚举按需追溯，不能占据产品首屏。

草稿离开保护、就地字段错误、焦点返回、只读与禁用区别、空／错／加载与失权必须设计。不能用通用“批准／完成”混淆决定、议题和任务状态；危险动作独立确认，不因页面更简洁省掉历史或依据。

### 14.6 原型阅读与真实验收

先总览查看注意力组织，再蓝图阅读／编辑，随后议题目录→常驻正文／折叠决策／混合动态，接着行动计划→工作→当前结果审核，最后督查、资料、智能体和设置。开启“设计讲解”按M1导航、M2主任务、M3内容解释。两主题和舒适／紧凑用于比较同能力的表达，示例名称／统计均为合成。

初稿编辑、回复、草稿离开、决定／结果动作弹窗仅在演示内存运行，不能证明真实状态、授权、审计、内容净化、深链或兼容。完整状态和特殊动作在模块竖切时补可审稿。所有项目页面最终通过主题渲染和办理，第三主题需检验详情／编辑／历史及缺失能力继承，不只检验home／workbench。

### 14.7 契约与迁移的判断时机

P06 R1仅home／workbench两个角色和format2提案不足以描述全项目覆盖，不作为本轮已采纳契约。先以“蓝图编辑＋议题详情／回复＋决定动作”的真实模块验证能力组件／动作及布局，再定有限视图／意图／版本声明、基础继承和包升级。新增可信组件或动作输入会影响ABI，应按消费者变化评估，不能预设ABI1永远保持；不可变旧ZIP不修改，不静默升级绑定。旧包只读能力不能称全功能主题完成，需显式升级或在新宿主中使用清楚标明的完整基础主题继承。

旧URL兼容保留对象／版本／评论／建议类型／hash／草稿语义，目标是新主题能力视图，不是保留旧Vue页。遇未知上下文解释错误或提供同主题能力索引，不能伪造定位。S06继续暂停；先闭合全项目功能与展示架构，再细化迁移，S07用于实用观察后的优化而非补齐被遗漏模块。真实Agent生成、素材与模板库目标保留，在能力／包协议形成后设计工具及授权，不本轮顺手发外部任务。

### 14.8 R3逐页修订与行动计划卡片（2026-10-14）

本节依据用户对DB-P07 R2逐页反馈生效，优先于14.3—14.6旧局部表述；具体截图来自tmp中的“任务主体.png”和“动态.png”，只参考排版与交互，不复制截图的私人正文、身份及工程信息到公开设计稿。原R2字节及检查归档于2026-10-14-R2反馈前；DB-P07同一路径更新R3，架构职责未变，DB-G23无需重画。

#### 统一页面框架

项目二级导航已提供页面身份，去掉PROJECT WORKSPACE、重复大标题和解释性副标题；当前页面按钮不再承担菜单已有的跳转。总览无“进入议题”等重复导航。目录／管理页面仅保留紧凑操作条、筛选与内容，边距、工具高度和内容面统一；工作、智能体等准确对象详情保留真实对象标题，不能为去通用页名而把办理对象也删掉。平台项目列表仍属于平台，保持自身身份。

#### 总览

蓝图摘要直接用蓝图标题和正文片段，无“项目方向”标签或“阅读蓝图”按钮；标题直接进入准确蓝图。多蓝图时右下角以浅灰文件署名标来源。初稿整个蓝图摘要区最多180个可见字符（标题32、正文100、来源24及省略号纳入总额），超出省略，完整文字在蓝图可读；不是对每篇独立限额后无限叠加。本版选一篇做摘要，之后多摘要总额度不变。

“最近判断”改“最近动态”，允许来自议题、决策和讨论等不同事实。点击内容本身打开准确对象／区域：议题进入正文，决策展开关联决策详情，讨论展开准确回复并定位；不放额外“进入来源议题”按钮。原型代表动态共用同一合成议题，事件／决策使用不同明确标识；生产必须用原对象ID／comment／revision，不能只跳同一模糊页面。

#### 蓝图两种布局

详情模式主体只渲染当前蓝图。顶部左侧浮动标题选择器，悬浮／点击可见标题列表，键盘有点击替代；右侧布局图标、新建和历史图标。历史下拉列当前选中蓝图版本，选中后替换主体并注明只读，不弹旧详情窗。主体右上阅览／编辑图标切换；编辑直接在主体textarea打样，保存到演示内存，真实产品沿原文件用例；更多包含重命名／归档／删除。

抽屉模式按顺序呈现多篇蓝图，每篇标题可折叠；顶部选择器选中后先展开对应篇，再滚动定位，不仅改选择值。每篇保留阅览／编辑与更多，操作作用于准确蓝图；新建／历史仍在页顶。未保存草稿可回读继续，切换／历史／离开保护须在真实浏览器验证；禁止原型成功提示代替文件保存。历史、当前与草稿分开，不把历史当可编辑正文。

#### 议题常驻正文与混合动态

参考截图顺序为正文→可折叠决策组→动态。决策组先显示标题与准确状态，选中展开详情及可用动作；草案编辑／删除与批准后的勘误／补充／替代／撤销保持区别。正文不随讨论／执行／历史筛选消失，也不再以原五页签割裂思考脉络。

动态按时间混合：历史操作一行呈现，讨论像论坛回复可折叠／展开与回复，执行关联的工作以独立div块展示准确标题、状态和依据摘要。支持由早到晚／最新在前，讨论、执行、历史仅过滤动态；评论锚点和展开状态应保留。最近动态进入具体回复／决策，不丢当前议题。生产时间来自持久事实，不能从报告文字猜阶段完成。

#### 行动计划的定位和卡片理由

产品名称改“行动计划”：表达打算怎样推进，尚未等于已落地的正式工作；当前原建议模型与admit是可复用承载，显示名调整不证明完整计划业务模型已形成。首批优先复用title、description（计划内容／预期结果）、可选topic／decision／agent及现有纳入关联。若需要独立目标、阶段或多任务关系，须核实际消费者再设计，不默认添表或发明状态。

卡片依次为：标题回答“做什么”；短预期结果回答“得到什么”；可折叠计划内容回答“怎么推进”；浅色可选来源回答“为什么”；底部转为工作或关联已有工作回答“如何落地”。内容完整度提示不是新增业务状态。目录区分待落实与已关联工作，纳入后显示准确去向；低频不采用在更多中，不能因美化丢原业务。

现有admit只把同一建议映射到一个正式工作，mode=create或link；同模式／目标重复幂等，异模式／目标冲突拒绝，拒绝状态不可纳入，link限同项目，create继承准确来源及原复核条件。这些规则由原Owner执行；卡片不自动启动任务、不从行动计划推断工作完成，不承诺尚无模型支持的一计划多工作。

#### 工作与督查

“正式工作”显示为“工作”，不在标题和按钮重复正式二字；入口以新建／搜索／列表等实际操作为主，保留列表标题、状态与下一动作，点击对象标题进入准确详情。督查同框架，以需介入事项与汇报分层，不再解释这是哪个页面。布局由同一间距和表面体系维护，必要业务动作与异常提示保留，去掉的是冗余介绍。

DB-P07 R3是合成界面修订，未改业务模型、真实保存、router或平台页面。代码检查不等于悬浮、滚动、键盘、响应式或用户审美验证；原file浏览器策略阻断仍有效，不换通道绕过。

| M1 平台外壳 | 全局导航、用户连接、公共主题库 | 保持平台身份与权限，主题不覆盖全局页面 |
| M2 项目宿主 | 当前Project、当前有权绑定、导航、页面解析、草稿与返回 | 一次成功选择后统一刷新绑定；导航、正文、数据上下文使用同一版本／generation |
| M3 主题定义与可信渲染 | 页面顺序／名称、有限布局、密度／颜色、能力视图与资料块 | 已声明字段必须有实际消费者；调研与默认在信息组织上存在可观察差异 |
| M4 原业务能力 | 蓝图、议题／讨论／决定、计划、工作、督查、文件、智能体和设置的读写规则 | 复用真实ID、权限、状态、历史与API；主题名称不改变业务类型 |
| M5 来源／版本／项目选择 | 受保护包、来源授权、不可变版本、唯一项目绑定 | 校验后显式选准确版本，失败保留原选择；回退也是新的显式选择 |

当前能力页面可以继续复用已完善组件。推荐先做有限、可复用的视图组合：以现有默认样式为基础，调研优先呈现课题／证据／结论，采用明确的目录与正文组织；资料展示可组合已注册的JSON／PNG块。蓝图、行动计划、工作、督查、项目资源及设置仍在该主题内可达，未覆盖能力明确继承基础视图。逐模块说明哪些由主题覆盖、哪些继承；不能将所有差异压缩为改色和改导航标题。

显示别名至少贯穿能力导航、目录、详情、创建／编辑及其提示；对象历史中的用户原文保持原文。主题提供的过滤、排序、初始选项只决定初始阅读，不能隐藏对象后把它解释为不存在，也不能改变可执行动作的准入。

### 15.3 何时可以切换

| 条件 | 界面表达 | 最终校验与失败结果 |
| --- | --- | --- |
| 来源可见、准确版本已发布且来源允许新选择 | 显示来源、版本及当前／候选区别 | 服务端重新授权；未发布、停用、撤回或越权拒绝新选择 |
| 原ZIP、声明资源及依赖可加载 | 预览显示校验错误和不兼容原因 | parser／宿主验证digest、format、ABI、基础版本和可信能力；未知依赖不自动安装 |
| 必需项目文件全部绑定且可读 | 按alias显示用途、类型、缺项；无要求时不增加输入 | 复用Project／Workdir边界校验；缺文件、错类型、超限及越界拒绝保存 |
| 当前编辑可以安全离开 | 切换确认前处理本项目未保存内容 | 默认取消切换／返回编辑；显式放弃需确认，不能用刷新强行丢弃 |
| 当前选择未被其他操作替换 | 显示准备切换的版本和当前选择 | 服务端expectedGeneration并发检查，409后重新读取并要求重新确认 |
| 数据和视图作用域一致 | 完成后明确当前版本，进入其可用页面 | 成功回读后统一传播；旧请求、旧返回令牌和旧页状态不能覆盖新主题 |

数据为空不阻止切换，按真实空态展示。原业务API临时不可用通常表现为页面错误与重试，不要求全项目所有接口先成功才允许切换。manifest声明的必需文件属于选择条件；切换后文件被删除则展示资源错误，不能静默改选。可选文件需求如出现，先用真实消费者细化契约，不把当前全部必需规则擅自放宽。

来源停用沿当前语义阻止新选择，既有绑定继续加载；安全撤回或包损坏保留绑定并明确故障。应急基础界面只在仍有项目权限时可达，标明正在使用应急视图；失权清空数据。界面始终提供可信的选择／恢复入口，不能因为目标主题缺设置页面而被困在其中。

### 15.4 切换时的页面、草稿与数据

主题选择提交成功后，以服务端回读的绑定为唯一事实。若成功写入后的回读或渲染失败，显示“已保存，加载失败”并允许重试／显式切回；不能把已提交的绑定说成未改变。写入结果不明时先读取绑定核实，禁止盲目重发或自动回滚。

不同主题的page ID允许不同。推荐按稳定能力定位：切换时没有正在办理的准确对象则进入目标总览；有议题／决定／工作／历史定位且目标支持该能力时保留准确对象，重新生成目标page ID。未声明的能力按基础继承定位，展示页无对应目标时进入明确首页或页面索引。不得照搬旧theme_page或用主题名称猜路由，不引入未经验证的任意首页脚本。

草稿按用户／Project／业务对象隔离并沿原业务revision校验，不把主题变化视为业务数据变化。主题相关的选择、查询、滚动和返回令牌按版本／generation隔离；对象草稿可以在同项目明确恢复，旧页缓存不能跨主题复用。刷新、新标签与重新登录从持久绑定重建当前主题；其他标签在重新聚焦或收到明确失效信号时重新核绑定，未完成核实前不能把旧界面当成已切换成功。

### 15.5 可携包与S06衔接

S04修复继续使用现有ThemeSource／Candidate／Version／ProjectThemeBinding，不增加第二套启用表或主题选择状态。S05依据代表页面消费者收敛最小契约增量；不能预定必须升级format或ABI，也不能让新增字段仅进入schema而没有运行时。旧发布包字节不可变，升级发布新版本，由项目明确选择。

S06导出的是原ZIP及其中明确携带的定义／资源；平台Vue可信组件由目标实例提供。兼容目标须满足实际format／ABI／baseVersion／组件能力；缺依赖在导入预览说明，不自动下载执行代码。包不包含用户、Project ID、凭据、Workdir绝对路径、alias映射、绑定generation、业务行、草稿或返回令牌；内容作者自行放入的文案／图片仍会随包携带，需要在导出说明中可见。

S04交付不可变包与项目切换证据，S05交付真实组件消费、双数据与办理证据，两者完成后联合验证默认→调研→默认，再细化S06。新实例导入后登记目标本地来源／版本、重新授权及绑定目标文件，不自动启用。S06的两环境实际迁移仍属于下一阶段，不在修复中提前实现导入／导出接口。

### 15.6 方案取舍与审阅边界

保留当前默认视图并做有限组合，可复用已完成治理能力，代价是主题只能表达平台已支持的布局与组件。每主题复制完整Vue业务页会分叉状态与授权维护；自由上传Vue／JS会引入运行隔离和代码审查范围，这两项不纳入当前修复。若调研的代表页面经实证无法由有限组合表达，则在S05设计小试处暂停该路径，带具体页面与成本重审；不能以未来扩展性为由现在建设通用低代码系统。

本节是依据本轮要求形成的修复设计。默认基线、多主题目标和独立分段由用户指令给定；新增的选择交互、调研代表页面及契约细节在各修复任务起始处形成具体审阅稿。日常技术实现由执行者承担。当前不重新审美重画默认九页，不扩展协作与组织权限，不把基础切换或数据适配留给S07。

### 15.8 平台完整管理与项目快捷入口（A1增补）

平台“项目→主题管理”是独立于项目主题页面的完整主题管理入口，拥有来源／候选维护、校验／预览、发布与版本、来源停用／撤回、项目分配、文件映射维护、当前选择核实、显式换版／切回及有权追溯。普通用户的恢复操作沿现有服务完成；数据库／卷恢复等部署操作仍由部署维护者负责。项目设置的主题卡片是固定当前项目的快捷入口，复用相同选择服务与校验。简化主题可不提供设置页面，不能因此失去主题管理能力，也不强制为它补出设置页。

平台界面明确区分“库来源范围”和“分配目标项目”。前者决定浏览／维护哪个来源，后者决定修改哪一个项目的唯一绑定。来源专属Project不是可随意切换的分配目标；选择目标改变后重读该项目当前绑定、可选版本与文件条件，清除旧目标的确认快照及映射，必要时先保护草稿。项目先行时重新选择版本；版本先行时仅保留所点准确版本引用作为待核对意图，旧适用性结论失效，须在新目标重新授权／校验后才能确认应用。确认区同时显示目标项目名称／标识、当前主题、拟用准确版本及文件映射，不能把来源筛选悄悄当作分配授权。

两种正常操作都成立：①先选项目→查看其当前主题与条件→选版本→预览／映射→应用；②先查看主题发布版→“分配到项目”→选择有权项目→重新校验该准确版本的适用条件→确认。第二条携带准确版本引用作为待确认意图，不能只跳到一个空选择器让用户再次寻找版本，也不能打开入口就写绑定。跨项目专属来源不合法时明确拒绝，选择其他版本／项目不得暗中提升来源为公共。

平台路径应用后留在平台管理页，显示服务端核实的该项目当前选择及结果，并提供“进入项目”；无需先进入项目设置才能证明应用成功。项目快捷入口按SYS15.4接续当前对象或目标总览。失败、409、响应丢失及写后加载故障沿同一协议处理。平台管理页面自身不依赖当前主题加载成功，即使项目主题未绑定、未声明设置或已损坏／撤回，只要仍有项目权限就能查看状态并显式换用有权版本。

平台无法读取另一标签尚未提交的编辑内容，不能宣称能跨标签自动保存或统一丢弃。操作说明需提示切换会影响目标项目的已打开页面；当前标签先保护本地候选／映射草稿，目标项目标签在发现绑定变化后保护其本地业务草稿再接续。共同generation与原业务revision仍执行，两个入口共享一个事实Owner，不增加批量分配、跨项目业务配置或组织权限。

DB-G26为<a href="图解/25-s04-dual-entry-20261015/dual-entry.html" target="_blank" rel="noopener">双入口与共同分配用例图</a>，补充DB-P08／DB-G25而不覆盖v1原始稿。DEV12.2的A1 v1.1定义增补交付与双入口验收。

平台具体交互增补见<a href="图解/24-s04-switch-a1-20261015/platform-v1.1.html" target="_blank" rel="noopener">DB-P08 A1 v1.1</a>，仅新增平台部分待确认，已认可v1继续有效；实际状态见LOG第50节。


### 15.9 S04-R本包实现边界回读（2026-10-16）

已认可的A1 v1／v1.1在同一服务和唯一项目绑定上实施：平台有目标优先、准确发布版本优先两条分配路径，保存后留管理页核实；项目设置复用同一选择流程。只读预检解释使用条件，最终应用仍重新授权、读取包和校验文件及generation，不保存第二套启用状态。无文件声明的版本不要求Workdir已经建立；有声明时保留原普通文件、alias、类型及容量边界。

项目宿主拥有统一绑定投影及作用域；局部能力仍归原业务Owner。主题改变先保护实际未保存输入，明确确认后销毁旧页面及请求上下文；跨标签变化由重新聚焦核对并保护该标签草稿。损坏／撤回时的应急基础界面不构成正式默认选择；从可信平台入口显式恢复。渲染故障边界仅作用于项目渲染／setup错误，平台错误不被项目错误屏障吞掉，普通事件异常不冒称保存成功。

本包真实结果、失败和未验以LOG第51节为准。调研当前ABI2仍复用基础能力组件，不能将标题、page ID及密度差异当作已完成调研内容组织；S05-R2的代表消费者及JSON／PNG双数据联合证明仍是后续独立任务。本节不改变15.1—15.8的需求，不自行批准S04／S05整体或启动S06。


### 15.10 本地内置样例整改、默认与应急统一（2026-10-16，已确认实施）

用户原话“三个模板审核通过”确认DB-P09／DB-G27；同轮授权主题管理无需原型直接整理。三套当前样例分别为“默认 · 项目管理”“精简 · 专注推进”“调研 · 阅读工作室”。实现及部署、独立Review、实际证据与未验范围由LOG53拥有，不据此宣告S04／S05整体验收。

默认与应急共用上一轮人工调整后的基础组织、九项可信能力及样式。正常默认显式选择当前发布版本；应急是包未绑定／不可用时的可信基础呈现，增加异常原因和恢复入口，保留持久绑定。默认总览保留原左侧条件Git审批、需要处理及当前推进，右侧蓝图、动态及条件Git占用；不因样例整改重画九页或改变已调整办理交互。

精简主题只显示总览、蓝图和议题主导航，总览以宽蓝图正文和窄最近动态两区组织；不挂工作统计、待处理或Git区。调研主题保留九项能力，采用深蓝项目导航、课题目录、研究问题正文和蓝图／动态侧栏。内容沿同一项目的原蓝图文件、Topic及决定DTO；已记录决定显示原状态，无决定即为空，不从讨论推断批准。主题显示不改变原权限、状态、历史或文件。

显式隐藏只作用于项目主导航，准确对象／历史链接和原办理能力保留，隐藏能力详情提供返回主题总览入口。缺省缺页仍继承基础能力，只有明确hiddenCapabilities才不补回六项导航；此为15.2／15.4缺省继承的受控补充。总览必须可见。最近动态仍只消费原topic／comment／decision事件，不新增蓝图编辑事件。

有限配置presentation与hiddenCapabilities由真实项目导航及总览共同消费，componentAbi为3，formatVersion仍为1；旧ABI1／2按原契约继续加载，旧宿主对新ABI明确失败，不静默忽略新组织。不使用theme.id特判、不复制三套业务页、不引入自由布局DSL、脚本或第二套绑定。

四个旧内置来源通过原disabled状态退役，正常目录仅三套当前来源，历史区可追溯不可变版本。原包及已绑定项目保留，不自动换版；旧绑定显示退役提示并提供平台显式选择。发布新版本不替换项目选择，预览不写绑定。

主题管理与项目列表并列，不提供重复的返回列表或手动刷新目录按钮。S03固定前端样例演示退出正式页面，旧书签进入主题管理；真实候选／发布版本的隔离预览保留。维护规则置于帮助，当前选择、条件、确认、结果与错误直接可见。来源切换、创建、编辑、发布、维护和分配后自动回读目录，聚焦时再核对，保留候选草稿且拒绝迟到目录覆盖。接口、唯一Project绑定、generation与文件边界复用原服务。

S05-R2的JSON／PNG双数据联合证明仍为独立未完成出口；本包局部调研组织不能替代整包验收。S06、协作和Andon保持暂停。


### 15.11 管理弹窗与真实项目只读预览（2026-10-16）

### 15.12 主题制作、发布与使用的概念及后继边界（2026-10-16）

主题库中的“来源”是保存一个主题系列的身份、权限、编辑草稿与版本历史的容器。界面优先使用“主题”表达，技术source ID按需追溯；它与Project业务数据的来源没有关系。“个人公共”实际只允许本人多个项目复用，界面显示为“我的主题”，旁注“供本人项目复用”；平台内置仍只读，项目专属仍限定有权Project，不改变现有uid隔离。

| 业务概念 | 用户在做什么 | 保存在哪里及什么时候生效 |
| --- | --- | --- |
| 创建可编辑副本 | 从有权准确发布版建立自己的主题，以便调整 | 新source身份与候选ZIP，记录原version引用；不自动发布，不改变任何项目 |
| 编辑草稿（原候选） | 修改受控定义／替换声明素材，保存并校验，预览准确修订 | 受保护主题文件域的ZIP＋PG候选revision／digest；与Project的Workdir文件分离 |
| 已发布版本 | 查看可供项目采用的不可变快照 | PG版本引用＋不可变原ZIP；查看列表不产生发布请求 |
| 发布新版本 | 将已保存、已校验草稿登记为准确版本 | 服务端校验expectedRevision；同来源同版本异字节冲突，必须显式更改版本标识；既有项目不自动升级 |
| 分配／应用主题 | 让一个有权项目选用准确发布版并绑定其必需文件 | 唯一ProjectThemeBinding及generation；后端最终校验并回读后接续宿主 |
| 存储检查与维护（原对账） | 查找引用包缺失／损坏和未引用残留，必要时人工处理 | 核PG候选／版本引用与受保护主题域的ZIP字节；检查与清理分开 |

例如：复制内置调研3.0.0为“我的调研”→编辑草稿、明确设置新的版本标识→保存校验并预览→发布新版本→项目A显式应用。此后继续编辑草稿，不改变A正在使用的旧版本；只有A再应用新版本才升级。复制不修改内置内容，也不等于已启用或可供所有用户使用。

主题详情顶部的“发布版本”属于查看模式，使用“已发布版本”并展示当前选中态。真正写入操作使用“发布新版本”，仅在有权可维护、候选存在且已保存、来源允许发布时可用，并说明发布后仍需显式分配。内置版只展示已发布内容及创建副本／预览／分配，不制造无法执行的发布按钮。复制成功直接定位新主题的编辑草稿，并解释尚未发布；失败区分完全未创建与身份已创建但复制未完成，核实后展示可恢复主题，不能误称完全未产生结果或盲目重试复制。

存储检查是低频技术维护，放入更多／维护区域，默认显示健康摘要及需要处理项，digest等明细按需展开。它不核Project业务数据、不提供页面可视化配置，也不承担素材编辑。清理仍只删除同源锁内复核的未引用普通包／临时残留，不能删除被候选／发布版引用的包；检查不自动清理，不把故障包误修成默认选择。

### 16.2 导出与导入的正常业务

导出入口位于主题详情的“已发布版本”，作用对象是准确有权版本。服务回读原ZIP，返回下载及原字节SHA-256；停用来源沿现有读取语义，撤回／越权／坏包不能导出。草稿先发布，再导出准确快照，首版不增加含义模糊的“导出当前页面／项目／未保存草稿”。文件名与响应头由服务安全生成，不暴露宿主路径。

导入入口位于平台“项目→主题管理”，无需先选分配项目。用户选择ZIP→看到只读预检摘要→选择建立个人主题（默认）或写入本人有权可编辑主题的草稿→明确确认保存→进入编辑草稿。项目专属目的地需先明确所属Project并重新授权；内置来源不能作为覆盖目标。主题名称／说明等目标库元数据可独立设置，不因改显示名重写原ZIP中的theme.id／version／source。

预检显示主题名／作者声明／原包digest／format／ABI／基础版本、页面及能力摘要、包内素材清单、必须重绑的Project文件alias和支持／拒绝原因；不创建来源、不改候选或绑定。确认保存仍重新解析实际上传字节及校验目标权限／候选revision，不能信任浏览器预检或一份过期摘要。不为此引入新的持久导入状态表、预检通过状态或通用迁移任务系统。

导入只保存目标可编辑草稿，不自动发布或启用。预检与已保存草稿可以查看定义和包内素材；只有选择有权目标Project并临时映射所需文件后，才能进行S05的真实业务预览。随后沿原“保存校验→预览→发布新版本→分配项目”完成使用，目标项目已有主题在明确应用前保持。三步“导入／发布／应用”在界面与记录中分别反馈。
